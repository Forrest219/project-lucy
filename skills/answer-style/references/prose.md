# 对话层与口径层

表格规则在 [business-style.md](business-style.md)。这里只规定表外的句子。

## 顺序

1. 导语一行。
2. 结果：多行用一张商务表；单值把数字放进导语，不套表。
3. 口径一行。
4. 再跑一句。仅当业务词可能对上更细或更粗的字段。

没有内容的段落直接省掉。前面不加「我来查一下」「根据查询结果」。不加 Markdown 标题，不加列表符号。答案后不贴英文 Provenance。

## 导语

```text
按 `category` 作为「产品线」，2026 年利润降序排名如下：
```

业务词用「」。字段名用反引号。时间、指标、升降序写在同一句。

用户用词已经是字段名时：

```text
2026 年利润降序排名如下：
```

单值：

```text
2026 年利润为 695,466.02。
```

截断时在这句写明「前 10」。

无记录时不画表：

```text
2026 年没有可计入的订单行。
```

## 口径

紧跟结果，以 `口径：` 开头。每个指标写成 `表达式 中文名`，中文逗号分隔；过滤和时间用中文分号接在后面。

```text
口径：SUM(profit) 排名，SUM(sales) 销售额，SUM(profit)/NULLIF(SUM(sales),0) 利润率；过滤 is_deleted = 0，年份为 YEAR(order_date)=2026。
```

- 表达式是实际执行的聚合，并符合 `skills/warehouse/references/metrics-policy.md`。利润率、折扣率用 `SUM / NULLIF(SUM, 0)`，订单数用 `COUNT(DISTINCT …)`。
- 过滤按这次查询实写。超市订单写 `is_deleted = 0`；来源没有该列时不照抄。
- 时间写清字段和谓词。
- 数据截至日和过滤期间不是一回事时，行末补 `数据截至 MAX(order_date)=YYYY-MM-DD`。
- 截断时补全量，例如 `表内为前 10，共 17 个产品线`。
- 这一行是用户可见的溯源。用户没有要审计明细时，不再追加 `Source tier / Tables / Measures`。

## 再跑一句

先按当前字段答完，最后加一句。不要先反问再查。

```text
如果你这里的「产品线」指的是更细的 `sub_category`，我可以按子类目再跑一版。
```

映射没有歧义时不加。一次只提一个相邻粒度。

## 失败

查询失败且没有成功事实行时，说明是否已重试、影响哪一项。不给数值结论，不写「数据完整」「完全对账」。
