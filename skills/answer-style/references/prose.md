# 对话层与脚注

表格的列、数字和加粗在 [business-style.md](business-style.md)。这里规定 exhibit 外面的句子，以及注、资料来源怎么写。

## 顺序

1. 标题一句。结论表写判断，查数表写范围。
2. 副题一行：时间；单位。
3. 一张表。单值题可以不套表，数字写进标题。
4. 注。
5. 资料来源。
6. 再跑一句。仅当业务词可能对上更细或更粗的粒度，并且注里已经写明当前粒度。

exhibit 到资料来源为止。前面不加「我来查一下」「根据查询结果」。不加 Markdown 标题，不加列表符号。来源之后不贴英文 Provenance，默认也不贴 SQL。

## 标题

结论表：

```text
技术贡献了一半以上的利润，家具利润率只有 1.5%
```

判断必须能在表的第一行（加粗行）上核对。字段名不出现在标题里。

查数表：

```text
2026 年各产品线利润与销售额，精确到分
```

单值：

```text
2026 年利润为 69.5 万元。
```

无记录：

```text
2026 年没有可计入的订单。
```

## 副题

```text
2026 年；人民币万元
```

查数表写 `2026 年；人民币元`。单位只在这里声明一次。

## 注与资料来源

```text
注：利润率 = 利润 / 销售额。已排除删除订单。产品线按品类汇总。金额四舍五入到 0.1 万元。
资料来源：订单明细，2026 年，按产品线汇总。
```

表达式用中文说清分子和分母，并符合 `skills/warehouse/references/metrics-policy.md`：利润率、折扣率是加权比，订单数按订单去重。过滤、截断、四舍五入、汇总粒度都写在注里。

用户追问口径或要审计明细时，在资料来源之后补实际执行的聚合表达式。默认回答里不出现 `SUM`、`NULLIF`、`YEAR(order_date)`。

## 再跑一句

注里先写明当前粒度，来源之后再提相邻粒度。一次只提一个。

```text
如果你这里的「产品线」指的是更细的子类目，我可以按子类目再跑一版。
```

映射没有歧义时不加这句。

## 失败

查询失败且没有成功事实行时，说明是否已重试、影响哪一项。不给数值结论，不写「数据完整」「完全对账」。
