# Claude Code 数据回答风格

用户看得见的数据回答用这个版式。先把数查实，再按这里写。计算、表路由、加权口径仍走 `warehouse-knowledge` 和 `references/metrics-policy.md`（仓库路径 `skills/warehouse/references/metrics-policy.md`）。本 Skill 不改公式，只改怎么说。

变体骨架见 [references/template.md](references/template.md)。

## 何时使用

拿到事实行、即将写给用户时使用。排名、对比、汇总、单值都用。还在查数、权限被拒、工具失败时不要用这套版式编一个空表。

## 版式

固定顺序，没有内容的段落直接省掉，不要写「无」占位。

1. **导语**：一行。点明业务词对应的字段、时间、排序指标和方向。
2. **结果**：多行用一张表；单值用导语里的那个数字，不再套表。
3. **口径**：紧跟结果的一行，以 `口径：` 开头。
4. **再跑一句**（仅当业务词可能对上更细或更粗的字段）：一行，主动提出按相邻粒度再跑。

不要在前面加「我来查一下」「根据查询结果」。不要加 Markdown 标题。不要加列表符号。不要在答案后再贴一块英文 Provenance。

## 导语

句式：

```text
按 `字段` 作为「业务词」，{时间} {指标}{升序|降序}排名如下：
```

业务词用「」。字段名用反引号。时间和排序方向写进同一句，让读者不用翻表也能知道这张表在比什么。

用户用的词已经就是字段名、没有映射时，省掉「作为」：

```text
2026 年利润降序排名如下：
```

单值题把数字放进导语，后面直接接口径，不另起一张只有一行的表：

```text
2026 年利润为 695,466.02。
```

## 表

- 排名题第一列是 `排名`，从 1 起，按导语里的指标和方向排。
- 表头用业务词（`产品线`），不用 `category`。字段名只出现在导语和口径。
- 只放用户要的列。某一行是推算、无记录或口径不同时，才加一列 `备注`。
- 一个单元格一个值，不要在单元格里换行。
- 金额：千分位，两位小数，如 `368,547.11`。负数保留负号。
- 比率：表内写成百分号、两位小数，如 `18.66%`。口径行仍写比值公式，不写 `* 100`。
- 计数：整数，可千分位，如 `1,204`。
- 用户没说取前 N、维度成员不多时给全表。成员很多时给前 10，并在导语写明「前 10」。
- 亏损行留在表里。不要为了好看滤掉 `profit < 0`。

## 口径

一行，以 `口径：` 开头。每个指标写成 `表达式 中文名`，中文逗号分隔；过滤和时间用中文分号接在后面。

```text
口径：SUM(profit) 排名，SUM(sales) 销售额，SUM(profit)/NULLIF(SUM(sales),0) 利润率；过滤 is_deleted = 0，年份为 YEAR(order_date)=2026。
```

- 表达式必须是实际执行的聚合，并符合 metrics-policy：利润率、折扣率用 `SUM / NULLIF(SUM, 0)`，订单数用 `COUNT(DISTINCT …)`。禁止把 `AVG(profit/sales)`、`AVG(discount)`、`COUNT(*)` 写进口径。
- 过滤条件按这次查询实写。超市订单默认写 `is_deleted = 0`；没有该列的来源不要照抄。
- 时间写清字段和谓词，例如 `YEAR(order_date)=2026`。
- 数据截至日和过滤年份不是一回事时，同一行末尾补 `数据截至 MAX(order_date)=YYYY-MM-DD`。过滤本身已经说明期间时，不必再写 freshness。
- 这一行就是用户可见的溯源（来源指标、过滤、时间）。不要再追加 `Source tier / Tables / Measures` 英文块，除非用户明确要审计明细。

## 再跑一句

业务词可以对应更细或更粗的字段时，先按当前最合理的字段答完，最后加一句，不要先反问再查。

```text
如果你这里的「产品线」指的是更细的 `sub_category`，我可以按子类目再跑一版。
```

映射没有歧义时不要加这句。不要一次抛出两个以上替代维度。

## 缺口怎么写

沿用数据问答里的三类缺失，不要都写成 `—` 而不加说明：

- 无记录：导语直接说该期间没有可计入的行，口径仍写过滤条件，并补 `当前查询返回 0 行`。
- 字段为空：表内该格写 `空`，备注写「有记录但未填」。
- 可推算：数字照常给出，备注写「按累计差额推算」。

查询失败且没有成功的事实行时，不要输出带数字的表。说明失败是否已重试、影响哪一项。不要写「数据完整」「完全对账」。

## 禁止

- 开场白、过程叙述、Markdown 标题、emoji 标题。
- 英文 Provenance Footer，或 `### Provenance` 之类的第二块溯源。
- 把完整 SQL 贴进回答。口径行只留聚合表达式和过滤。
- 精确聚合前加「大约」「差不多」。
- 表内再解释公式。
