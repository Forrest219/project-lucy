## 1. 拆分原则

1. **第一类（吸收）**：能接到现行 `0.30` 总账已有合同句／已计划条目的设计口径，写入本文件映射；推进时在对应 Spec／Plan 内消化，**不另立可信证据产品面**。
2. **第二类（未来池）**：尚未在 `0.30` 开工或立项的能力，一律进 [post-0.30 可信证据需求池](lucy-20261115-post-030-trust-evidence-requirement-pool.md)。**入池 ≠ 立项 ≠ 开发授权**。下一产品线开线时再迁入该线总账。
3. **不做清单**（两侧皆禁）：综合可信度分数；第一阶段质量拦截；照搬 Claude live sharing；「有写权限即可认证」；自建完整 DQ 平台；看板／图表库／叙述短视频。

## 2. 第一类：吸收进 0.30（已有／已计划）

| 吸收点 | 挂接 | 吸收内容（设计口径） | 明确不吸收 |
|---|---|---|---|
| A1 物理新鲜度真源 | **P0-B／REQ-030-028**（待 R2-F） | 新鲜度基于物理更新时间或管道任务成败；`not_checked`／过期 ≠ 正常；禁止语义层文件 mtime 冒充业务截止期 | 一次建成全库 CDC；把监控型质量预警整包塞进本条出口 |
| A2 可核对块诚实披露 | **P0-4／REQ-030-022**（功能合同已收口） | 继续强制露出 sources／caliber／cutoff；未检查写 `not_checked`；新鲜度／认证／质量分轨并列的**原则**作为后续扩展解释，**不回写已冻 cutoff 合同** | 重开功能合同；宿主 UI 强制渲染（O1＝A）；未授权前接真实 freshness |
| A3 只揭示不拦截 | **P0-5／REQ-030-018**（已收口）＋呈现闸原则 | 风险／空结果只提示，不因质量新增阻断；既有权限与口径门禁不变 | 新增质量阻断闸 |
| A4 查看者自身权限 | 既有 ACL／行域默认（非新 REQ） | Token 只鉴权不改变行域；**拒绝**分享者代执行（live sharing） | 任何「作者权限代跑」产品形态 |

### 2.1 推进时的动作（仍须各条既有门禁）

- **P0-B**：R2-F／R4 前只改 Spec／Plan 时，可把 A1 与「监控型失败可自动清除」写成设计约束；**不得**借本裁决提前改代码。
- **P0-4／P0-5**：合同已收口；本裁决**不改变** Spec 头部状态，只约束「解释与续作叙事」——续作（如扩路径覆盖）必须走第二类池立项后迁入总账，不得静默扩已收口出口。
- 任一吸收点若要变成可测出口增量，须**新 REQ + 总账行**（可标不入核心分母），不得旁路。

## 4. 与 0.30 总账的关系

- 本拆分**不**向 `0.30` 总账新增第二类工作项行（避免未开线能力占满跟进带宽）。
- `0.30` 总账变更行登记本裁决指针；P0-4／P0-B／P0-5 摘要可链回 §2。
- 第二类任一 REQ 被下一产品线采纳时：先入该线执行总账并回写该线需求池，再开 Spec。
