| 状态 | `open`。名册 503 已复现，现场握手长尾已定位阶段，细粒度归因待查 |

## 1. 症状与影响

- 客户完整名册三次由 Lucy 返回 `DISPLAY_SNAPSHOT_BUSY`。恢复后同接口服务端仅 65–81 ms，约 4.90 MiB 的完整响应下载仍用 11–19 秒。快照忙与完整响应传输是两个可独立出现的用户问题。
- 现场四条握手耗时 26.8–43.3 秒。KTX 上游响应头为 4–657 ms，Lucy `catalog_resolve` 为 16.6–28.9 秒、`skills_load` 为 7.9–14.0 秒。两段合计约占 93%–96%。另三条独立 `lucy_catalog` 用时 77–87 秒，其自身阶段埋点未覆盖目录处理，暂不能逐项归因。

## 2. 复现要点

使用现场同提交，载入全局基线的 500 Agent、200 正式角色、2,006 张物理表和约百万条合成审计。先校验合法纯 MCP 身份的 1,403 个可见 Source 与真实订单数，再比较热态、并发及正式配置写入同窗。每次用真实前台 Chrome 等待本轮名册可见。

两次定向跑次均在写入同窗看到摘要 503；最终一轮服务端 1,518.8 ms，`permissions` 1,432.5 ms，`builds=0`。同次页面重试返回 200，页面 5.42 秒就绪，进程无需重启。最终一轮的写入窗四条合法 MCP 旅程均完成，握手最长 5.43 秒。20 并发握手全部拿到响应，P50 1.58 秒超过既有 200 ms 门槛；四条写入同窗样本也出现超过 5 秒的握手，应按正式 20 并发变更窗复验。详见[全局规模跑次](../qa/uat/suites/interactive-read-resilience/runs/2026-11-23-kscc-global-baseline.md)。

## 3. 根因与证据边界

- **名册 503。** Agent 普通备注保存也走权限写屏障。名册摘要依赖已核验的权限与连接代次，写入待完成、核验逾期或代次变化时，读取共用 1.5 秒恢复等待预算，超时会返回业务 503。写入同窗的反复复现确认该路径可触发故障；`builds=0` 说明该请求未启动构建。未采到这些请求的内部原因，仍需区分 `write_pending`、核验逾期、代次变化等实际分支。现场原始请求缺少同请求关联及同实例写入流水，触发条件待核对。[写入屏障](../../webui/server/admin/agents.ts#L303) · [快照读取](../../webui/server/display-snapshot.ts#L619)
- **MCP 握手。** Lucy 在应答前串行构建目录和 Skill 指引。描述索引即使命中也先遍历并逐文件 `stat`，未命中还要读 YAML 并再次验指纹。每次握手用 `loadAllSkillsFresh()` 扫描并加载 Skill，再筛选权限。记录确认这两段是现场长尾所在，尚不能把其墙钟耗时拆成读盘、计算或调度等待。现场四次都只解析 7 个 Skill；管理面当前见到 26 个成功解析的 manifest、2,643 条启用表记录，受影响 MCP 身份及磁盘扫描量仍待补采。不同口径的计数只能作为夹具线索。[索引指纹](../../webui/server/proxy/source-descriptions.ts#L267) · [握手构建](../../webui/server/proxy/mcp-proxy.ts#L2119)
- 写入同窗两条路径都有放大，支持继续排查共享资源竞争。现有记录未把两条现场症状关联到同一请求窗口、实例或阻塞函数。

## 5. 举一反三

1. 每次升级按实际运行的构建 SHA、镜像摘要和动作记录核对修复差集。发包稿只能证明计划版本，现场生效版本要取运行证据。
2. 用合法纯 MCP 查询、前台页面就绪与真实配置信号建立同窗对照。保留首个失败、恢复过程和分母。兼容成功、热态收益与并发尾部各有独立断言。
3. 以可见目录、逐连接文件分布、真实权限展开和响应体积核验夹具。全局资源水位作为压力档，现场复现按已验证的受影响范围取样。
4. 按请求记录耗时、快照忙原因及代次。进程健康状态继续反映进程与接流条件，用户路径延迟使用独立指标。
