## 1. 症状与影响

- 客户 2026-11-17 升级到含 P1-20 修复的 `abb38913`，随后**回退**到 `3a9f0711`。现场同事 2026-11-18 的健康检查确认当前版本为 `3a9f0711`。
- 客户在「准备表结构」读 `hive-jd` 字段失败，页面只有「表「…」没有读到字段。」（HTTP 400 `READ_FAILED`）。排障因此围绕「hive-jd 的 Kerberos／元数据服务」展开：写了取证清单、两轮行动指南、Kerberos 指纹字典，现场做了两轮取证。
- 现场两轮取证结论是 SelectDB 一侧此刻健康（冷表 `DESC` 50 到 235 毫秒成功，权限、表形态都排除），而页面仍失败，排障陷入僵局。
- 影响面：客户当前版本下，**所有**外部目录（`hive-1`、`hive-jd`）读字段都失败，与 Kerberos 无关。

## 2. 复现要点

同一套 SelectDB、同一份连接配置、同一批表：

| 项 | `3a9f0711`（客户当前版本） | `71e5b941`（当前 HEAD） |
|---|---|---|
| 页面「准备表结构」读 `hive-1` | 失败，`READ_FAILED`，约 470 毫秒 | 129 张表 129 成功 |
| 页面「准备表结构」读 `hive-jd` | 失败，同上，约 460 毫秒 | 177 张表 177 成功 |
| 容器内 `ktx sql --connection … "DESC …"` | `SQL contains read/write operation: Describe`，约 0.45 秒 | 同左（KTX 本身就拒绝） |
| SelectDB 审计里该 Lucy 来源的 `DESC` 条数 | **0**（只有 `SHOW`） | 618 |
| 同一张表在 SelectDB 里直接 `DESC` | 成功，49 到 231 毫秒 | 同左 |

失败耗时约 0.5 秒，与现场 11-17 记录的 1.18 秒、2.77 秒同量级（KTX 守护进程冷启动时约 2.3 秒）。有 Kerberos 的 `hive-jd` 与无 Kerberos 的 `hive-1` 同样失败、提示一样。

页面上读**不存在的表**也是同一句提示，因此取证必须用真实存在的表。

## 3. 根因

- **版本**：`3a9f0711` 不含 `97fe7ee8`。读外部目录单表字段走 `ktx sql` 发 `DESC`（`readCatalogTableColumns(... execute: typeof runSql)`）。
- **KTX**：KTX 0.16.0 的只读校验在本地拒绝 `DESC`／`SHOW`，请求**不会到达 SelectDB**。`abb38913` 起改走直连通道，没有这个问题。
- **呈现**：KTX 本地拒绝与 SelectDB 返回错误在页面上是同一句话，原因同 P1-43。
- **未证明的部分**：现场 11-17 记录的 1.18 秒、2.77 秒和 `hive-1` 结构差异 `QUERY_FAILED`，没有时间戳，**未能确认**发生在回退前还是回退后；回退前 `abb38913` 上「`hive-1` 能读、`hive-jd` 不能读」的症状，本机用 `71e5b941` 在两个目录上都成功，**没有复现**，原因仍未知。

## 4. 为何漏检

- **回退没有对照已修复项。** 回退到旧基线等于把已修复的缺陷放回客户，但回退时没有「基线缺哪些已修复项」的清单，也没有对外部目录读字段做回退后冒烟。
- **P1-20 的客户现场复测一直是「未验」。** 总账里该条只有本机结论。
- **取证清单第一步没有固定版本。** 两轮清单都从 SelectDB 一侧入手，没有先要 `gitSha`，也没有强制同时测无 Kerberos 的 `hive-1` 作对照。
- **症状与变量绑定。** 把「`hive-jd` 失败」直接当成 `hive-jd` 的问题，没有先排除「所有外部目录都失败」。
- **耗时没被当作指纹。** 约 0.5 秒的失败不可能来自 Kerberos 握手或元数据服务，这一点本可更早用来判断。

## 5. 举一反三

1. 排障第一步先固定变量：版本（`gitSha`）和对照组。必须同时测一个已知正常、结构相近的对照连接（本案是无 Kerberos 的 `hive-1`），再讨论某个连接独有的原因。
2. 回退基线前，先列出「基线缺的已修复项」，回退后对这些项做冒烟；回退不是中性操作。
3. 失败耗时先看数量级：亚秒级的失败不会来自网络握手或服务端慢；请求是否到达服务端，要看服务端审计里有没有这条语句。
4. 给现场的取证清单，第一项必须是版本号，第二项必须是对照组。
5. 排障前先确认测试对象真实存在：本案里不存在的表与真正失败的表提示相同，是 P1-43 范围内的同类问题。
