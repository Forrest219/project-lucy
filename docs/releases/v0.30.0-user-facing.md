# Lucy 0.30.0

本版主题是把问数从「能查」推到「查得对、答得清」：选表与口径有硬约束，成功答复可核对，空结果有下一步；运维侧补齐概念治理与连接生效反馈。相对上一 tagged 版本 `0.25.0`。

> 产品叙事对齐分支 `lucy-v0.30` tip `8f6d612a`。客户交付与正式 tag 以发版台账为准；本文件不代替 `v0.30.0-release-notes.md`／`v0.30.0.json`。

## 行级隔离（核心闸，尚未验收）

## 问数约束：选对表、守住口

### 问题类型绑定固定表与口径

运维可以为某类业务问题绑定「唯一数据源 + 固定口径」。Agent 或客户端若偏离该绑定去查别的表、换别的口径，Proxy 会当场拒绝，并且不会把错误请求送到上游执行。之前只能靠提示词软约束；现在命中绑定后有硬门闩。

### Catalog 带上业务语义

可见表在 Catalog 里会带回业务描述等语义信息，选表时可以按业务含义判断，而不只盯着表名字符串。首期列表排序仍是字母序；按业务相关度排序不是本版承诺。

### 按 Source 裁剪可见字段

可以按数据源裁剪暴露给 Agent 的业务字段。权限范围内「看得见但不该用」的列可以收起来，缩小误用面。

### 多表命中：能判断的放行，拿不准的放行并披露

当多个可见来源都可能回答同一业务词时，系统按三档处理，不再一刀切地先澄清：

- **多张表已被语义层声明过 join 并连成一个整体**（含经中间表传递连通）：直接放行，答复里不额外加提示。这是分析师的正常多表查询路径。
- **多张表互相没有声明过 join，或钉选的表不在业务词命中范围内**：照样放行，但成功答复的 `answer_verifiability` 里会加一个 `sourceSelection` 字段，写明实际用了哪些来源以及原因，并在服务端审计里留一条记录（只记来源与原因，不记取值）。
- **仍然硬拦的情形**：引用了解析不到的来源、Catalog 健康检查失败、跨连接、一次引用超过 4 个来源。这些在任何档位之前判断，错误请求不会送到上游。

另外，还没调用 `lucy_begin_question` 就直接钉选多张已连通表时，同样按第一档放行，不披露也不审计；一张表都没钉选时，仍会提示先说明要用哪张表。

## 答复呈现：可核对、空结果有路

### 成功答复强制可核对信息

纳入路径的成功查询答复会带上来源、口径与截止期等可核对信息。物理新鲜度真源尚未齐备时，截止期可以诚实标成「未核对」，而不是假装已经核过。

### 空结果给出结构化下一步

查询严格返回 0 行时，结果里会带上结构化的下一步指导（例如去核对粒度、周期或筛选项），减少空结果后瞎编或原地打转。

## 问询预算与复盘

### 默认预算更宽

默认问询预算窗口放宽到 60 次调用／300 秒（续查仍限 1 次）。正常的多步问数更不容易被过早掐断。

### 审计能复盘预算卡点

审计记录可带上问询预算快照，以及调用流水表尾相关字段。事后更容易分清是卡在预算，还是卡在业务与数据本身。

### 调用链路可追溯（审计）

每次 MCP 调用现在会按阶段（准入、权限、选表、预算、上游调用、响应序列化等）各记一条阶段记录，同一次调用共用一个 Trace ID（调用链路 ID）。事后可以看到一次调用在哪个阶段花了多久、在哪个阶段被拒绝，而不只看到最终状态。阶段记录与调用流水在同一个事务里写入，不会出现有调用无记录或反过来的半截状态。

封存导出（v2）因此有两处变化，**既有列的顺序与内容都没有改**：

- 新增文件 `spans.csv`，每行一条阶段记录，manifest 里登记行数、sha256 与截止序号；导出状态里新增阶段记录的覆盖率和未排序数量。
- `calls-v2.csv` 在**末尾**追加三列：`ip_source`、`trusted_source`、`rejection_fingerprint`。历史行这三列为空；`rejection_fingerprint` 是带服务端密钥的摘要，不含入参原文。读取该文件的下游脚本如果按列位置解析前 44 列，不受影响；如果校验"列数必须等于 44"，需要放宽。

已知限制：正式完整导出（`mode=complete`）目前仍会因一项既有的失败关闭条件拒绝出包，`spans.csv` 只在诊断导出里验证过。本项不入核心分母，测试台为 PASS WITH GAP。

## MCP 连接体验

- **握手更快**：`initialize` 返回的说明文本在权限与技能未变化时走缓存，宽目录（几百个 Source）下握手长尾明显缩短。
- **拒绝更快**：被门闩拒绝的请求不再先编译一遍 Agent 权限，宽目录下拒绝响应的 P50 约从 570 ms 降到 190 ms。
- **失败信息可操作**：调用不存在的工具名时，会返回当前身份真正可用的工具清单；缺少 `measures` 等必然被拒的形状在转发前就以明确文案返回；会话丢失返回结构化的 `session_lost` 并提示重新 `initialize`。
- **重复被拒有提示**：同一会话 60 秒内把同样的请求原样再发一次被拒的请求，响应会附"相同请求刚被拒绝，请勿原样重试"和下一步建议。

持续失效时的自动短路本版没有做；本项测试台为 PASS WITH GAP，不入核心分母。

## 概念治理（运维）

运维可以通过 Lucy Ops 控制面维护轻量概念注册表：扫描候选、人工审写后生效。本版概念注册表的产品交付面是 Ops MCP；没有单独的概念 CLI，也没有 WebUI 概念页。

## 连接与执行层

创建或编辑连接后，在具备 supervisor 的环境里，写路径会统一走执行层重载。成功面上会诚实回报配置是否已经进入执行层，避免「界面显示保存成功，问数却还在用旧连接」的假象。（清单 P1-15／REQ-030-036；不入核心分母。）

## Fixes

- **访问关系图**（P1-17／REQ-030-038）：会话 begin 之后，同会话触表会写入 confirmed；还没有任何访问时会画出闲置骨干连通带，空白桑基不再容易被误当成故障。
