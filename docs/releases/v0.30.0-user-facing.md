# Lucy 0.30.0

本版主题是把问数从「能查」推到「查得对、答得清」：选表与口径有硬约束，成功答复可核对，空结果有下一步；运维侧补齐概念治理与连接生效反馈。相对上一 tagged 版本 `0.25.0`。

> 产品叙事对齐分支 `lucy-v0.30` tip `eb38eee5140c`。客户交付与正式 tag 以发版台账为准；本文件不代替 `v0.30.0-release-notes.md`／`v0.30.0.json`。

## 问数约束：选对表、守住口

### 问题类型绑定固定表与口径

运维可以为某类业务问题绑定「唯一数据源 + 固定口径」。Agent 或客户端若偏离该绑定去查别的表、换别的口径，Proxy 会当场拒绝，并且不会把错误请求送到上游执行。之前只能靠提示词软约束；现在命中绑定后有硬门闩。

### Catalog 带上业务语义

可见表在 Catalog 里会带回业务描述等语义信息，选表时可以按业务含义判断，而不只盯着表名字符串。首期列表排序仍是字母序；按业务相关度排序不是本版承诺。

### 按 Source 裁剪可见字段

可以按数据源裁剪暴露给 Agent 的业务字段。权限范围内「看得见但不该用」的列可以收起来，缩小误用面。

### 多表命中先澄清

当多个可见来源都可能回答同一业务词时，系统不会静默挑一张表成交。需要先澄清选哪张，或失败关闭；用错限定名也可以被拦住。

## 答复呈现：可核对、空结果有路

### 成功答复强制可核对信息

纳入路径的成功查询答复会带上来源、口径与截止期等可核对信息。物理新鲜度真源尚未齐备时，截止期可以诚实标成「未核对」，而不是假装已经核过。

### 空结果给出结构化下一步

查询严格返回 0 行时，结果里会带上结构化的下一步指导（例如去核对粒度、周期或筛选项），减少空结果后瞎编或原地打转。

## 问询预算与复盘

### 默认预算更宽

默认问询预算窗口放宽到 60 次调用／300 秒（续查仍限 1 次）。正常的多步问数更不容易被过早掐断。

### 审计能复盘预算卡点

审计记录可带上问询预算快照，以及调用流水表尾相关字段。事后更容易分清是卡在预算，还是卡在业务与数据本身。

## 概念治理（运维）

运维可以通过 Lucy Ops 控制面维护轻量概念注册表：扫描候选、人工审写后生效。本版概念注册表的产品交付面是 Ops MCP；没有单独的概念 CLI，也没有 WebUI 概念页。

## 连接与执行层

创建或编辑连接后，在具备 supervisor 的环境里，写路径会统一走执行层重载。成功面上会诚实回报配置是否已经进入执行层，避免「界面显示保存成功，问数却还在用旧连接」的假象。（清单 P1-15／REQ-030-036；不入核心分母。）

## Fixes

- **访问关系图**（P1-17／REQ-030-038）：会话 begin 之后，同会话触表会写入 confirmed；还没有任何访问时会画出闲置骨干连通带，空白桑基不再容易被误当成故障。
- **库内扫表读法**（P1-16／REQ-030-037；事故修复）：Doris 外部目录上的 Hive 类连接列库／列表，以及普通 MySQL 准备表结构，读路径已收敛，减轻慢扫与错扫；此项不作为本版核心能力主张（不入核心分母）。
