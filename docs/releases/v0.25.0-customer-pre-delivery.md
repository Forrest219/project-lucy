## 0. 一句话：客户为什么要升到 0.25

相对 `0.20.0`，`0.25.0` 的核心增益是：**治理台能把「谁能看什么、问了什么、改错了怎么办」说清楚并可操作**——行权限保存前能预览最终约束；问询与用量能对账可读；多表语义可批量维护；误发布可按批次整批恢复；授权与访问关系更可理解。企业登录（OIDC）、可选邮件提醒、Skill 负责人等为增强项，按客户现场需要启用。

## 1. 优先级定义（本文件专用）

| 档 | 含义（用户价值） | 交付口径 |
|---|---|---|
| **P0** | 不讲清／不验过，客户升级收益说不圆；或直接关系到数据安全／误操作可恢复 | 交付说明**必须**覆盖；你**必须**亲手点一遍 |
| **P1** | 明显提升日常治理效率或企业接入体验；缺了体验差一截，但不阻塞「能安全用起来」 | 交付说明建议覆盖；按客户场景抽检 |
| **P2** | 体验打磨或可选能力；默认关闭或不改变主路径 | 按需介绍；启用才验 |

> 说明：仓库内部的「P0-1 审计契约 / P0-2 行权限…」是工程波次编号。下表是**对客户讲故事与自检**用的价值排序。

## 2. 核心功能清单（用户价值增益）

### P0 — 必须讲清、必须验过

| # | 能力（用户语言） | 用户得到什么 | 对应条目 | 交付前须知 |
|---|---|---|---|---|
| P0-1 | **行权限保存前看得清最终约束** | 改角色行策略时，保存前能预览「多角色并集后到底能看哪些行」；字段绑不上时明确失败，而不是悄悄变宽 | L25-14 R2／R4／R5 | 功能合同已收口。重点验：两个受限角色不得预览成「全部行」；保存后配置审计有终结记录 |
| P0-2 | **一笔问询能读完、用量能对账** | 访问日志里点开一笔问询：完整表身份、轮次、调用／尝试、预算是否真耗尽；使用概况里 Token／表排行可对账，不再只有「数据异常」 | L25-02／03（P0-4）+ L25-09 读口径 | 读取合同已收口。重点验：长表清单不收成「等 N 个」；表排行可复制完整 `connectionId / schema / table` |
| P0-3 | **多表语义可批量维护并生效** | Catalog 多选下载维护包、批量校验、导入预览冲突；发布工作台统一确认生效；失败可恢复、写入与生效串行 | L25-11 | 功能合同已关闭（FC-01–32）。重点验：导入只暂存、真正生效走发布台；不误改启用表／角色／行策略 |
| P0-4 | **误发布可按批次整批恢复** | 正式发布前有批次快照；发现误改可预检后整批恢复为新批次（不改写历史），冲突则零写入阻断 | L25-15 | **代码已落地**；正式 SRR 验收矩阵仍在 `0.30` 池。交付前**必须**你亲自做一次「发布 → 恢复预检 → 恢复／冲突阻断」旅程，不得只靠「代码在仓」 |
| P0-5 | **审计事实可信、可导出对账** | 问询／调用／尝试状态统一；导出与只读对账在证据不足时失败关闭，不伪造完整 | L25-09 | 功能合同（S01–S07）已收口。重点验：不可证明时正式完整导出被拒／诊断模式给出缺失集合 |

| 项 | 原因 |

## 3. 交付前自检 Checklist（请你亲自勾）

用法：每项填 `PASS` / `FAIL` / `PENDING` / `N/A`，并记证据（截图路径、包 SHA、URL、时间）。**任一适用 P0 或出包必验项为 FAIL／PENDING，不得标记为可生产交付。**

### A. 版本与制品身份

- [ ] **A1** 产品版本显示为 `0.25.0`（WebUI 版本信息 + `/api/health`），构建提交可复制且与出包 `BUILD-INFO` 一致
- [ ] **A2** 客户镜像 tag 形如 `customer-amd64-0.25.0-YYYYMMDD-<gitSha>`；源码干净（dirty=false）；Chart `appVersion=0.25.0`
- [ ] **A3** 发版台账 `docs/releases/v0.25.0.json` 已回填真实 `commit`、交付包摘要、门禁结果；不再是「仅版本对齐、无包」
- [ ] **A4** 若宣称生产放行：存在 `docs/releases/ux/0.25.0.md` 且结果块为 passed（台账规则要求）

### B. P0 功能手检（用户旅程）

- [ ] **B1 行权限** 建／改含行策略的角色 → 保存前预览显示最终行约束 → 故意绑不存在字段应失败关闭 → 配置审计可见 intent／终结
- [ ] **B2 问询可读** 产生至少一笔真实问询 → 访问日志打开详情：完整表清单、轮次、调用／尝试；长列表不收成「等 N 个」
- [ ] **B3 用量对账** 使用概况：配置 Token 数 vs 窗口内活跃；表排行完整身份可复制；与只读 API／CSV 同一窗口口径
- [ ] **B4 语义批量** Catalog 多选 ≥2 表 → 下载包可再导入 → 批量校验出报告 → 导入预览区分新增／修改／冲突 → 发布台确认生效
- [ ] **B5 整批恢复** 做一次内容发布 → 在发布历史选该批次恢复预检 → 无冲突时恢复生成新批次；人为制造冲突时期望零写入阻断
- [ ] **B6 审计失败关闭** 在证据不足场景（或诊断模式）确认：正式完整导出／对账不会假装「完整」

### C. P1 抽检（按客户合同勾选）

- [ ] **C1 授权摘要** 打开一目标 Agent／角色：不看 YAML 能口述可读表集合；MCP 调试台预览一致
- [ ] **C2 行策略模板／按表反查** 套用模板保存成功；反查页能按表看到授权主体
- [ ] **C3 访问关系图** 打开页面：能指出闲置授权边与需复核边；空图／降级有明确说明
- [ ] **C4 OIDC**（仅启用时）IdP 登录成功；关掉 IdP 后本地所有者密码仍可登录／break-glass 路径仍在
- [ ] **C5 运维 MCP W-A**（仅交付控制面时）`lucy_ops_connection_tables`／`lucy_ops_source_import`：preview→commit，审计可见 actor／委托
- [ ] **C6 Hive** 默认 **N/A**；若客户 POC：单独书面边界「支持状态 planned，非正式 GA」

### D. P2 与体验（可选）

- [ ] **D1 Skill 负责人** 指定／修改／清除 → 配置审计有前后值与操作者
- [ ] **D2 SMTP**（仅启用时）测试邮件可达；未配置时无出网、行为与关闭态一致
- [ ] **D3 IME** Audit／配置审计等 URL 驱动搜索框：中文输入法可正常上屏、切换

### E. 出包与升级安全（供应方硬门禁摘要）

完整条文见客户升级交付 Checklist C01–C20。交付前你至少确认：

- [ ] **E1（C01／C05／C20）** 公共包无密钥；客户私有引导附件与签发状态同次齐备；同实例复用、不同实例独立；已有管理员不重发
- [ ] **E2（C07／C08）** G1–G4／G4b／G4c／G8 过关；linux/amd64 ELF 真验；离线 Python／KTX 可用
- [ ] **E3（C12–C16）** 在约定平台完成：旧版→本包真实升级、管理员旅程、原 MCP Token／业务连续、停机备份、恢复再升级（Helm rollback **不能**代替安全状态恢复）
- [ ] **E4（C13／C14）** 升级后原账号可登录；吊销凭据仍不可用；查询允许／拒绝路径与升级前一致
- [ ] **E5（C19）** 交付说明列出：本文件 P0／P1 主张哪些已验、哪些 N/A、哪些明确不宣称

## 4. 建议的客户沟通顺序（口头／Release Note 提纲）

1. **先讲安全与可信**：行权限预览闭环、审计／问询对账（P0-1／2／5）  
2. **再讲运维效率与容错**：语义批量维护、误发布整批恢复（P0-3／4）  
3. **再讲看得懂授权**：授权摘要、模板／反查、访问关系图（P1-1–3）  
4. **按合同附加**：OIDC、运维 MCP、SMTP、Skill 负责人（P1-4／5，P2）  
5. **明确边界**：不做对话产品；Hive 非正式 GA；帮助中心与升级自动化不在本版主张内
