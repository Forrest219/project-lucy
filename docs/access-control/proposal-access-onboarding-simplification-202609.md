## 0. 一句话结论

当前访问治理把 **企业级 ACL 对象模型**（Role → Agent → Token）和 **控制面登录**（登录账户）并列暴露给管理员，导致几乎所有人都在问「配置逻辑」和「怎么管用户」。  
**问题不在页面不够多，而在默认路径要求用户先成为权限架构师。**  
建议：保留底层模型不变，把默认体验改成 **意图优先（加人 / 开权限）+ 渐进披露（专家能力藏进高级区）**。

---

## 1. 现象与根因

### 1.1 现场现象（产品侧已确认）

- 多数管理员首次到达「访问治理」时，不知道该点 **角色权限 / Agent / Token 凭据 / 登录账户** 中的哪一个。
- 「怎么管理用户」被反复追问：产品里没有叫「用户」的一等入口；真正对应「加人」的是 **Agent**，真正对应「管后台账号」的是 **登录账户**。
- Help / Handbook 里已经写清三层心智与场景速查，但 **文档补救 ≠ 产品默认路径**——用户在进页面之前已经迷路。

### 1.2 设计超前在哪里

| 层面 | 现状（对专家友好） | 用户实际心智（80% 场景） |
|---|---|---|
| 信息架构 | 7 个并列入口：使用概况 / Agent / Token / 角色 / 日志 / 调试台 / 配置审计 | 「给张三开通 Lucy」 |
| 对象顺序 | Role-first：先定权限边界，再建身份，再发凭证 | Person-first：先选人，再选能看什么，再拿配置粘贴进客户端 |
| 概念正交 | 数据面 Agent ≠ 控制面登录账户 ≠ 部署许可席位 ≠ Token | 全部被口语化为「用户 / 账号 / 密钥」 |
| 高级能力默认可见 | Agent 强制约束、多 Role、行级策略、YAML Diff、参考模板 vs 正式 Role | 只要「财务只读」「评测机器人」两类模板 |
| Spec 133 | 在同一心智模型内做 Tab 扁平化、选择器、Danger Zone | **不解决「该点哪个菜单」** |

### 1.3 明确不在本提案范围内

- 不推翻 Role-first 运行时模型、`access.yaml` 结构、Fail-closed ACL。
- 不合并 WebUI 登录与 MCP Bearer（安全边界必须保留）。
- 不在本提案中改 Proxy 裁决语义（`capability` / `row_policy` 等）。

## 2. 设计原则（请审批）

| # | 原则 | 含义 | 建议裁决 |
|---|---|---|---|
| P1 | **意图优先，对象其次** | 默认 CTA 回答「你要做什么」，而不是「你要编辑哪个 YAML 对象」 | ☐ 同意 / ☐ 反对 |
| P2 | **一人一路径** | 「加人」默认一次完成：选权限模板 → 创建 Agent → 签发 Token → 复制 MCP 配置 | ☐ 同意 / ☐ 反对 |
| P3 | **渐进披露** | 行级策略、强制约束、多角色、YAML Diff、全局 Token 清单进「高级」；新手路径不可见 | ☐ 同意 / ☐ 反对 |
| P4 | **术语对外降噪，对内不改 canonical** | UI 主文案可用「使用者 / 权限模板 / 接入凭证」；技术词 Agent / Role / Token 作副标签保留（术语标准可增补别名） | ☐ 同意 / ☐ 反对 |
| P5 | **控制面与数据面物理分隔** | 「WebUI 管理员」永不出现在「加人开权限」主路径；登录账户保持系统设置 | ☐ 同意 / ☐ 反对 |
| P6 | **底层零损失** | 专家仍可进入 Role / Agent / Token 完整编辑面；与 Spec 133 的专家区抛光兼容 | ☐ 同意 / ☐ 反对 |

## 3. 目标心智（对外一句话）

```text
权限模板（Role）= 这类人能看什么
使用者（Agent）  = 具体是谁（审计主体）
接入凭证（Token）= 这台电脑 / 这个客户端怎么连上
WebUI 管理员     = 谁能登录运维后台（另一套，别混）
```

默认操作顺序从「先建角色」改为：

```text
① 选一个权限模板（没有合适的再去「新建模板」）
② 添加使用者并绑定模板
③ 签发接入凭证并复制 MCP 配置
④ 出问题再查访问日志 / MCP 调试台
```

Role-first **作为系统事实**保留；Person-first **作为默认 UX 编排**。

## 4. 优化建议（分轨）

### 轨 A — 默认路径：加人向导（P0，建议优先做）

**入口**

- 访问治理分组顶部增加主 CTA：`添加使用者`（或 `开通接入`）。
- Agent 列表空态 / Token 列表空态 / 角色列表「尚无引用」态，统一引导到同一向导。
- 系统概览若检测到「无启用 Agent」或「无可用 Token」，主待办指向该向导（与 Onboarding 检查对齐）。

**向导步骤（建议 4 步，可回退）**

| 步 | 用户看到的问题 | 背后写入 |
|---|---|---|
| 1 是谁 | 显示名、用户 ID（可自动建议）、启用 | `users[]` Agent |
| 2 能看什么 | 从正式 Role 下拉选择（展示连接 / 表 / 工具摘要）；无合适则「从模板复制新建」旁路 | `roles` 绑定 |
| 3 怎么连上 | 客户端类型（Cursor / Codex / Claude Code / 通用）、可选设备备注、可选过期 | 签发 Token；一次明文 |
| 4 完成 | 复制 MCP 配置 +「去 MCP 调试台试调」+「查看访问日志」 | 无新对象 |

**产品规则写进向导文案（防误配）**

- 「同一人多台电脑：不要再点添加使用者，应在该使用者下再发凭证。」
- 「权限变了：改权限模板，不要给每人重发特殊 Token。」
- 「WebUI 后台密码在系统设置 → 登录账户，与接入凭证无关。」

### 轨 B — 信息架构：从「对象仓库」改为「任务 + 专家区」（P0/P1）

**建议导航（访问治理）**

| 现导航 | 建议 | 理由 |
|---|---|---|
| 使用概况 | 保留 | 运维观测 |
| Agent | 改名为 **使用者**（副标题保留 Agent） | 对齐「怎么管用户」口语 |
| Token 凭据 | 降为 **使用者详情内嵌**；全局清单移入「高级 / 全部凭证」 | 全局 Token 页对新手是碎片 |
| 角色权限 | 改名为 **权限模板**（副标题保留 Role） | 降低「角色=人」误解 |
| 访问日志 | 保留 | 排障 |
| MCP 调试台 | 保留，但空态链回向导 | 试调入口 |
| 配置审计 | 移入折叠「高级」或系统设置旁 | 低频 |
| （新增） | **添加使用者** 向导入口（可非独立路由，挂在使用者页顶） | 默认路径 |

**登录账户**

- 系统设置内标题改为更明确：`WebUI 管理员账户`（术语可登记别名）。
- 在使用者向导与 Agent 页增加一次性说明条：「这里管的是数据问答接入身份，不是后台登录账号。」

**审批点 B2**：全局 `/admin/tokens` 是否降级为高级入口？  
☐ 降级　☐ 保留主导航　☐ 主导航保留但默认引导进 Agent 详情签发

### 轨 C — 权限模板体验：先「选」后「编」（P1）

当前 Role 详情 5 Tab + 杂交表选择器（Spec 133 已指出）对专家都重，对新手更重。

**建议分层**

1. **选用层（默认）**：卡片/表格展示正式模板；一行说清「谁在用、覆盖几张表、几个工具」；主操作是「用于添加使用者」。
2. **编辑层（次级）**：进入 Spec 133 规划的扁平工作台（资产层级选择器、Danger Zone、Pre-flight Diff）。
3. **专家层（折叠）**：行级策略、`catalog_bound`、`permission_model_version`、多 Role 能力代数说明。

**出厂模板策略（交付友好）**

- Demo / 新部署预置 2～4 个可读正式 Role（如：业务只读、评测只读、运维数据面 `lucy_admin`），避免「只有参考模板、看起来能跑其实不能绑」。
- 参考模板在列表中视觉降权（已有 Spec 59 方向），主按钮永远是「复制为正式模板」而非「分配」。

**审批点 C1**：是否要求新部署默认带齐可读正式权限模板（不仅参考模板）？  
☐ 是　☐ 否（客户自行从参考模板复制）

### 轨 D — 渐进披露高级 ACL（P1）

默认隐藏或折叠：

| 能力 | 默认 | 入口 |
|---|---|---|
| Agent 强制约束 | 折叠「对单人再收紧」 | 使用者详情 → 高级 |
| 多 Role 绑定 | 默认单选 Role；「绑定多个模板」进高级 | 同上 |
| 行级策略 / predicates | 权限模板编辑 → 高级 | Role 工作台 |
| YAML Diff | 仅在保存确认弹窗出现（对齐 Spec 133 Pre-flight） | 保存时 |
| 编译器口吻文案 | 删除；改为权限管线示意 | Spec 133 §3.3.2 |

**审批点 D1**：AC-P1.5 强制约束是否默认折叠？

### 轨 E — 决策教练内嵌产品（P1，低成本高收益）

把 Handbook「场景速查」做成页面内 **决策条 / 空态教练**，而不是只靠 `/help`：

| 用户说 | 产品引导 |
|---|---|
| 新同事要开始用 | 打开「添加使用者」向导 |
| 换电脑 / 新开 Cursor | 进入该使用者 → 签发凭证 |
| 整组扩权 / 收权 | 编辑权限模板 |
| 某人比同组更严 | 高级：单人收紧；或换更窄模板 |
| 密钥可能泄露 | 撤销该凭证并重发 |
| 要登录 WebUI 后台 | 系统设置 → WebUI 管理员账户 |

## 5. 非目标与风险

| 风险 | 缓解 |
|---|---|
| 「使用者」与「登录账户」仍被口语混淆 | 文案强制对照；向导内阻断式说明；禁止在 Agent 页出现「密码」字段 |
| 向导弱化 Role-first，导致每人私有权限 | 向导强制先选模板；「从零手搓权限」不进默认路径 |
| 导航改名冲击测试断言 / 术语标准 | 先增补术语标准别名，再改 UI；断言同步 |
| 全局 Token 页降级后运维丢入口 | 「高级 → 全部凭证」+ 使用概况下钻保留 |
| 与已批准 Spec 133 文案冲突 | 本提案批准后，修订 Spec 133 范围说明：专家编辑面，不负责默认 onboarding |
