## 建议包 E（推荐整包采纳）

| 项 | 建议裁定 | 若不采纳时的替代（须书面另选） |
|---|---|---|
| **O1** 体感分公式 | `realQuestions < 1` → 不可用。否则 `score = clamp(0, 100, round(100 - 40×空结果率 - 30×拒绝率 - 20×慢标记率 - 10×(首次成功 ? 0 : 1)))`。某一率分母为 0 时该项惩罚按 0，不把缺样本当 100% 失败。`round` 四舍五入，.5 向正无穷 | A′：保留 D13，权重仍开放至 O 闭合——阻塞 SC-06；B′：二元「顺畅／不畅」无连续分——不满足 per-user 0–100 承诺 |
| **O2** 阈值跌破 | 默认滚动 **24h**。仅率状态 **可用** 时告警：首次成功率 &lt; 0.5，或空结果率 &gt; 0.4，或拒绝率 &gt; 0.2。`no_data`／`unavailable` 不告警。回到阈值内入队一次恢复事件，去重键含指标与窗口桶 | A′：7d 窗口或三套阈值另值——须书面写清并与 SC-11 对齐；B′：只告警无恢复事件——运维无法确认自愈 |
| **O3** 连续空结果 | **N＝3**。同一 `user_id` 最近成功查数尾部连续 `result_empty=1` 达 3 则触发；中间非空成功打断。去重键：**用户 + 上海日期**，同一天只入队一次 | A′：N≠3 或 `streakId` 粒度——须写 SC-12；B′：全局累计空结果不计用户——误报面过大 |
| **O4** 反馈入口 | **延期**。反馈入口**不在本条出口**；日后若做 P0-min 须另升版本补验收 | A′：**P0-min**（单入口写本地台账或 admin-only API）——范围紧时勿默认；与本条 Spec §3 非目标冲突须书面豁免 |
| **O5** 邮件用户标识 | 邮件只含**角色 id** 与 `user_id` 的 **sha256 前 8 位**；不含明文 `user_id`、问句、SQL、行级业务值 | A′：明文 `user_id`——隐私与合规风险；B′：仅角色无用户锚点——排障困难 |
| **O6** SMTP profile 键 | 键名 `notifications.experienceAlerts`，布尔，**缺省 false**。解析与热加载与现网 `notifications.auditHealth` **同级且互不影响** | A′：并入 `auditHealth` 单开关——与 D9 正交原则冲突；B′：缺省 true——未配置环境噪音告警 |

整包采纳后的合同后果（授权后才实现）：

1. O1 闭合后 `composeExperienceScore` 按上式产出 0–100；O1 未闭合时仍只返回 `null`／`unavailable`（D13）。
2. `experienceMonitorTick` 在 O2 闭合后按 24h 阈值判定 breach／recovery；`no_data`／`unavailable` 永不入队跌破告警。
3. O3 闭合后连续空结果按 N=3 + 日级去重 enqueue；Admin 读取路径仍不入队（D12）。
4. O4＝延期：本条 SC 无反馈入口验收；清单可登记「反馈另条」。
5. O5 闭合后告警 payload 脱敏策略固定为角色 + hash 前缀。
6. O6 闭合后 profile 关则只算仪表盘、`experienceAlerts=false` 时不入队。
