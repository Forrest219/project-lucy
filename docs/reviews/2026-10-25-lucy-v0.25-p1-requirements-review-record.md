## 3. 审查发现（实施前待办）

四条均为**不退回**项：不影响设计基线成立，但必须在对应实施开始前关闭。

### F-01 P1-2 深链的 `tool` 参数当前不承载行为

- **现象**：P1-2 §4.1 的深链形如 `/admin/mcp-playground?agentId=<userId>&mode=dry-run&tool=lucy_query&args=<url-encoded-json>`。代码事实是：页面只读 `args`、`agentId`、`mode`（`webui/src/pages/admin/McpPlayground.tsx:41-56`、`:90-91`、`:89`），ACL 预览的工具名是**硬编码** `lucy_query`（`:233-237`），受控试调硬编码 `tools/list`（`:245-249`）；且 `useEffect` 在加载后主动把 URL 中的 `tool` 与 `args` 删除（`:132-138`）。
- **影响**：今天该链接可用——`args` 的 `connectionId`／`sourceName` 预填已被既有测试覆盖（`webui/src/__tests__/mcp-playground.test.tsx:371-383`）。但 `tool` 是装饰性参数：URL 里的值被丢弃，实际工具由页面硬编码决定。若实施期调试台支持多工具选择，URL 中的 `tool` 会静默失效而不报错。
- **处置**：实施前二选一——① 页面改为消费 `tool` 参数并据此选择工具；② 明确深链只承载 `agentId`／`mode`／`args`，从 Spec 删去 `tool`。

### F-02 授权路径计数单位的表述不统一

- **现象**：`webui/docs/187-access-relation-sankey-spec.md` §4.2（规范性）与术语标准「访问权限升级」节的 `Grant Path` 条目用五元组 `(Agent, Role, Connection, Schema, Table)`；同一 Spec 的 §3.3、§4.1，以及 P1-1 裁决 P1-D7 用三元组 `(Agent, Role, Table)`。
- **影响**：Schema 默认折叠时两种写法等价，不改变计数与守恒结论；一旦按三元组实现并在展开 Schema 层时使用，会把跨 Schema 同名表误合并。
- **处置**：实施前把 §3.3／§4.1／P1-D7 的表述统一为「规范源键」（或五元组），并以 §4.2 为唯一规范性定义。

### F-03 术语标准存在重号 `§4.8`

- **现象**：`webui/docs/00-product-terminology-standard.md` 有两个 `### 4.8`——`:684`「MCP 调试台／ACL 裁决可见性」与 `:701`「访问权限升级」。该重号为**既有问题**（HEAD 已存在），本轮 P1 新词条落在 `:726-735` 的第二个 §4.8。
- **影响**：既有引用按内容分别指向两个小节（`docs/ui-ux-feedback/pages/admin-audit.md:403` 指向第一个；`docs/access-control/plans/20260809-gate-c-sc-evidence.md:154` 指向第二个）。直接重编号会破坏其中一类引用。
- **处置**：不在本轮重编号（属独立文档 housekeeping）。本轮 P1 引用一律写作「术语标准 §4.8 访问权限升级」消歧；真正重编号须单独一次变更并同步全部引用。

### F-04 Hive 三个新术语未进术语标准

- **现象**：P1-4 Terminology Compliance 声明 `HiveServer2（HS2）`、`Hive 直连`、`Hive 编译桥` 三个新词，只在该 Spec 内登记；术语标准 §4.1 数据库接入未收录。
- **影响**：符合 AGENTS.md「新模块新增产品概念时，必须先补充术语标准**或**在功能 Spec 的 Terminology Compliance 小节登记」，因此不构成退回；但连接界面文案若引用「Hive 编译桥」，将没有标准依据。
- **处置**：实施期写连接界面文案前，按 AGENTS.md 补入术语标准 §4.1，或在 UI 规范中登记。
