## 2. Spec 收口决议

### L25-09

- 不重开 U1–U12；实施 Plan 先完成 R1–R10／R12 同步，A01–A12 继续保持未执行直至取得真实证据。
- Stage 1 在开发单机执行 A01–A12；Stage 2 在 linux/amd64 K8s 单副本重跑 **A01／A02／A04／A10／A11**。静态回放、文档冻结或环境不足不得记为运行通过。

### L25-14

- 修正 OR 合并伪代码：不得用 `all` 初始化累积值；增加“两个受限 Role 不得预览为全部行”的反例。
- 保存前预览必须使用 draft 覆盖后的候选配置，经运行时同一编译路径 dry-run，不得读取旧配置或提前落盘。
- 模板存储 D1、`commitEffectivePolicy`、配置审计 intent／终结记录及失败恢复作为同一合同裁决；禁止运行时权限已放宽但无有效审计。
- `catalogLoaded` 必须来自 Schema Manifest 的真实路径解析、读取与解析结果，区分“字段不存在”“清单不可用”“目录能力未知”，三者均失败关闭。
- D-03 归属 **0.20.Z 维护线（当前基线 `0.20.0`）**，是受影响客户环境的交付价值依赖，不是 R2／R4／R5 的开工依赖；V19–V22 在 v0.25 作为集成回归，不重复计作新功能。台账补充该归属注记，`fixedIn` 在实际修复验证前保持为空。
- 重编两个 `### 1.4`，同步全部 **9 处内部指针与 3 处外部指针**；统一 V01–V22 完成口径及模板下拉、模板删除的已知歧义。

### L25-11

- 实库执行“不在本期验证”必须作为独立证据或不适用维度，不得进入阻断 verdict；`not_run` 仅表示应执行但因超时、取消等未执行的检查，消除正常发布必被阻断的矛盾。
- D1–D4 在冻结前裁决。D4 与 L25-14 D6 联动：角色保存是否进入共享协调器必须明确；共享写入口、运行镜像或恢复状态时写入与生效串行，只有证明资源与故障域隔离后才可并行。

### 版本与评审记录

四份 Spec 统一重打 v0.25 目标版本、评审状态与 P0／P1／P2 优先级；L25 与文件名中的 `v2p5` 仅保留为既有标识。仓库只保留本 Final 决议，不保留交叉审阅和复核过程稿。

## 3. Wave 0b：交付链必须实测解锁

GHCR 命名空间／令牌权限失败已记录在 v0.20.0 发布台账与发布说明中，属于既有阻断；Wave 0 将其挂入 G-01 或新建缺陷条目，明确责任与关闭证据。本决议选择**解锁交付链并保留完整 P0 退出标准**，不改为“除交付链外通过”。

1. **镜像可推送、可拉取**：设置 `LUCY_IMAGE_NAMESPACE=forrest219`，或配置对目标命名空间具有 `write:packages` 的等价凭据；实际产生候选 registry digest。Helm Chart 与 Compose 无需连带修改。
2. **2a—`real-e2e` 可调度**：注册带 `self-hosted, lucy-protected, linux, amd64` 标签的受保护 runner，消除无 runner 导致的未调度。
3. **2b—`real-e2e` 可运行并产出证据**：
   - 配齐 `LUCY_E2E_NAMESPACE`、`LUCY_E2E_BASE_URL`、`LUCY_E2E_MCP_URL`、`LUCY_E2E_DB_HOST`、`LUCY_E2E_DB_PORT`、`LUCY_E2E_DB_OWNER_ROLE`、`LUCY_E2E_CAPABILITIES`；
   - 配齐 `LUCY_E2E_ANTHROPIC_API_KEY`、`LUCY_E2E_OPENCLAW_API_KEY`、`LUCY_EVIDENCE_SIGNING_KEY`；
   - 准备 kubectl／helm 与隔离 K8s 命名空间、工作流要求的 **Claude Code＋OpenClaw** 真实客户端、一次性 PostgreSQL 及 per-run owner 凭据；
   - 以同一候选镜像跑通原生 amd64 构建／推送、门禁和真实 `real-e2e`，产生可复查证据包。

仅设置变量、注册 runner 或达到“可调度”不算解锁完成。未完成时整批 P0 保持 **`blocked_delivery`**；未调度、推送失败、环境不足或证据缺失均不得记 passed。执行时重新核验 GitHub 配置快照。
