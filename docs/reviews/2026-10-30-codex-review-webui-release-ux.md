# 发版前 WebUI 三层检查：Codex 交叉审阅

- 审阅方式：本机 Codex CLI 0.163.0，`codex exec -s read-only`，只读，未改文件。
- 第 1 轮对象：Spec v1.0 与 Plan v1.0。
- 第 1 轮结论：退回修订。阻塞 0，高 3，中 5，低 0。

## 第 1 轮发现

Codex 原文如下。

1. **F01｜高｜脏构建分支仍可落到 passed**
   - 位置：Spec §4，UX-R01。
   - 问题：`workspace is dirty` 只声明不能签通过，没有返回。表面全 PASS 时后续仍会 `passed`。
   - 最小修复：把构建提交、健康检查、脏构建设为提前返回，并增加「表面全绿但构建脏仍不得 passed」的断言。

2. **F02｜高｜结构层红分支无法生成符合自身规则的非生产台账**
   - 位置：Spec §4，Plan §6。
   - 问题：结构层红时禁止走查，但 `notExecuted` 又要求写明走查已经做完。
   - 最小修复：拆开两种 `notExecuted`：结构失败导致走查未开始；走查完成但阻断未关闭。

3. **F03｜高｜生产放行约束没有落实到台账校验与验收**
   - 位置：Spec D8、SC-10，Plan S3。
   - 问题：现有校验器不要求特定门禁存在，也不检查 `productionReady`。只加手工 evidence 例外时，可生产记录仍可以没有这条门禁。
   - 最小修复：`productionReady: true` 时必须存在名称、required、passed 和本版 evidence 都符合的门禁，并为缺失、错误状态、错误路径分别拒绝。

4. **F04｜中｜缺下一步的空态同时属于 P1 和阻断**
   - 位置：Spec D9、UX-R06。
   - 最小修复：拆开阻断条件与 P1 条件。已登记的 P1 可以随版通过。

5. **F05｜中｜「不矛盾」被扩大为「只能有一个状态」**
   - 位置：Spec D4、§6 第七问、UX-R08。
   - 问题：术语标准允许「正式 Role」和「使用中」同时成立。
   - 最小修复：改为同一状态维度不得互相矛盾，并给出允许并存的正例。

6. **F06｜中｜禁止词替换表给出了错误的规范目标**
   - 位置：Spec §5、SC-05。
   - 问题：术语标准里 Data Capability Preview 的 UI 主术语是「数据能力」，不是「数据能力预览」。`constraints` 在主标签与补充说法上没有分开。
   - 最小修复：按「禁止值、适用语境、允许例外」重写。SC-05 同时覆盖禁止主标签和允许补充说法。

7. **F07｜中｜表编辑器必走要求未进入执行分母**
   - 位置：Spec D12、§4、§6、UX-R02。
   - 最小修复：§6 增加表编辑器代表行。覆盖检查包含代表编辑器和本版改过的编辑器。

8. **F08｜中｜S1 的验收依赖 S2 才创建的文件**
   - 位置：Plan §2–§4。
   - 问题：S1 含 SC-07，而 runbook 到 S2 才创建。
   - 最小修复：把清单测试和 SC-07 移到 S2。

第 1 轮同时确认：独立 Playwright 目录可以避开现有全量命令；§6 覆盖全部侧栏主入口；UX-R 编号与 UX-01–UX-07 无冲突。

处置见 Spec §12。第 1 轮之后的正文曾是 Spec v1.1 / Plan v1.1。

## 第 2 轮

第 2 轮对象是 Spec v1.1 / Plan v1.1。结论：退回修订。新发现阻塞 0、高 0、中 1、低 0。F01–F06 与 F08 闭合。F07 部分闭合，因为 §6 允许代表行合并覆盖变更，SC-07 却要求变更编辑器必须另有一行。

**F09｜中｜代表编辑器与变更编辑器的合并覆盖规则相互冲突**

- 位置：Spec §6 与 SC-07，Plan 的清单测试落点。
- 最小修复：SC-07 改为检查变更编辑器是否被覆盖。只有未被代表行覆盖的变更编辑器才追加行。已合并的行须注明。

v1.2 已按该修复改 SC-07 与 Plan。

## 第 3 轮

第 3 轮对象是 Spec v1.2 / Plan v1.2。结论：**可定稿。** F09 已闭合。代表行注明同时覆盖变更时不要求第二行；未被代表行覆盖的变更编辑器才追加行。Plan 的清单测试仍在 S2，并使用同一规则。本轮没有新的控制流或验收矛盾。

定稿版本是 Spec v1.2 / Plan v1.2。开发仍未授权。
