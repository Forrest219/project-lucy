# 登录账户页：Codex 交叉审阅

- 审阅方式：本机 Codex CLI 0.163.0，`codex exec -s read-only`，只读，未改 Spec / Plan 正文。
- 对象：Spec v1.0 与 Plan v1.0（`lucy-20261030-login-accounts`）。
- 结论：**退回修订，不批准交付开发。** 阻塞 4，高 2，中 1，低 0。

## 发现

1. **F01｜阻塞｜界面保护与本地恢复所有者底线不一致**
   - 位置：Spec §6，核心流程 `guard`。
   - 问题：禁用、删除、降权只看启用所有者人数。`localOwners` 算出来后没有参与这三个动作。A 是唯一有本地密码的启用所有者，B 是只绑定单点登录的启用所有者时，Spec 允许把 A 降权，服务端会返回 `LOCAL_OWNER_REQUIRED`。这是同一份名册上的确定性分叉，不是并发过期。
   - 最小修复：三个动作补上最后一名本地密码所有者保护及原因。改掉「还有另一名启用所有者就可以自降权」的无条件允许。补这个双所有者反例。

2. **F02｜阻塞｜凭据关键分支没有被 SC 完整约束**
   - 位置：SC-07、SC-11、SC-15，核心流程 `showRemoveLocalPassword`。
   - 问题：SC-11 的可见正例只要求「已绑定的运维、单点登录启用」，没有要求仍有本地密码。删掉 `hasLocal` 后现有 SC 仍能全过。`loginMethods` 缺失的兼容分支没有用例。创建侧只断言不传 `oidcBinding`，没有断言勾选后发出三项绑定，并成功创建无本地密码账户。
   - 最小修复：覆盖 `["oidc"]` 不显示移除按钮、双凭据显示、字段缺失按本地密码计数、非最后一名本地密码所有者的允许态。补勾选绑定后的 POST body 和无密码成功断言。

3. **F03｜阻塞｜保护 SC 缺少允许分支的正例**
   - 位置：SC-09、SC-10，核心流程 `guard` 的允许分支。
   - 问题：两条 SC 主要检查拒绝态。把禁用或降权全部禁止，仍能满足这些 SC。当前登录保护没有用「还有其他所有者」的夹具单独验证，会被唯一所有者保护遮住。
   - 最小修复：多所有者时，当前人仍不可禁用或删除，其他合法账户可以禁用。两种所有者底线都满足时可以降权。唯一启用所有者不可降权。允许态断言发出请求，拒绝态断言零请求。

4. **F04｜阻塞｜删除比较的归一化分支无法被 SC-12 打假**
   - 位置：Spec §5.5，SC-12。
   - 问题：正文要求去掉首尾空白并区分大小写。SC 只写「一致 / 不一致」。只测完全相同的 id 时，删掉 trim 或改成忽略大小写，SC 仍可能通过。粘贴换行的预期没有写死。
   - 最小修复：SC 列出精确 id、首尾空白、大小写变化、首尾换行、id 中间换行。写明比较前的输入处理。每种情况断言是否发送 `DELETE`。

5. **F05｜高｜没有证明采用 aria-disabled，也没有覆盖键盘拒绝**
   - 位置：Spec §6，SC-09–SC-12。
   - 问题：「不可执行、原因可读、点击不请求」区分不了原生 `disabled` 和 `aria-disabled`。没有要求可聚焦、悬浮或聚焦打开原因、气泡关闭后说明节点仍在。没有 Enter 和 Space 的零请求断言。SC-10 对降权没有明确零请求。
   - 最小修复：保护按钮和删除确认按钮分别断言。角色控件断言说明关联，以及拒绝选择后零 `PATCH`。

6. **F06｜高｜未启用单点登录时，抽屉把已有绑定说成未绑定**
   - 位置：Spec §5.4 身份绑定，SC-06、SC-11。
   - 问题：单点登录未启用不等于没有已保存的绑定。列表仍返回持久化绑定。正文要求这时统一写「未绑定单点登录身份」。SC-06 只查新建对话框，SC-11 只查移除密码按钮。抽屉里误放绑定输入框，现有 SC 仍可能通过。
   - 最小修复：未启用时的说明与已有绑定事实一致。补抽屉在启用 / 未启用、已绑定 / 未绑定下的显示，以及字段隐藏断言。

7. **F07｜中｜Plan 的现有断言迁移清单不完整**
   - 位置：Plan §3.2、S2。
   - 问题：Plan 点了 SEC-03-V05，没有点名这些必然失效的断言：`admin-accounts.test.tsx` 直接查页内表单和行内禁用、删除；`admin-accounts-oidc.test.tsx` 要求整页 OIDC 面板，并用唯一所有者夹具执行移除本地密码；`admin-auth.spec.ts` 的 SEC-04-V11 直接点击行内「禁用」。导航测试、手册里的旧路径、帮助中心恢复说明、走查登记的 Browser Check 也没有列清。
   - 最小修复：按文件写明迁移方式，保留原来的安全语义。只改入口和选择器。

已核对且没有问题的点：所有者列表实际返回 `loginMethods` 和 `oidcBindings` 数组，创建请求使用单数 `oidcBinding`。正常完整列表里，界面的本地密码与服务端 `password_hash` 计数同向。运维写接口仍是 403。开放模式与四列只读名册和现有页面一致。旧路径被登录守卫记下后，回跳仍须替换到 `/admin/accounts`。页头继续叫「登录账户」。闭口出口没有整库旅程、浏览器走查或 Docker。
