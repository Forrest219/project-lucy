## 建议包 F（推荐整包采纳）

| 项 | 建议裁定 | 若不采纳时的替代（须书面另选） |
|---|---|---|
| **O1** 策略声明落点 | 声明写在该 **source overlay 顶层** `freshness` 键。本版**不设** connection 级默认；缺键即未配置（D1）。manifest 中出现 `freshness` 视为声明位置错误 → `policy_invalid`，不打业务库 | A′：connection 级默认策略——易掩盖未逐表声明的缺口，与「未配置即可见」弱化为隐式继承；B′：只在 manifest 登记——与 publish overlay 真源脱节、ACL 修订面扩大 |
| **O2** 水位聚合执行器 | **服务端内部聚合**：固定形状为该声明日期字段的 `max`；复用该 source 的 ACL 与行权限。不新增 MCP 工具，不由模型拼 SQL。超时与用户 `lucy_query` **分开计**（D6／SC-05） | A′：暴露专用 MCP 让模型拉水位——放大注入面与 ACL 漂移；B′：读侧预聚合物化表——本条非目标（§3），引入 CDC／定时扫描承诺 |
| **O3** 水位是否缓存 | **本版不缓存**。每次 `lucy_freshness` 按策略实时读取；进程内／Redis 等缓存留到后续版本（与 D9「按调用读取」一致） | A′：短 TTL 进程内缓存——须书面写 SC 与 stale 披露，否则易用旧水位冒充；B′：与用户 `lucy_query` 共用结果缓存——粒度和失效策略与工具合同冲突 |

整包采纳后的合同后果（授权后才实现）：

1. overlay 顶层 `freshness` 为唯一声明落点；无键或 `unconfigured` → 可见未配置，水位字段 null（SC-01）。
2. `business_date_max` 经服务端 `max(dateField)` 聚合；失败／空最大 → `unavailable`，不编造时间（SC-04／SC-05／SC-07）。
3. 无缓存；每次调用独立读取。成功 `lucy_query` 的 `cutoff.status` **仍** `not_checked`（SC-08；**不**改 P0-4）。
