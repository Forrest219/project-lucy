## 优化方案裁决

### 1. 名册写中可读需要定义提交边界（阻断 SC-04／05）

**认同**先量发布排队、快照核验、写入、运行态确认、审计和响应投影，再迁出能用提交事实生成的展示工作。现有快照先核验再等待写入，共用 1.5 秒恢复预算。缩短屏障可以改善自然窗，首个摘要请求能否在较长的正常备注提交期间成功，仍取决于读端能否安全取得已提交视图。当前摘要和完整名册共用权限槽，槽键绑定整份配置版本；把旧权限拼到正从盘上读取的新 Agent 配置，会把两个代次混进同一响应。[Spec §2.1](../specs/lucy-20261123-interactive-read-resilience-spec.md#21-名册在正式备注保存期间持续可用) · [快照读实现](../../webui/server/display-snapshot.ts#L620) · [权限槽](../../webui/server/admin/agents.ts#L1004) · [名册摘要](../../webui/server/admin/agents.ts#L1344)

**建议优先评估**只在已有可核验的已提交视图、实际差异在发布资格内确认仅备注、授权依赖仍然等价的条件下，让独立会话读到整份一致的已提交视图（含旧备注）。明确提交完成后的第一读必须返回新备注和对应的配置版本。无已验证视图、混合写入、授权变化、外部输入无法核验或未确认回滚，沿用现有保护。真实运行态确认仍核对本次持久化输入的摘要。`after.agent` 与版本从同一次提交捕获，写后读和幂等查询都不得绑定后续提交。保留现有发布协调与屏障锁序、持久审计终态和撤权取消顺序。[写入回执](../../webui/server/admin/agents.ts#L335) · [共享发布协调](../../webui/server/admin/access-config.ts#L347) · [运行态确认与审计](../../webui/server/admin/access-config.ts#L650) · [策略版本计算](../../webui/server/proxy/acl.ts#L2738)

前端另有写入代次。发起写入的浏览器上下文可能先等待再发送请求，也可能丢弃跨写代次的响应。因此把 **C 独立会话的写中活读**和 **A／B 发起保存的上下文在保存后刷新**写成两个断言，各测首个网络响应和页面 `primaryReady`。如果承诺发起写入的会话也能立即读，需要另行论证前端行为。受控用例应在已证实的屏障内暂停纯备注写超过 1.5 秒，观察 C 仍取得一致结果，提交后核对新版。再以相同阶段对授权改动、撤权、混合 PATCH 和核验故障作反例，并记录实际忙因。若只实施屏障缩短，验收承诺应限定于冻结的自然负载档，受控长提交结果单列。[浏览器查询等待](../../webui/src/lib/displayQueryOptions.ts#L33) · [浏览器写入代次](../../webui/src/lib/apiClient.ts#L231) · [响应淘汰](../../webui/src/lib/apiClient.ts#L316) · [现 UAT-07](../qa/uat/suites/interactive-read-resilience/cases.md#uat-read-res-07--多角色问数与同账号并发维护必做同窗运维场景)

### 2. MCP 优先移出无效工作，握手与查数分别给出结果（阻断 SC-02／03）

**认同**先补观测再选择最小优化。第一对照建议测握手是否可以直接复用同一份**按请求授权**的目录事实，由独立 `lucy_catalog` 保留描述增强。当前握手用 Source 四元组、连接和裁剪后的示例拼装指引，调用的目录函数会额外扫描、核验并丰富描述。和同输入的原指引逐项比较来源、顺序、示例和列暴露规则，再判断能否移出描述增强。描述索引热命中仍枚举文件并逐份 `stat`，只测 YAML 解析复用可能遗漏热并发耗时。Skill 优先验证内容解析可复用的收益，发现授权继续以每个请求自己的上下文快照计算。[目录事实与描述增强](../../webui/server/proxy/acl.ts#L2197) · [握手内容构建](../../webui/server/proxy/mcp-proxy.ts#L2122) · [索引指纹](../../webui/server/proxy/source-descriptions.ts#L267) · [Skill 筛选](../../webui/server/proxy/skill-acl.ts#L89)

**有条件认同**初审建议的有界指引。若首轮仅承诺指定 Docker 工况守住既有握手预算，维持完整指引并使候选达标即可。若承诺客户端超时下仍可进入合法问数，应定义从入站到完整 `initialize` 的 deadline、到点行为、剩余资源和首次查询旅程。不能只给动态指引加计时器，正常分支还要等上游响应体，上游异常分支也构建指引，共用事件循环卡顿时计时器本身可能迟到。优先验证有界的 Lucy 基础指引与现有按需发现，原样透传可保留既有注入失败语义，但不能预设宿主会自动刷新 `initialize` 指引。若采用降级，至少验证一个真实宿主从自然问题走目录／Skill 到正确查询、撤权负例、取消后共享工作有界、重连和旧会话不串。逐请求计时还应覆盖独立目录和首次查询，避免把 77–87 秒的待调查长尾留给下一步而仍主张用户可用。[正常路径与本地回退](../../webui/server/proxy/mcp-proxy.ts#L7427) · [注入失败合同](../../webui/docs/07-mcp-auth-proxy-spec.md#44-initialize-instructions-注入v13) · [Lucy 基础指引](../../webui/config/data-qa-instructions.md#基础规则) · [现场阶段证据](../specs/lucy-20261123-interactive-read-resilience-spec.md#1-现场证据与待验证假设)

若引入并发合并，要求写明共用的是哪一层、范围和内容代次怎样验证、等待及容量上限、无等待者时的清理和响应前的授权检查。组合用例至少覆盖目录或 Skill 变更、新旧客户端跨授权生效点、共享任务原发起者断开而另一合法等待者仍成交。以客户端终态与底层实际退出分别记账。测试控制应卡在本地构建阶段，另外保留慢上游响应头和响应体对照。[现有 UAT-03／06](../qa/uat/suites/interactive-read-resilience/cases.md#功能合同选择器) · [当前上游请求取消](../../webui/server/proxy/mcp-proxy.ts#L4456)
