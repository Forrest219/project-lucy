## 3. 阻断项

| 编号 | 位置 | 问题 | 建议修订 |
|---|---|---|---|
| **B1** | Spec §5.4「SOAK 时延」＋D5／D6／D8；fixtures §9.2／§9.3 | **窗口统计与样本下限互相矛盾，且到达模型参数没有冻结。** ①§5.4 要求「每窗口沿用对应题档绝对预算」并比较相邻／首尾窗口的 P95；但 D6 规定 N<20 不输出正式 P95，D5 又要求按场景、客户端、并发组独立采样。50 身份、150 秒窗口，在 μ 约 60 秒思考时间下单窗口只有约百级轮次，再按场景或角色组切分后每格远小于 20，窗口 P95 不可估计，判定器没有规则可用。②全仓只写「记录 μ、σ、截断上下界」，**没有任何文档冻结 μ、σ 与上下界的数值**（grep 无命中）；D17 又禁止本条自造数字，规模基线 §1.1 也没写。「截断正态」因此无法机检、无法跨跑次比较，12 窗口的样本量更无从预估。 | ①给窗口判定定义口径：按 `budgetClass` 合并（simple／complex）并规定窗口最小样本；N 不足时窗口 P95 记 `not_estimable` 并改用中位数＋绝对上限，同时说明首尾窗口比较改用「相邻若干窗口合并」；或把窗口数改为随 N 自适应。②在规模基线 §1.1（owner）冻结 μ、σ、clipMin、clipMax 与随机种子，Spec 只引用；并给出预期到达量估算以证明 §5.4 样本下限可达。 |
| **B2** | Spec D3／D15／§4.2 `turnWallClockMs`、SC-12；Plan 风险表 | **供应商错误归类未定，FAIL／BLOCKED 不是全函数。** D15 写「宿主不可用＝BLOCKED、预算越线＝FAIL」，§4.2 又说「超过 120 秒不因供应商归因豁免」。50 路真实模型会话持续 1800 秒时，429 限流、5xx、连接重置、模型侧超时必然出现：算 FAIL 则门禁被供应商噪声支配，算 BLOCKED 则可被「长期封锁」。判定器无法实现，且与 D12「判定失败关闭」的可复算要求冲突。 | 在 D15 增一张错误分类表：①供应商限流或 5xx 且重试证据完整→BLOCKED，并要求同跑次同指纹重跑至有限次数；②超过上限仍无法完成→BLOCKED 带 `providerUnavailable` 计数，**不得转 PASS**；③模型已返回但答案错误或超 120 秒墙钟→FAIL。同时规定 BLOCKED 的最长持续与升级路径（见 B3），并登记成本与限流预算（Spec「风险」只说成本只记录）。 |
| **B3** | Spec D15／D16／§9「主路径可用性自检」；Plan Task 6 第 3 步 | **门禁对「出包／升级」没有应急逃生。** §9 只论证「不拦在线用户请求」。但出包与升级本身是客户修复事故的主路径：客户回滚、P1-39 同类事故修复都要经出包。D15 把「宿主不可用」「样本不足」「基线缺失」一律判 BLOCKED，Plan 又令 `SEED_ONLY／FAIL／BLOCKED／NOT RUN` 均令 releaseReady=false，且必做项不接受 PASS WITH GAP。外部模型宕机或首次无基线时，事故修复包无法放行。仓库第一性原理（规则第 0 条）要求「约束生效」与「合法用户仍可用」两面同时验收。 | 增补「事故修复放行」合同：仅当委托人具名、限时、写明原因，且已存在总账事故修复授权时，允许 releaseReady 带 `waived` 标记；`waived` 不得写成 PASS、不得进入基线、须在跑次报告置顶、到期自动失效；并在 UAT 加一条「无豁免时 BLOCKED 仍拦截」「有豁免时放行且可审计」的双向用例。这条在 §9 补一句，Plan Task 6 补验证。 |
| **B4** | Spec D20／§5.4「LONG_FOLLOW 比例」；P1-79 Spec §3.2、§4、§5 | **长链数量与「只执行一次」口径不闭合。** SOAK 档 50 身份要求至少 5 条长链（`ceil(0.1×50)`）；P1-79 的覆盖要求只写「至少 3 条链」。D20 又规定「同批链不得二次执行」，并把「同批链被二次执行」设为负控。若 5 条长链来自 3 条题组链，则同一链被不同身份执行，到底算「同链复用」还是「二次执行」未定义；P1-79 §5 又写「题组需增链并升版」，说明依赖方知道缺口却没写进最低要求。另外 P1-79 每链 `identity` 固定，而 SOAK 把身份分到 `lucy_admin` 和两个受限角色，按角色的逐轮 oracle 是否独立编写也未说明。 | ①统一术语：**链实例＝链 ID×身份×runId**；D20 的「只执行一次」只约束同一链实例，不同身份执行同一链模板合法，并写进负控定义。②P1-79 最低链数改为不少于 5 条，或明确「模板数 3＋实例数由身份扩展」并规定各角色 oracle 的来源；先改 owner，再改 P1-78 引用。③SC-15 增检查：链实例数≥`ceil(0.1×N)`，且每实例的 `identityId` 与 oracle 对应。 |
