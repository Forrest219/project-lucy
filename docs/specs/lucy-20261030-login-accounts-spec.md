- 层级：功能合同
- 本条承诺：登录账户页以名册为主画布；所有者用对话框新建、用抽屉维护一个账户；四条保护在界面上不可执行并说明原因；旧路径打开后地址栏变为 `/admin/accounts`

- 上线关系：本条收口不表示可上线

## Terminology Compliance

This feature follows `webui/docs/00-product-terminology-standard.md`.

New terms:

- Current Login Mark: UI 主术语「当前登录」。标在与当前会话登录账户 id 相同的那一行。
- Create Login Account: UI 主术语「新建账户」。页头主操作和对话框标题。提交按钮仍是「创建账户」。
- Manage Login Account: UI 主术语「管理」。所有者打开该账户抽屉的行内动作。
- Delete Login Account Confirm: 对话框标题「删除登录账户」。确认前必须输入该登录账户 id。确认按钮是「删除账户」。

Forbidden terms:

- 页头、侧栏或对话框标题使用「用户管理」「账户管理」「新建用户」「添加用户」。
- 当前登录标记写成「我」「本人」「当前用户」。
- 删除确认写成「输入用户名」。
- 未绑定单点登录时，确认文案写成「将只能使用单点登录」。

术语标准 §4.11.1 已登记上表。实现不得另起译名。`OIDC`、`issuer`、`sub`、登录账户 id、`/admin/accounts` 在用户可见 DOM 上使用 `translate="no"` 与 `notranslate`。

## 1. 背景

`/admin/admins` 把名册、常驻新建表单和整页 OIDC 身份绑定叠在同一屏。新建表单约 672px，名册约 116px。同一登录账户在表格和页面底部各出现一次。禁用、删除和移除本地密码都画成可点的普通按钮。单点登录未启用时，新建表单仍展开身份源、主体和联系邮箱。

服务端已经拒绝拆掉最后一名启用中的所有者、拆掉最后一名仍有本地密码的启用中所有者，以及在没有绑定的情况下移除本地密码。这些拒绝没有画在按钮上。禁用和删除失败后，列表不显示错误。

## 2. 目标

1. 浏览器路径改为 `/admin/accounts`。打开 `/admin/admins` 后，地址栏变为 `/admin/accounts`。
2. 主画布只有名册。所有者从页头「新建账户」打开对话框，从行内「管理」打开该账户的抽屉。
3. 四条保护在界面上不可执行，并说明原因。删除须输入该登录账户 id。
4. 单点登录未启用时，新建对话框不出现绑定字段。抽屉不提供绑定写入；已有绑定只读展示。
5. `/api/admin/admins` 的路径、字段和错误码保持不变。

## 3. 非目标

| 不做 | 原因 |
|---|---|
| 改 `GET` / `POST` / `PATCH` / `PUT` / `DELETE /api/admin/admins` 的路径或语义 | 呈现升级，接口继续复用 |
| 新增身份源配置页，或把未启用说明做成链接 | 产品里没有这个页面 |
| 在抽屉里修改显示名 | 显示名仍只在新建时填写，抽屉里只读 |
| 把「移除本地密码」画成禁用按钮 | 条件不成立时不渲染该按钮 |
| 用原生 `window.confirm` 删除账户 | 删除必须输入登录账户 id |
| 改运维对账户接口的 403 | 运维继续不能治理登录账户 |
| 改密码策略 | 继续至少 10 个字符，失败显示接口文案 |
| 重写 L25-06 的历史记录和接口说明 | 那些文档写的是 API，不是本页路径 |
| 为窄屏新做断点 | 本仓库默认不做移动窄屏 |

## 5. 页面

### 5.1 路径与页头

| 入口 | 结果 |
|---|---|
| 侧栏「登录账户」 | `/admin/accounts` |
| 直接打开 `/admin/accounts` | 本页 |
| 直接打开 `/admin/admins` | 地址栏替换为 `/admin/accounts`，渲染同一页 |

页头标题「登录账户」。说明保持：「管理 WebUI 登录账户，并配置所有者或运维角色。」`WebUI` 继续 `translate="no"`。

所有者且登录已启用时，页头右侧是「新建账户」。运维和开放模式没有这个按钮。

单点登录未启用、且当前人是所有者、且登录已启用时，页头下显示一句：

> 当前未启用单点登录；新增或替换绑定需要先启用身份源配置。

这句用次级文字，不做成链接，不在表格每一行下重复。

开放模式继续显示现有说明，包括 `LUCY_WEBUI_AUTH=required` 和登录页链接。

### 5.2 名册

容器是 `pl-data-grid-frame`。页面上不再出现「添加登录账户」和「OIDC 身份绑定」标题。

| 读者 | 列 |
|---|---|
| 所有者，登录已启用 | 登录账户、显示名、角色、状态、登录方式、操作 |
| 运维，或开放模式 | 登录账户、显示名、角色、状态 |

登录方式沿用现有文案：本地账户登录、单点登录，两者都有时用「 · 」连接。没有可用方式时写「无可用登录方式」。

状态列继续写「启用」或「已禁用」。

与 `me.id` 相同的登录账户 id 旁标「当前登录」。id 本身保持 `translate="no"`。

所有者的操作列只有「管理」。

### 5.3 新建账户

对话框字段顺序：

| 顺序 | 字段 | 单点登录未启用 | 单点登录已启用且未勾选 | 已勾选「同时绑定单点登录」 |
|---|---|---|---|---|
| 1 | 登录账户 | 必填 | 必填 | 必填 |
| 2 | 显示名 | 可选 | 可选 | 可选 |
| 3 | 角色 | 运维 / 所有者，默认运维 | 同左 | 同左 |
| 4 | 初始密码 | 必填，至少 10 个字符 | 必填，至少 10 个字符 | 可以留空 |
| 5–7 | 身份源、主体、联系邮箱 | 不出现 | 不出现 | 三项一起必填 |

角色下的说明保持现有句子：运维负责连接、语义、Wiki、发布、Eval、Agent / Role / Token；所有者另含登录账户治理。`Agent`、`Role`、`Token` 继续 `translate="no"`。

勾选后，密码下说明：「已填写单点登录身份绑定，本地密码可以留空（仅单点登录登录方式）。」未勾选时不显示这句。身份源、主体、联系邮箱的匹配说明只出现在这个展开区：三个字段需要一起填写；邮箱只作联系信息，不参与登录匹配。

提交调用现有 `POST /api/admin/admins`。未勾选或单点登录未启用时不传 `oidcBinding`。失败显示在对话框内。成功后关闭对话框并刷新名册。

### 5.4 账户抽屉

「管理」打开右侧抽屉，一次一个账户。标题用该登录账户 id。显示名只读。

分组顺序：

1. **角色。** 可改为运维或所有者。选中可选项后立即 `PATCH`。失败时恢复为打开抽屉时的角色，并显示接口文案。
2. **状态。** 已启用时按钮为「禁用」，已禁用时按钮为「启用」。可执行时立即 `PATCH`。
3. **本地密码。** 「新密码」和「保存密码」。成功后清空输入并显示「本地密码已更新。」失败显示接口文案。条件见 §6 时才出现「移除本地密码」。
4. **身份绑定。** 已有绑定就只读显示身份源、主体、联系邮箱，不写「未绑定单点登录身份。」没有绑定才写这一句。单点登录未启用时，再写 §5.1 的同一句说明，并且不出现输入框、「新增／替换绑定」和「删除绑定」。单点登录已启用时可以新增／替换；已有绑定时还可以删除绑定。删除绑定继续先确认，确认句保持现有「会先撤销该账户的既有会话」。
5. **删除。** 底部「删除账户」。可执行时打开 §5.5，不直接调用删除接口。

### 5.5 删除确认

对话框标题「删除登录账户」。说明：「输入该登录账户以确认删除。此操作不可撤销。」

输入的标签是「登录账户」。控件 `autocomplete="off"`，`translate="no"`。比较使用去掉首尾空白后的字符串。首尾空白只包括空格、制表、回车和换行。不改大小写，不删除中间的任何字符。中间换行与 id 不一致。

「删除账户」在不一致时 `aria-disabled="true"`，且没有原生 `disabled`。点击、Enter 和 Space 不发出请求。一致后使用 `pl-btn pl-btn--danger`，调用现有 `DELETE /api/admin/admins/:adminId`。失败时说明留在这个对话框里。成功后关闭确认和抽屉，并刷新名册。取消只关闭确认，抽屉仍在。不可执行的抽屉底部「删除账户」不打开这个确认框。

## 6. 保护

计数只用当前名册：

```text
enabledOwnerCount = 启用且角色为所有者的行数
localOwnerCount = 启用、角色为所有者、且视为仍有本地密码的行数
视为仍有本地密码 = loginMethods 缺失，或 loginMethods 含 "local"
```

`me.id` 来自当前登录状态。

| 动作 | 不可执行的条件 | 原因 |
|---|---|---|
| 禁用 | 该行 id 等于 `me.id` | 无法禁用当前登录账户 |
| 删除 | 该行 id 等于 `me.id` | 无法删除当前登录账户 |
| 禁用、删除，或把角色改为运维 | 该行是启用中的所有者，且 `enabledOwnerCount` 为 1 | 至少保留一名启用中的所有者 |
| 禁用、删除，或把角色改为运维 | 该行是启用中的所有者，且该行视为仍有本地密码，且 `localOwnerCount` 为 1 | 至少保留一名可使用本地密码登录的启用中所有者 |
| 移除本地密码 | 单点登录未启用，或没有身份绑定，或该行不视为仍有本地密码，或该行是启用中的所有者且 `localOwnerCount` 为 1 | 不渲染按钮 |

多条原因同时成立时都显示，顺序固定：当前登录，然后启用所有者底线，然后本地密码底线。中间用句号连接。例如唯一一名启用中、且仍有本地密码的当前登录账户：「无法删除当前登录账户。至少保留一名启用中的所有者。至少保留一名可使用本地密码登录的启用中所有者。」

不可执行的按钮保持在界面上，使用 `aria-disabled="true"`，没有原生 `disabled`，因此仍可聚焦。外观与 `.pl-btn:disabled` 相同：半透明、不可用光标。悬浮和键盘聚焦都打开原因气泡，气泡文本与原因相同。`aria-describedby` 指向一个在气泡关闭时也存在于 DOM 中的说明节点，节点文本含全部原因。点击、Enter 和 Space 不调用接口，也不打开删除确认。

「运维」不可选时，该选项为原生 `disabled`。角色控件的 `aria-describedby` 指向控件旁可见的原因，原因覆盖该行命中的每一条底线。把值改成运维不发出 `PATCH`。

「启用」和把运维改为所有者不受上表限制。当前登录的所有者只有在改完后两条底线都仍成立时，才可以把自己改为运维。只剩另一名没有本地密码的启用所有者时，不能把自己改为运维。没有本地密码的启用所有者，在改完后仍有一名启用所有者时，可以改为运维。

界面判断只用于能不能点。并发修改后若接口仍拒绝，按 D15 显示接口文案。接口文案保持：

| code | 文案 |
|---|---|
| `LAST_OWNER_REQUIRED` | 至少保留一名启用中的所有者 |
| `LOCAL_OWNER_REQUIRED` | 至少保留一名可使用本地密码登录的启用中所有者 |
| `AUTH_CREDENTIAL_REQUIRED` | 登录账户至少需要一种可用登录方式 |

移除本地密码的确认句改为：「确定移除登录账户 {id} 的本地密码？该账户之后使用单点登录登录。」这句只出现在按钮已经渲染的时候。

## 核心流程（伪代码）

```text
open(path):
  if path == "/admin/admins": replace location with "/admin/accounts"
  render 登录账户

canvas(me, mode, methods, rows):
  if mode != "required":
    show 开放模式说明
    show 四列表
    return
  if me.role == "owner":
    show 新建账户
    if "oidc" not in methods:
      show 一次「当前未启用单点登录；新增或替换绑定需要先启用身份源配置。」
    show 六列表
    在 id == me.id 的行标「当前登录」
    每行操作 = 管理
  else:
    show 四列表

createDialog(oidcEnabled, bindChecked):
  fields = [登录账户, 显示名, 角色, 初始密码]
  if oidcEnabled and bindChecked:
    fields += [身份源, 主体, 联系邮箱]
    初始密码可选
    三项都非空才可提交
    body.oidcBinding = { issuer, sub, email }
    密码为空时 body 不含 password
  else:
    初始密码必填
    body 不含 oidcBinding
  提交 POST /api/admin/admins

guard(row, action, me, rows):
  reasons = []
  owners = rows 中启用且角色为所有者
  localOwners = owners 中视为仍有本地密码者
  if action in {禁用, 删除} and row.id == me.id:
    reasons += 对应的「无法禁用／无法删除当前登录账户」
  if action in {禁用, 删除, 改为运维}
     and row.角色 == 所有者 and row.启用 and count(owners) == 1:
    reasons += 「至少保留一名启用中的所有者」
  if action in {禁用, 删除, 改为运维}
     and row.角色 == 所有者 and row.启用
     and row 视为仍有本地密码 and count(localOwners) == 1:
    reasons += 「至少保留一名可使用本地密码登录的启用中所有者」
  if reasons 非空:
    aria-disabled = true
    不用原生 disabled
    按当前登录、启用所有者、本地密码的顺序显示 reasons
    点击、Enter、Space 不发请求，删除确认不打开
  else:
    动作可执行

showRemoveLocalPassword(row, oidcEnabled, rows):
  hasLocal = row.loginMethods 字段缺失，或数组含 "local"
  空数组表示没有本地密码
  localOwners = 启用的所有者中视为仍有本地密码者
  return oidcEnabled
     and row 已有身份绑定
     and hasLocal
     and not (row 是启用的所有者 and count(localOwners) == 1)

bindingSection(oidcEnabled, binding):
  if binding: 只读显示 issuer、sub、email
  else: 显示「未绑定单点登录身份。」
  if not oidcEnabled:
    显示未启用说明
    隐藏输入框、新增／替换绑定、删除绑定
  else:
    显示新增／替换绑定
    if binding: 显示删除绑定

deleteConfirm(row, typed):
  打开「删除登录账户」
  key = 去掉 typed 首尾的空格、制表、回车、换行
  if key != row.id:
    「删除账户」aria-disabled，点击、Enter、Space 不发 DELETE
  else:
    DELETE /api/admin/admins/{row.id}
  失败则把接口文案留在确认框
```

SC-01 对应 `open`，并包含登录后再次进入旧路径。SC-03–SC-08 对应 `canvas` 与 `createDialog`。SC-09、SC-10、SC-17 对应 `guard` 的拒绝与允许分支。SC-11 对应 `showRemoveLocalPassword` 的每一行。SC-12 对应 `deleteConfirm` 的五种输入。SC-15 对应 `createDialog` 的两种请求体。SC-18 对应 `bindingSection` 的四格。
