## 闭口层级

- 层级：功能合同
- 本条承诺：冻结 X5 降级提示的位置、触发、手动刷新入口、不改导航和术语引用；X3 承载位置（头／信封）不在本合同。
- 本条出口：提示位置、触发映射、刷新行为经 X5 实现并由 09／10 前台逐格验证；文案断言取自术语标准 §4.6.1。
- 不在本条出口：X3 响应头／信封字段、降级状态机、P1-81 对齐、导航变更、写入与权限判定语义。
- 上线关系：本条收口不表示可上线；本合同冻结 ≠ 功能合同收口；≠ UAT PASS。

## 核心流程（伪代码）

伪代码豁免：本合同只冻结用户可见提示的位置与触发映射（见 §3 表），不含新算法；状态机伪代码见 [Spec 核心流程](lucy-20261123-interactive-read-resilience-spec.md#核心流程伪代码)。

## 1. 范围与不变项

**范围。** WebUI 页面读取到 `grace`／`stale`／`pending`，或非错误型降级越过 D_max（180 秒）时的用户可见提示。语义字段集合沿用 Spec OQ-3：状态、数据年龄（毫秒）、视图代次。

**不变项（冻结）。**

1. **不改导航**：不增删改一级分组、二级菜单项、二级页内分页 Tab，不改路由与默认 Tab。本合同新增的 banner、分区提示和刷新入口都不是导航项或 Tab，不触发[导航 IA 独立确认](../../webui/docs/06-navigation-ia.md)。
2. 不改既有页面布局的信息架构：提示是叠加在现有页头或分区上的一行状态，不替换页面内容，不新增页面。
3. 写入、权限预览、dryRun、保存按钮等所有走 fresh 核验的动作，行为与文案不因本合同改变。
4. 不改 B、C 类 503 的既有错误态与恢复入口；本合同只管 200 降级。核验错误型持续失败越过 D_max 后的 C 类 503（拟 `DISPLAY_RECONCILIATION_FAILED`）使用既有错误状态与恢复入口，其文案不在本合同。

## 2. 提示位置

| 层级 | 位置 | 使用条件 |
|---|---|---|
| 页头 banner | 页面标题区（`PageHeader`）下方、页面主体内容上方的整宽单行提示，页内唯一一条 | 页面首读主数据整体处于 `grace`／`stale`／`pending`，或任一必读分区降级且页面无法自行分区表达时 |
| 分区提示 | 对应卡片、表格或面板的标题行内侧，紧邻该分区内容 | 页面由多个独立分区各自读取（如概览、使用概况的分栏、启用表范围按连接的卡片）时，只在受影响分区显示，未受影响分区不显示 |

规则：

1. 同一页面同一时刻，同一分区不重复显示；页头 banner 与分区提示同时存在时，分区提示只显示在 banner 未覆盖的分区。
2. 提示不得遮挡主操作区，不使用 Toast／Modal／Drawer 承载（降级是持续状态，不是一次性事件）。
3. 详情页与二级 tab：提示跟随当前 tab 的受影响分区；tab 切换后受影响分区变化时，提示随之变化。tab 标题本身不加角标，不改 tab 个数。
4. 视觉层级低于错误提示，使用现有 `pl-notice` 的中性／提醒样式，不使用红色错误样式；不显示图标之外的原始状态词。具体样式 token 由 X5 实现按现有组件选择，不新增组件体系。

## 3. 触发与展示

内部状态到用户可见提示的映射（内部状态词只在 Spec／UAT／日志中出现，**不进入 UI**，见术语标准 §4.6.1）：

| 内部状态 | 触发 | 用户可见提示（术语主句） | 数据区域表现 | 手动刷新 | 自动行为 |
|---|---|---|---|---|---|
| `fresh` | 请求内完成核验 | 无提示 | 正常内容 | 保持页面既有刷新入口 | 无 |
| `grace` | 同代次已提交视图，年龄在宽限内（元数据 120 秒、全量摘要 180 秒） | 数据可能不是最新（可附「约 N 分钟前更新」） | 正常显示已核验视图的内容 | 显示 | 不额外轮询，沿用页面既有刷新节奏 |
| `stale` | 同代次已提交视图，年龄越过宽限，且请求内恢复等待后仍无法核验 | 数据可能不是最新（附「约 N 分钟前更新」，必附） | 正常显示已核验视图的内容 | 显示 | 自动轮询，直到回到 `fresh` 清除提示 |
| `pending` | 无可服务视图（写后代次切换首读、冷启动、`build_capacity` 等；Spec §2.5.1） | 正在加载… | 该区域**不显示任何数据**：不得用空列表、零值、「暂无数据」或空指标卡冒充；保留区域骨架或占位 | 显示 | 自动轮询，回到 `fresh` 后替换为正式内容 |
| 非错误型降级越过 D_max（`stale`／`pending` 连续超过 180 秒，无核验错误） | 对应分区或页面连续降级时长超过 D_max | 长时间未更新（替换「数据可能不是最新」／「正在加载…」主句，仍保留年龄与刷新入口） | 同该分区当时的 `stale` 或 `pending` 表现 | 显示，位置提升为提示行内首个操作 | 继续轮询；**不转为错误态**，不隐藏内容 |

补充约束：

1. 提示主句只取术语标准 §4.6.1 的四个主术语：「数据可能不是最新」「正在加载…」「长时间未更新」「刷新」。次级文案只允许「约 N 分钟前更新」这一种数据年龄写法（N 向下取整到分钟；数据年龄不足 1 分钟时省略该次级文案，仅显示主句）。
2. 页面不显示 `degraded`、`grace`、`stale`、`pending`、`busyReason`、`X-Lucy-Busy-Reason`、原因码、毫秒值、视图代次。这些只进入日志、证据与测试内部断言。
3. `pending` 与启用表范围：该页在 `stale`／`pending` 下沿用 P1-80 的三态诚实——不据旧数据或无数据判定缺 Manifest／无效启用，「移出无效启用」等危险动作不可达（Spec §2.5.1 边界 3）；该页 `pending` 区域继续使用专用文案「正在读取表清单…」，其余分区使用「正在加载…」。
4. 页面加载自动探测（`purpose=automatic`）降级时，在对应连接卡或探测结果位置，显示最近一次结果并带「约 N 分钟前更新」，无结果时显示「正在加载…」；用户主动探测的 503 保留既有反馈。
5. 降级态下的写入类动作（保存、预览、dryRun、撤权相关）不使用降级视图，按钮保持可用且在点击时走 fresh 核验；核验失败按既有写入错误合同反馈。降级提示**不得**与「已保存」「已生效」「已同步」等结论文案同屏并用。
6. 无压冷读（08-A）下提示出现次数须为 0（Spec §2.5.1 边界 4）；提示出现是降级事实的可见记录，UAT 以逐格出现次数与数据年龄核对。

## 4. 手动刷新入口

1. 位置：提示行（banner 或分区提示）内，文案固定为「刷新」；与页头既有「刷新」按钮同名同义，不新增第二个并列主刷新入口名词。
2. 行为：仅重新读取**该提示所覆盖的分区**的展示数据；不触发写入，不改变权限或配置，不清空页面其他分区的草稿与筛选状态。
3. 进行中：按钮进入禁用并显示进行中状态，避免重复点击；读取完成前不清除提示。
4. 成功：回到 `fresh` 后提示消失，内容替换为新数据；若返回仍为降级，提示保持，年龄按新视图更新。
5. 失败（超时、仍降级或受控错误）：保持提示与当前内容，不清空、不弹出原始错误；仍可再次点击。受控错误（B、C 类）使用各自既有错误状态。
6. 键盘与读屏：提示行使用 `role="status"`（`aria-live="polite"`），刷新按钮可聚焦；状态变化（出现、升级为「长时间未更新」、消失）各朗读一次，不循环朗读。
7. 浏览器翻译防御：提示主句为纯中文，无需 `notranslate`；若次级文案包含数字之外的专业英文术语、路径或代码，按术语标准 §2.6 添加防御。

| 检查 | 对应 |

| `pending` 不显示数据字段，不以空列表、零值冒充 | 10-C |

## Terminology Compliance

This feature follows `webui/docs/00-product-terminology-standard.md`.

New terms:
- 数据可能不是最新 / 正在加载… / 长时间未更新 / 刷新（均已于 2026-11-24 登记在术语标准 §4.6.1，本合同仅引用，不另立新词）。

Forbidden terms in user-visible copy:
- `degraded`、`grace`、`stale`、`pending`、`busyReason`、原因码、毫秒值、视图代次、服务故障（对非错误型降级）。

No other new product terms introduced.
