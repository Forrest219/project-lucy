## 闭口层级

- 层级：功能合同
- 性质：事故修复／主路径可用性。
- 本条承诺：在 Docker 单实例、与 MCP／展示读同进程的现行拓扑下，混压时**公共入口面**在预算内可用；合法 MCP 与已登录管理只读**每一臂**须二选一：同窗成功成交，或在有界时限内返回可重试拒绝且停压后同 PID 重试成交；任一臂出现超时、0-byte、无限挂起或非有界错误即整体 FAIL；不得用「全面拒绝数据面」换入口绿。
- 本条出口：SC-01–SC-08，以及 `UAT-PES-R0／01–08`（含 04b 安全负例、06b 触发条件、对照臂）必做跑次。**SC-09（反向洪水）随 OQ-6，默认不挡本期出口。**
- 不在本条出口：WebUI↔MCP 进程拆分（除非终稿裁定选项 C 并另开／扩写 P1-82 B1）、审计写者拆分、KTX worker 池、多副本、K8s／客户拓扑、管理页展示读 503／降级合同全文（P1-75）、假活自愈（P1-81）、MCP 四层容量数值（P1-82）、扩大 `isPublicApi`。
- 上线关系：本条收口不表示可上线；本条不证明进程级 HA。

## 1. 问题陈述

### 1.1 合同输入（待复证假设）

下列数字来自混压／压力**语境叙述**（含聊天摘录），**不是**已挂测试台的可复核跑次结论。正式 `f5e4b14d` 压力跑次探测账本以 `/api/livez`、`/api/readyz`、`/api/project` 为主，**未登记** `GET /`、`GET /api/branding`。

| 探测 | 语境主张（待复证） |
|---|---|
| `GET /` | 10 秒内 0 bytes |
| `GET /api/branding` | 10 秒内 0 bytes |
| `GET /api/sources`（已鉴权，**非本条对象**） | 15 秒内 0 bytes；归 P1-75 |
| `GET /api/livez` | 200；服务端处理可极短，但不得与客户端耗时混作同一可用性证据 |
| 事件循环 | p99／max 可达数秒量级 |

**诊断 Gate（已完成 2026-11-24；证据 [`inbox/p184-diag-20261124`](../../inbox/p184-diag-20261124/REPORT.md)；仍为终稿与开发授权前置清单中的「已勾」项）：**

3. 空闲与异步突发下入口**当前不失败** → **不取消本条**：事件循环臂预算仍要求选项 A；不得在未让出时终稿「饥饿下仍满足 §3.2」。
4. 历史「探针绿且入口 0-byte」混压分裂：**仍待**正式混压账本复证（本 Gate sync 臂为同滞，不是分裂形态）。

工作假设（Gate 后）：同进程**同步**工作可饿死公共入口（**已升格**）；「livez 绿／入口死」分裂仍待复证；P1-82 本期排除分进程（OQ-2＝A）。

### 1.2 公共入口面与三类合同

清单 ⊆ `isPublicApi`，不得扩大白名单。路径分三类，**不得共用一套「只读小状态」伪代码**：

| 类 | 路径 | 合同要点 |
|---|---|---|
| **A 静态只读** | `GET /`、首屏必需 JS／CSS、`GET /api/branding`、`GET /api/branding/logo` | 可缓存已提交小状态；须代次／写屏障（§3.4）；禁止 await MCP／全量展示构建／重审计扫描 |
| **B Session 感知读** | `GET /api/auth/status` | **禁止**跨身份共享响应缓存；须保留撤权、DRAINING、`no-store`、现有 Session 解析语义；可快路径但不能短路鉴权结论 |
| **C 认证写入** | `POST /api/auth/login`（bootstrap／OIDC 公开入口仅当夹具启用） | **不是**只读模型；保留限流、scrypt、CSRF、Session 持久化、审计屏障、Cookie；健康认证存储＋合法凭据须**成功签发** |

不在本条承诺：`/api/sources`、`/api/admin/*`、MCP 工具、`/api/help*`（OQ-5）、`/api/health` 业务体。

## 2. 目标与非目标

**目标**

1. 混压下 A／B／C 类入口按类满足预算与语义。
2. 入口失败与 `livez` 分列可观测。
3. 主路径：合法纯 MCP 与已登录管理只读**两臂各自**须同窗成功成交，或有界拒绝＋停压后同 PID 重试成功；至少一臂成功成交；任一臂超时／0-byte／挂起即 FAIL。
4. 改前对照臂与改后最终臂同一分母；浏览器 `primaryReady` 与 API 分列。

**非目标**

- 默认不在本条完成分进程（选项 C 须另裁并衔接 P1-82 B1）。
- 不重开 Spec 174／P1-21 收口句；不替代 P1-75 全页面 503 合同。
- 反向公开洪水公平性默认登记 OQ-6，不挡本期出口（除非委托人纳入）。

## 3. 行为合同

### 3.1 架构决策（OQ-2；已裁定＝A）

同进程下「只改公开 handler、禁止 await」**不能单独证明**同步 CPU／事件循环饥饿下的秒级预算。决策记录如下：

| 选项 | 含义 | 本条可承诺 |
|---|---|---|
| **A 同进程让出** | 重工作切片／让出／移出主线程（或等价），使事件循环在登记上限内可调度公开请求；公开路径仍禁止 await MCP／全量展示构建 | 可承诺事件循环臂下的入口预算 |
| **B 收窄承诺** | 不做同步让出；只优化异步排队／禁 await／小缓存 | **删除**「事件循环饥饿下仍满足 §3.2 预算」；仅验异步排队臂 |
| **C 独立执行域** | 公共入口由独立执行域承接 | 须与 P1-82 B1 对齐并**另行授权**；本条不得独自宣称分进程已交付 |

**已裁定（2026-11-24，委托人批准诊断 Gate＋OQ-2）：选项 A。** 选项 B／C 本条不采用。

响应预算一律以**客户端发送 → 首字节／完整响应**计量，不得只测 handler 内耗时。

#### 3.1.1 选项 A 的冻结边界（热点范围／同步片段上限／公平性）

本节只冻结**范围与指标**；切片或 off-thread 的具体算法留实现阶段，以下列指标验收。

**热点范围（本期冻结，事实源＝既有登记，不另造清单）：**

| 编号 | 热点 | 事实源／现状 | 本条处理 |
|---|---|---|---|
| H1 | 展示快照全量构建与协调 | `webui/server/display-snapshot.ts`；P1-75 并行修改 | 基线实测同步段 > 片段上限者，纳入切片；**与 P1-75 合流顺序：P1-75 先落地，本条在其结果上复测**，不重复改同一函数 |
| H2 | 审计导出与行展示 | `webui/server/admin/audit*.ts`，已用 `yield-slices.ts` 分片（P1-32／33） | **只回归**，不改写；EQUIV-GUARD／SWEEP 门禁不得退化 |
| H3 | 推断问询补算 | `webui/server/admin/inferred-turn-maintainer.ts`（P1-38／47 已让出） | **只回归** |
| H4 | MCP 代理侧同步处理 | `webui/server/proxy/`（P1-82 范围） | 基线实测超上限者**登记差集**并指向 P1-82，不在本条改 |

**不可切片且基线同步段 > 上限的热点**：不在本条出口；登记差集，转 P1-82 B1／选项 C 另案，不得借本条宣称已解。

**同步片段上限（冻结）：** 单个同步片段 **≤ 250 ms**（沿用既有 `yield-slices.ts` 口径）。最终臂混压期间事件循环延迟 **p99 ≤ 400 ms、max ≤ 800 ms**（p99 对齐 `UAT-SWEEP` 既有口径；max 取 800 而非 1000，以便为 `GET /api/branding` ≤ 1 s 预算留余量）。以事件循环延迟快照与客户端账本共同判定，不得只信其一。

**故障注入器的使用边界：** Gate 使用的 `ops-step-uat/sync-section`（`Atomics.wait`）是**有意把线程整段阻塞**的测试挡板，任何产品切片都救不了它。因此它**只用于基线臂机制鉴别**（R0／01 证明基线越线）。**最终臂的事件循环压力必须来自生产重工作臂**（H1 的冷槽／并发展示构建，及 scale 档审计读／导出）；若基线上没有任何生产重工作臂能复现越线，则最终臂的「生产重工作臂」判 `BLOCKED`＋差集登记，不得以注入器通过冒充产品修复，套件至多 PASS WITH GAP。

**公平性原则（冻结）：** 让出对所有排队任务一视同仁（FIFO 宏任务），**不引入公开入口抢占式优先队列**；重工作在持续公开探测（≥ 1 Hz）下必须仍能完成，完成耗时 ≤ 基线空闲耗时的 **3 倍**，不得被无限推迟。反向洪水完整验收仍归 OQ-6。

### 3.2 响应预算（OQ-1 冻结）

| 探测 | 默认预算 | 通过条件 |
|---|---|---|
| `GET /` | TTFB ≤ 2s；文档完整 ≤ 5s | `primaryReady`（§3.5） |
| 首屏静态资产（单资源） | ≤ 3s | 200；非空 |
| `GET /api/branding` | ≤ 1s | 非空可解析 JSON |
| `GET /api/branding/logo` | ≤ 2s | 完成或既有无自定义短路 |
| `GET /api/auth/status` | ≤ 1s | 语义正确；身份不串 |
| `POST /api/auth/login`（合法凭据＋健康存储） | ≤ 3s | **成功签发 Session**，并完成一次受保护只读 |

**判定口径（冻结）：** 预算逐样本核对；每条路径须同时满足：无超时、无 0-byte、状态符合期望；**P99 ≤ 预算**；**max ≤ 2 × 预算**。不得用平均值或单一分位掩盖超时与 max。「有界拒绝」＝客户端 **≤ 10 s** 内收到带可读 code 的结构化 4xx／5xx。

### 3.3 混压臂

| 臂 | 必做？ | 说明 |
|---|---|---|
| 事件循环臂 | **必做** | 基线臂可用注入器作机制鉴别；**最终臂须为生产重工作臂**（§3.1.1）；可观测 delay 升高；禁止假延迟中间件 |
| MCP 臂 | **必做**（与事件循环同窗叠加） | 真实 MCP 在途：压力持续期内**任一时刻至少有 MCP 查询在途**，量级复用 P1-82 `UAT-MCPHA-03`；不得只发单条合法查询 |
| 展示构建臂 | 推荐 | 冷槽／并发构建；H1 生产重工作臂可与之合并 |

### 3.4 品牌缓存一致性（类 A）

若缓存 branding／logo：必须绑定已提交代次；写前／写中屏障；删除与外部文件修改失效；**写后首读**不得返回旧文案／旧 Logo。**外部修改失效时限＝修改后的下一次读（首读）即生效**（每次读以 mtime／size 校验，不得仅靠定时过期）；若实现做不到，则禁止对该资源启用缓存。外部修改用例**必做**。对齐 Spec 126「立即生效」。UAT-PES-08。

禁止对 `/api/auth/*` 做跨请求共享身份响应缓存。

### 3.5 `primaryReady`

浏览器判定首页可用＝登录表单（或已登录壳主框架）**可见且可操作**，且 OQ-3 登记的首屏必需 JS／CSS（及 Logo 若适用）均成功完成。仅 HTML 可解析不等于通过。

### 3.6 失败形态

- 类 A／B：禁止 0-byte 挂死；允许预算内快速 4xx／5xx（配置损坏等既有语义）。
- 类 C：合法凭据正向用例禁止用 503／429／开放模式 400 冒充通过。
- **快路径安全负例（必做，`UAT-PES-04b`）：** 错误密码 401 且不签发 Session／Cookie；跨站请求按既有 CSRF 语义拒绝；超限 429；吊销或过期 Session 下 `auth/status` 的 `me` 为空；`auth/status` 响应带 `Cache-Control: no-store`；Session 存储／审计写入失败时不发 Cookie；非目标受保护 API（如 `/api/sources`、`/api/admin/*`）在新分类器与钩子顺序下仍不被公开。
- **DRAINING：** 同一 DRAINING 请求序列下，A／B／C 各路径的状态码在基线臂与最终臂**一致**（差分验证）；既有 `process-drain.test.ts` 须仍绿。
- **既有认证回归（必须仍绿）：** `webui-admin-auth.test.ts`、`webui-auth-rate-limit.test.ts`、`webui-session-revocation.test.ts`、`auth-failure-timeline.test.ts`、`branding.test.ts`（`webui/server/__tests__/`）。OIDC／bootstrap 分支仅在夹具启用时加测。
- 排空／自愈窗口有界拒绝须可观测，并对齐 P1-63／81。

### 3.7 改前／改后对照（B5）

不得写「同一最终镜像既要改前失败又要改后通过」而无控制。采用其一：

1. **双镜像**：冻结基线镜像（或已知越线候选）与最终镜像，同一夹具／资源／请求序列；或
2. **对照臂**：最终镜像上测试专用关闭快路径／让出的开关，并证明该臂走旧路径且可复现越线。

## 4. 核心流程（伪代码）

```text
# OQ-2 已裁定＝A（同进程让出）

classify(req) -> A_static | B_session | C_auth_write | other

onIncomingHttp(req):
  kind = classify(req)
  if kind == other:
    return existingHandlers(req)
  # 选项 A：H1 等生产热点单片同步 ≤ 250ms 并在片间让出（§3.1.1），使下列路径可被调度
  if kind == A_static:
    return serveStaticCommitted(req)      # 代次缓存；禁 MCP／全量展示构建
  if kind == B_session:
    return serveAuthStatusFresh(req)      # 每请求鉴权；禁共享 me 缓存
  if kind == C_auth_write:
    return serveLoginFullSemantics(req)   # 限流／scrypt／Session／审计；合法凭据须成功

underPressure(window):
  assert entry_A_B_C_meet_budgets(window)           # 客户端时间
  assert livez_and_entry_separable(window)
  assert at_least_one_mainpath_success(window)      # MCP 或管理只读至少一臂成功，见 SC-06
  for arm in [mcp, admin_read]:
    if not success(arm):
      assert bounded_reject_within_10s(arm)         # 超时／0-byte／挂起 → FAIL
      assert post_pressure_retry_success(arm)       # SC-06b，同 PID
```
