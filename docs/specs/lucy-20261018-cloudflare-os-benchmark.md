## 0. 一句话结论

Cloudflare OS 是全员浏览器 Agent 工作区。Lucy 是数据 Agent 的上下文编译器、受治理 MCP 运行时，以及规划中的可刷新报告。

值得对标的是：业务人员如何安全地重复使用公司数据，以及治理如何出现在界面上。个人应用运行时、办公套件、万能连接器、开源托管留在产品边界外。

19 项里：直接对标 7，改成 Lucy 形态 5，Lucy 已经更完整、应保持 3，留在边界外 4。

先做三件已经写进设计、界面上还看不见的事：问询读过哪些表，报告刷新是否走语义契约，分享时按查看者权限重判。然后给业务人员一个窄的浏览器问数页。

## 1. 两边各是什么

| | Cloudflare OS | Lucy |
|---|---|---|
| 公开时间 | 2026-08-04 开源；2026-10-01 开放全托管候补 | 本仓 `lucy-v2.0` 持续交付 |
| 谁在用 | 公司里每个员工的浏览器工作区 | 数据工程师和管理员的治理台；问数发生在客户自己的 Host Agent |

## 2. Cloudflare 内部五条原则，Lucy 怎么接

来源是 Cloudflare CIO Sam Rhea 2026 年 8 月的内部推广复盘。

| 原则 | Lucy 的接法 | 落点 |
|---|---|---|
| 先有要完成的工作，再选工具 | 用现场提问收集重复问法，再发布 Skill 和评测 | 质量评测 |
| 非工程人员也要能使用 | 浏览器问数页只开放已发布语义和 Skill | 第二波 |
| 人拥有产出 | Skill 与报告有负责人，账户停用后交接 | 第一波起 |
| 组织上下文重于模型 | 继续用语义资产、Wiki 和发布门禁，模型留在客户的 Agent | 保持 |
| 用 AI 时权限不放大 | 查看者重判；结果释放前已有耐久记录，字段级出站策略另计 | 第一波 |

内部复盘还有一条直接适用的警告：把擅长写代码的工作台交给所有人，会先出现一批还没有业务问题的应用。所以第二波问数页的产出固定为报告，模板只带口径和布局。

## 3. 三波升级

第一波只改已经存在的治理界面，以及设计里已经写明的报告状态。第二波才增加业务入口。第三波等企业合同提出身份、预算和限额。

### 3.1 第一波 · 治理可见

- 访问日志详情显示本问询读过的表、轮次和耗时。问询预算默认是 20 次数据工具或 120 秒，协议里已有，界面上没有当场展示。
- 使用概况按 Agent 汇总消耗，预算用尽时给出明确提示。
- 可刷新报告预留三行状态：上次成功、本次失败、本次走语义契约。失败保持失败标记。Cloudflare 第一版的教训是每天重跑同一份晨报，token 耗在重复步骤上。
- 现场提问里的高频问法，在业务 Skill 页变成待发布清单。
- Skill 增加负责人。

### 3.2 第二波 · 窄的问数页

依赖可刷新报告的固定入口。该平面在 `docs/design/design-agent-live-report.md` v1.5，尚未作为已上线页面。

- 客户品牌下的浏览器页面：选择已发布 Skill，或在已发布语义里提问。
- 左侧提问，右侧打开报告。提问仍走现有 MCP 治理。
- 资源卡只出现在角色已允许的表上，动作写明「将读取」。
- 分享报告与分享模板分开。模板不含他人数据和授权。
- 返回外部 Agent 的字段写入出站记录。安全账本已经要求内容释放前先耐久记录，这和字段级防泄漏是两件事，见 §4。

### 3.3 第三波 · 企业控制

- 身份源对接。当前边界仍是本地登录账户，以及设计中的独立报告查看会话。
- 按团队汇总工具调用预算，以及触顶后的行为。
- 按角色限制调用速率。
- 负责人停用后，名下 Skill 与报告交给指定接替者。
- 列级脱敏维持现有范围，除非合同单独要求。

## 4. 对照清单

处置口径：对标是做成 Lucy 的界面或运行时；改造是同一目标、Lucy 的形态；保持是 Lucy 已经更完整；边界外是另一类产品。

### 4.1 对标（7）

| 主题 | Cloudflare OS | Lucy 现状 | 下一步 |
|---|---|---|---|
| 起始页是重复工作 | 登录后从部门技能开跑，成果在右侧。主路径是已有工作 | 业务 Skill 在治理台查看发布状态。执行发生在 Cursor、Claude Code、Codex 等外部 Agent | 已发布 Skill 做成可点的工作清单。点开后的成果是报告 |
| 当场看见读什么、花多少 | 会话中出现资源卡：系统、对象、读取动作，以及 Skip / Connect。角上标出本次花费 | 权限由管理员事先配置。问询预算在协议中。访问日志事后能追到表和轮次 | 在访问日志详情和未来的问数页，当场显示将读取的表、已用轮次和耗时 |
| 看过的数据跟着产物走 | 记录 Agent 观察过的每个资源。他人打开时，按对方对原始资源的权限重判 | 访问日志按问询记录触达的表。报告设计要求快照授权摘要与当前授权一致，否则停发。界面上还没有这个对象 | 每份报告列出读过的表。查看者缺权限时写明缺哪一项，并停发该快照 |
| 使用数据时权限保持原样 | 用 AI 时对业务系统的权限不得大于本人原有权限。分享后使用接收者自己的授权 | Agent 经 Token、角色、表范围和行策略访问，数据库账号只读。设计已写明查询权与发布权分开 | 写成客户能看见的承诺。分享时按查看者角色重判，作者权限不随之转移 |
| 重复报告不再重跑模型 | 第一版每次重跑技能都消耗大量 token。第二版把稳定步骤写成应用，再次打开同一份晨报时不再调用模型 | 愿景和报告设计就是按语义契约定时刷新，刷新不携带外部对话 Token。该页面尚未交付 | 状态写明上次成功时间、本次失败，以及本次走的是语义契约 |
| 结果离开信任域前留下记录 | 推理经过 AI Gateway，可套用数据防泄漏规则，使指定数据到不了模型供应商 | 2026-10-18 安全账本要求先耐久记录再释放内容（ADR D2）。企业安全 Spec 写明：合法结果交给客户端之后的出站治理，由客户部署策略共同负责。这还不是按字段拦截送往模型供应商 | 账本继续做释放前记录。字段级「哪些列可以离开」另立范围，先从记录放行字段开始 |
| 产出有负责人，并可交接 | 人对其 AI 产出负责。员工离开后，经理继承这些 Agent 和工作流 | 配置审计记录操作者。Skill 和报告还没有负责人，也没有账户停用后的交接 | Skill 与报告增加负责人。账户停用时把名下资产交给指定接替者 |

### 4.2 改造（5）

| 主题 | Cloudflare OS | Lucy 现状 | 下一步 |
|---|---|---|---|
| 业务人员用浏览器问数 | 全员浏览器工作区。认证后即可运行，工作在云端继续 | 治理台在浏览器。业务问数需要单独配置外部 Agent。可选 Agent Chat 不进入默认交付包 | 增加客户品牌下的问数页，只覆盖已发布语义和 Skill。身份先用独立的报告查看会话 |
| 按人、团队和用途看消耗 | AI Gateway 按人、团队、工作区归因，可设预算、速率和触顶行为，并把例行任务转到更小的模型 | 模型费用在客户的 Agent 订阅里。Lucy 能看的是调用监控、使用概况和问询预算 | 使用概况按 Agent、Skill、报告汇总工具调用和耗时，并写明预算用尽后的提示 |
| 入口用客户的名字 | 核心与部署仓分开。部署仓放客户术语、界面、连接和策略 | 品牌外观可改 Logo、产品名和副标题。语义、Wiki、Skill 已经是独立的客户包 | 业务入口显示客户产品名。实施只交付客户包，核心升级不要求改语义文件 |
| 定时刷新先于事件触发 | 工作流可手动、定时或由外部事件触发。确定步骤用代码，判断步骤才调用模型 | 报告定时刷新在设计中。没有通用工作流引擎，也没有工单或 CRM 事件入口 | 第一期只做报告的定时与手动刷新。事件触发等有真实上游再单独立项 |
| 企业身份源 | Cloudflare Access 校验每个用户和每次请求。托管版需要域名、访问策略和 AI Gateway | WebUI 使用本地登录账户。当前规格把 SSO 放在范围外。报告设计要求查看者单独登录，匿名链接不可读 | 先做实查看者登录、席位和匿名不可读。身份源对接放到企业合同明确要求时 |

### 4.3 保持（3）

| 主题 | Cloudflare OS | Lucy 现状 | 下一步 |
|---|---|---|---|
| 语义契约、评测和发布门禁 | 公司上下文主要是术语、流程和技能文档。公开材料没有评测集、发布校验或指标契约 | 表粒度、指标、分群、关联、业务 Wiki、评测用例、趋势和发布工作台已在治理台 | 继续把质量飞轮做深。上下文保持可校验的语义资产 |
| 从真实问法长出技能 | 用人工值守的邮箱收集员工不想重复做的工作，再写成技能和连接。内部估计销售团队一个月省下约 1 万小时 | 现场提问和安全评测候选已从访问日志收问法，并可以收成评测用例 | 写成客户上线方法：先收重复问法，再发布 Skill 和评测 |
| 凭据隔离与只读数据面 | Gatekeeper 代持凭据，可限制到单个资源、遮蔽字段、限速，写操作可要求人工批准 | 数据库凭据不进入 Agent。范围是连接、表和行策略。列级脱敏在当前范围外。数据面使用只读账号 | 保持只读和凭据隔离。按角色的调用限额放到第三波。列级脱敏维持现有边界 |

### 4.4 边界外（4）

| 主题 | Cloudflare OS | Lucy 的边界 |
|---|---|---|
| 个人应用运行时 | 每个文件可以是隔离的全栈应用，可分享应用或只分享蓝图。内部 30 天新建超过 4,000 个应用 | 规格写明不做任意脚本托管，也不做拖拽式 BI。分享物限于报告和报告模板 |
| 文档、幻灯片和表格 | 工作区直接产出可继续编辑的文档、幻灯片和表格，并可导出到 Google Drive | 业务交付面是可刷新的报告和看板。长文档编辑留在客户已有的办公工具 |
| 连接公司里的每一个系统 | 用 Gatekeeper 和 MCP Portal 接入工单、代码库、CRM，并加上速率和区域控制 | 治理对象是客户数据库和已发布语义。API 接入仍是计划中的准入 |
| 开源核心与一键托管 | 核心与示例部署分仓。2026-10-01 开放全托管候补，伙伴包含 Presidio 与 Happy Cog | 客户以 Docker 或 Kubernetes 私有化运行。启动说明收成三项：地址、身份、Agent 接入 |

## 5. 界面手感

这些交互来自 Cloudflare OS 产品页和内部第一版。落到 Lucy 时，对象仍是表、问询、Skill 和报告。

| 界面 | Cloudflare OS | 落到 Lucy |
|---|---|---|
| 起始页 | 部门技能，一键运行 | 业务 Skill 对授权用户显示可运行清单 |
| 布局 | 对话在左，成果在右 | 问数页左侧提问，右侧打开报告 |
| 资源卡 | 系统、对象、动作、跳过或连接 | 仅对已授权表显示「将读取」 |
| 消耗角标 | 会话角上的金额 | 问询角上的轮次、秒、表数 |
| 刷新徽章 | 再次打开应用不再调用模型 | 报告标明上次成功，以及本次是否走语义契约 |
| 两种分享 | 分享应用，或只分享蓝图 | 分享报告，或只分享模板 |
| 默认私有 | 应用默认只有本人可开 | 匿名链接不可读，查看者单独登录 |

## 6. Lucy 应继续拉开的差距

Cloudflare OS 的上下文是人写的术语、流程和技能。Lucy 的上下文是可校验的语义资产：粒度、指标、分群、关联、发布校验和评测。现场提问把真实问法收成用例。私有化部署让数据留在客户环境，模型留在客户自己的 Agent 里。
