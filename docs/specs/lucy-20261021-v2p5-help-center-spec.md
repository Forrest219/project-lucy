Lucy 当前是「单一长页面 + 左侧 H2–H4 目录 + 子串搜索」，没有分类门户、文章页、面包屑和本页目录；手册 3144 行，首次打开即整卷渲染，定位和阅读负担大。这是本次改造的出发点。

### 1.3 明确不照搬的部分

Kimi 帮助中心是公开营销站点的一部分，以下内容与 Lucy 治理台内置帮助的产品形态冲突，不照搬：

- 站点营销页脚、下载 / 试用 / 登录入口、社交媒体图标墙；
- 分类封面使用外链摄影图（Lucy 客户环境离线，必须零外部资源依赖）；
- 多文章 CMS 后台、阅读反馈投票、在线客服入口（本轮探查文章页末尾未见反馈组件，亦不引入）；
- 把帮助做成对外的产品营销页。Lucy 帮助中心继续服务已识别的三类读者：管理员、接入协作者、开发者。

## 2. 需求判断、目标与边界

当前系统手册信息架构是一维的：3144 行单页、H2–H4 平铺目录、搜索命中落到章节锚点。读者回答「我这个角色第一步做什么」「某个功能模块怎么配」需要在一维长目录里上下翻找。对标 Kimi 后，三层 IA（分类 → 文章 → 小节）能把同一本手册变成可浏览、可检索、可深链的门户；这属于展示与信息架构改造，不是新运行时能力，与 §2 既有五项展示改造同类。

本期包括：手册分类门户首页、分类页、文章页、本页目录、搜索结果归属化展示、URL 语义化与深链兼容。目标旅程：打开 `/help` → 按角色或任务找到分类 → 进入文章 → 用本页目录跳到小节 → 需要时搜索直达。

本期不包括：内容重写或扩写（手册正文继续由 `docs/SYSTEM_HANDBOOK.md` 单一事实源驱动，自动同步机制不变）；多文件 / CMS 化改造；搜索分词或向量检索；反馈投票与数据分析；帮助内容的多语言版本；新增任何权限、审计或配额语义。公开可访问（无需登录即可查看）保持不变。

## 3. 信息架构合同

### 3.1 三层 IA 与既有手册结构的映射

服务端继续只读 `docs/SYSTEM_HANDBOOK.md`，从标题结构派生三层 IA，不改事实源文件的维护方式：

- **手册分类** = H2 章。现行 7 章映射为 7 个分类：常见问题速查、系统概述与架构拓扑、快速上手、功能模块操作指南、Agent / 客户端接入指南、配置与环境变量速查、FAQ 与排障指南。
- **手册文章** = H3。每个分类下的 H3 是一篇文章，文章页是新的阅读单位。
- **小节** = H4。文章页内部的锚点，进入右侧「本页目录」，不进左侧分类树。

现行手册 H2 之下存在游离的 H2 块（如 YAML 交付章节内的「结论 / 阻断项 / 验收命令」）。这些块在派生时归入所属分类（按其在文档中的最近前置 H3 所属文章），不得生成新分类或孤儿页面；无法归属的游离标题列入构建期检查失败，要求作者修正手册结构。

### 3.2 分类元数据

分类卡片与分类页需要「一句话描述」和「文章数」。描述取该 H2 章引言首段（截取约定长度），不在手册外维护第二份描述表；文章数由派生 IA 实时计算。分类顺序即手册章节顺序，不另设排序配置。

### 3.3 URL 与深链

- `/help`：帮助首页（分类门户）。
- `/help/<分类 id>`：分类页。
- `/help/<分类 id>?section=<文章 id>`：文章页；文章 id 沿用 `SECTION_ID_CONTRACT` 的稳定 id。
- 现行 `/help?section=<id>` 深链与 `LEGACY_SECTION_IDS` 全部继续可用：新路由落地后旧查询串映射到对应分类页下的文章位置，不静默失效、不出现死链。
- 搜索、场景内引导（如 MCP 调试台、登录页帮助入口）继续以 section id 为引用单位，id 语义不因 IA 改变而变化。

## 4. 页面合同

### 4.1 帮助首页

- 问候标题 + 说明副题（沿用「系统手册」产品名，术语见 Terminology Compliance）。
- 居中大搜索框：placeholder 轮播真实高频问题（取自手册 FAQ，如「MCP 返回 401 怎么查？」），轮播文案来自手册内容，不在前端硬编码第二份。
- 分类卡网格：分类名、一句话描述、文章数（「N 篇」）。卡片用产品图标与既有色板，不使用外链图片。
- 保留来源路径、更新时间、etag 徽章与「无需登录即可查看」说明，位置移至页脚信息区，不抢占首屏。

### 4.2 分类页

- 面包屑：系统手册 / 分类名。
- 分类标题、描述、文章数。
- 文章卡列表：文章名 + 首段摘要；摘要取文章正文首段，不另维护。
- 保留并显式展示 FAQ 性质的速查内容；「常见问题速查」分类即首页速查卡片的落地页。

### 4.3 文章页

- 面包屑：系统手册 / 分类名 / 文章名。
- 正文沿用 `MarkdownPreview` 渲染；架构图白名单（`HELP_DIAGRAM_IDS`）在文章页内继续可用。
- 右侧「本页目录」：该文章内 H4 小节锚点列表，随滚动高亮当前小节；短文章（可视高度内可读完）自动隐藏，不用空目录占位。
- 文末保留「返回系统概览」及分类内上一篇 / 下一篇导航（上一篇 / 下一篇为草案默认，列 §8 待裁决）。

### 4.4 搜索

- 沿用服务端 `/api/help/search` 子串匹配与现有排名（标题命中加权、命中数、首现位置）；本期不改匹配算法，分词或向量检索列 §8 待裁决。
- 结果展示升级：显示「找到 N 条相关结果」；每条结果标注归属路径（分类 › 文章）；结果按分类分组排列；保留关键词高亮与空态（空态文案引导换关键词，不引导跳出帮助中心）。
- 搜索入口：帮助首页居中；分类页 / 文章页在左侧栏。支持 Escape 清除、键盘可达。
- 搜索只命中手册正文与标题，不命中徽章、时间等界面元数据。

## 5. 兼容、工程与治理约束

1. 事实源单一：`docs/SYSTEM_HANDBOOK.md` 继续是唯一内容源，自动同步与 `etag` 机制不变；前端不缓存脱离事实源的第二份 IA。
2. 公开可访问不变；帮助中心不新增登录要求，不泄露需要登录才能看到的运行数据。
3. 分类树、面包屑、本页目录数字必须与派生 IA 同源；分类卡片文章数与分类页列表数一致。
4. 旧深链兼容以测试固化：`/help?section=<旧 id>`（含 10 位哈希旧 id）必须落在有效文章位置。
5. 零外部依赖：样式、图标、插画全部本地化；帮助中心在完全离线环境可用。
6. 浏览器翻译防御：分类名、文章名、路径、id 含英文术语的 DOM 节点带 `translate="no"` 与 `notranslate`（沿用 `HelpCenter.tsx` 现有做法）。
7. 可访问性：分类树展开折叠、目录锚点、搜索结果均可键盘到达；尊重 prefers-reduced-motion。
8. 不新增数据库表、不新增运行时接口语义；服务端仅增加 IA 派生数据（可由 `/api/help/handbook` 扩展字段承载），读取路径与安全约束（`assertHelpAppReadable`）不变。
9. 术语遵守 [webui/docs/00-product-terminology-standard.md](../../webui/docs/00-product-terminology-standard.md)；新增术语登记见 Terminology Compliance，不在 UI 中使用未登记说法。

## 6. 数据模型草案

在 `HelpHandbook` 响应上扩展派生字段（示意，最终以实施 Plan 为准）：

```text
HelpHandbook {
  ...现有字段不变（id/title/sourcePath/updatedAt/etag/toc/legacySectionMap/markdown）
  categories: HelpCategory[]
}
HelpCategory {
  id            # 沿用 H2 契约 id（faq-quick-reference 等）
  title         # H2 章名（去编号）
  summary       # 章引言首段截取
  articles: HelpArticle[]
}
HelpArticle {
  id            # 沿用 SECTION_ID_CONTRACT 稳定 id
  title         # H3 名（去编号）
  summary       # 正文首段截取
  sectionIds    # 文内 H4 小节 id 列表（本页目录数据源）
}
```

搜索响应每条增加 `categoryId / categoryTitle`，归属路径由前端拼接。以上均为只读派生，无写路径。

## Terminology Compliance

产品名沿用「系统手册」，导航名、面包屑首页级统一为「系统手册」；「系统帮助」不再作为面包屑出现。Catalog、Manifest、Schema、MCP 调试台等沿用现有定义。含英文术语、路径、id 的 DOM 节点必须带 `translate="no"` 与 `notranslate`。

## Design System Compliance

遵循 [页面布局模式](../../webui/docs/design-system/20-patterns-page-layout.md)：首页为门户网格，分类页为列表页，文章页为三栏内容页，不增第二套导航体系；按钮、卡片、面包屑复用既有组件规范。空态、加载态与降级显式说明，不用空图冒充正常结果。分类卡视觉不用外链摄影图，以图标系统实现。后续仅在明确授权的桌面验证阶段执行浏览器验证，本次无 UI 改动。
