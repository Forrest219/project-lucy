## 3. 范围与关键裁决

### 3.1 授权展示组（P1-1／P1-2／P1-3）

- R1 模板只复用静态谓词；R3 是独立只读页，不并入 Access Map，也不提供第二写入入口。
- 授权摘要只读复用有效权限，不新增 Agent 个人 `allow`、Token 授权或运行时裁决算法。
- Access Path 是窗口内允许调用的去重存在性路径，`accessCalls` 独立计数；全局调用按稳定调用 ID 去重。
- 确凿越权必须由调用当时匹配快照证明；缺失、损坏或身份不符均不得升级结论。
- 规划导航只登记设计目标；当前路由与菜单未实现。术语与 TD-187-01 已做设计登记，不代表 UI 已交付。

### 3.2 Hive（P1-4）

- 需要修改 KTX 才能正确、来源合并不一致、SQL 无法正确执行、策略不能证明聚合前生效时，停止对应能力交付。
- 禁止正则改 SQL、盲目转译、切换 MySQL／Postgres 驱动或删除安全断言绕过。
- 客户 HS2／认证／TLS／依赖未提供时，对应认证为 `blocked_environment`；参考环境结果不得外推。
- 数据库支持状态保持 `planned`；本 Spec、静态接口核查和文档 lint 都不是支持证据。

### 3.3 升级验证组（P1-5／P1-6）

- 固定真实旧版与候选身份；只用隔离、本次运行所有的 linux/amd64 环境，不触碰生产或共享 demo。
- 备份先在独立实例恢复，再执行原地升级；切换前失败与切换后业务失败分别取证和恢复。
- 候选验证必须空卷起步，先整卷覆盖再启动候选；含安全库时必须 quiesced 备份。
- 最新安全状态单独注入并轮换验证环境会话；来源不明时安全断言 `SKIPPED`，不得记通过。
- 两项均为非门禁；报告不写 `release-readiness.json`、`ops.json` 或签名发布包。
