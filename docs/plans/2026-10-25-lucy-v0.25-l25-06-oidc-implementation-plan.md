## 1. 范围

### 1.1 本轮实施对象

Spec §12 的四个阶段全部落地为实现产物：

| 阶段 | 内容 | 本轮产出 |
|---|---|---|
| S1 配置与账户模型 | 扩 `parseOidcProfile`（openid 必含／logout 可选）、启动期缓存、methods 派生、绑定 API 与 issuer 精确校验、最后本地 owner 保护、扩 `AuthEventKind`／`SUMMARY_KEYS`、本地 `method=local`、`password_removed` 与绑定事件 | 后端配置层＋账户层＋审计层 |
| S2 协议主链 | start／callback、一次性登录事务、code＋PKCE、ID token 验证、绑定解析、既有 v2 会话签发、§8.2.1 四类桶与 gate | 后端协议层 |
| S3 UI 与恢复体验 | 登录按钮、错误映射、绑定维护、退出说明、公开手册、术语防御 | 前端 |
| S4 客户交付 | Helm、Secret、离线依赖、升级回滚、amd64 K8s 与目标 IdP 验收 | Helm 接线与交付文档；**真实环境部分记 blocked** |

### 1.2 本轮不做（与 Spec 边界一致，不得越界）

- 不推送 registry、不注册 runner、不设 GitHub 变量与密钥、不产出客户离线交付包、不部署客户环境、不发布。
- 不接真实客户身份源、不做真实客户迁移；OIDC-24／OIDC-25 的真实链路证据**本轮不产生**。
- 不实现 IdP 全局退出、refresh token、离线访问、JIT 建号、email 匹配、IdP 组→角色映射、SSO claim、多 IdP、多副本。
- 不改 KTX 源码；不改 MCP Agent／Role／Token 数据面权限。
- 不升安全库 schema 版本（登录事务为进程内内存态）。
- **不把「代码实现完成」写成「验收通过」或「客户交付通过」。**

## 3. 依赖与库决策（Spec §12 要求实施 Plan 确定）

| 项 | 决定 | 依据 |
|---|---|---|
| OIDC／JOSE 库 | **`jose@6.2.13`**（MIT，维护中，零运行时依赖，ESM-only，Node ≥ 20） | Spec §8.3 要求用维护中的库、不手写 JWT 验签。本机 Node v24.14.1 满足。`jose` 提供 `jwtVerify`／`createRemoteJWKSet`，覆盖 RS256＋JWKS＋claims 校验 |
| code 交换 | Node 内置 `fetch` 直接 POST 静态 token 端点 | Spec §4.2「静态端点为唯一事实源」，不做 discovery，不引入第二个 OIDC 客户端 |
| 运行时 | Node v24 + ESM，`tsx server/index.ts` | 仓库现状，jose v6 ESM-only 与既有 `.js` 后缀导入一致 |

## 4. 波次定义

### W1 后端主链（主持执行）

1. **配置层**：扩 `parseOidcProfile`——`scopes` 必含独立 scope `openid`；`endSessionEndpoint`／`logoutStyle` 转可选；`discoveryUrl` 保持可选且不参与裁决。
2. **运行时层**（新 `oidc-runtime.ts`）：启动期读取 profile＋secret，构造 `oidcRuntimeView { enabled, profile, profileDigest }`；secret 只驻内存；失败时 `enabled=false` 且**不抛到启动流程**（本地登录继续）。
3. **事务层**（新 `oidc-transactions.ts`）：进程内一次性事务，键 `SHA256(state)`，TTL 10 分钟，上限 1024，**先消费后校验**（成功失败均不可重放）。
4. **客户端层**（新 `oidc-client.ts`）：code 交换（PKCE verifier＋精确 redirect_uri＋单一 secret 方式）；`jose` 验签（JWKS 远端缓存、未知 kid 有界刷新一次、拒绝 `none`／`HS*`）；校验 `iss`／`sub`／`aud`／`azp`／`exp`／`iat`／`nonce`。
5. **协议路由**（新 `oidc-routes.ts`）：`POST /api/auth/oidc/start`、`GET /api/auth/oidc/callback`；`returnTo` 站内绝对路径白名单；`Cache-Control: no-store`、`Referrer-Policy: no-referrer`。
6. **账户层**（`routes.ts`／`admins-store.ts`）：绑定写接口（`PUT`／`DELETE`）、带绑定建号、`removeLocalPassword`、最后本地 owner 保护、`OIDC_ISSUER_MISMATCH` 仅由绑定写接口返回。
7. **限速层**（`rate-limit.ts`）：四类桶＋`gateOidcStartAttempt`／`gateOidcCallbackAttempt`；事务桶只为已存在真实 `stateHash` 创建。
8. **审计层**（`auth-events.ts`）：扩 `AuthEventKind`（`password_removed`、三个绑定事件）与 `SUMMARY_KEYS`（五新键）；**未知键在开发测试中显式失败**，不得静默丢失；本地登录补 `method=local`。

### W2 前端 UI（worker）

登录页 OIDC 主按钮与辅助说明、OIDC 失败固定错误映射、账户页「登录方式」与「身份绑定」维护、退出文案、术语防御（`translate="no"`＋`notranslate`）、`returnTo` 传递。不做移动窄屏测试（仓库默认口径）。

### W3 交付接线（worker）

Helm `oidc.enabled`（默认 false）、`existingSecret`／`clientSecretKey` 引用、ConfigMap＋Secret 只读挂载、Pod env 仅两个文件路径、`extraEnvFrom` 覆盖保护、`enabled=false` 不接线、probes 不访问 IdP、离线不拉 discovery／JWKS／前端资源。

### W4 集成挂载（主持）

`webui/server/index.ts` 挂载 OIDC 路由；前后端契约联调。

### W5 Code Review（对抗式）

对 W1–W4 全部改动做独立对抗式审查：Spec 合规、安全边界（state／nonce／PKCE／token 处理）、审计封闭清单、限速维度、失败关闭路径、术语一致性。

### W6 Debug & 优化（主持）

跑全部单测＋类型检查＋两个 lint 门禁；按失败清单定位修复（系统化调试，不猜）；补齐可自动化的验收断言。

### W7 汇总与交付（主持）

按 S2 要求产出**进展汇总 MD**，随附验收状态表（OIDC-01–26 逐条标注「已执行／未执行／blocked_environment」＋证据位置），交付审阅后 commit。

## 6. 风险与阻断

| 风险 | 处置 |
|---|---|
| `jose` 为 ESM-only，仓库 server 已是 ESM | 无迁移成本；若工具链报类型错，用 `import type`＋本地声明兜底 |
| 依赖进离线镜像需重建 amd64 镜像 | 属交付链职责；本轮只保证 lockfile 与 SBOM 口径已就位，镜像重建不在本轮 |
| 真实 IdP／amd64 K8s 证据缺失 | OIDC-24／25 记 `blocked_environment`，不以 mock 替代 |
| 共享 `sourceTotal` 与 D10／OIDC-14 措辞冲突（终审 N-02） | 实施 Plan 落文：在 D10／OIDC-14 口径处补限定语；不改共享桶设计 |
| `issuerDigest` 无写入点（终审 N-01） | 实施时在 `account_not_bound` 分支同时记录 `issuerDigest`＋`subjectDigest`，与 §8.1 键表用途对齐 |
| 既有 P0／P1 交付阻断 | 本功能不解除既有阻断；P0 波次状态不变 |

## 7. 汇总与交付

- **S1**＝W1–W6（开发 → Code Review → Debug&优化）。
- **S2**＝W7：进展汇总 MD ＋ 验收状态表 ＋ 证据位置 → **交付审阅** → commit。
- 汇总 MD 落 `docs/reviews/` 或 `docs/plans/`，**不新建与 Spec／评审记录并行的第三份口径源**；验收状态以汇总 MD 为准。
- commit 前置：`npm run lint:spec`、`npm run lint:terminology`、`npm run lint:ia-boundary`、webui `npm test`、类型检查全部通过；未通过项必须在汇总 MD 中显式列出并说明。
