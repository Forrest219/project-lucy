## 1. 目标与非目标

### 目标

- 5 个已在本机复现的缺陷，各自在候选上有**先红**的自动化用例，修复后**转绿**，且场景规模、阈值、断言不被降低。
- 修复遵守各 Spec 修订草案的合同，不新增无逃生的不可用路径（第一性原理：主路径可用性优先）。
- UAT 判定能识别「预算耗尽后零进展」「慢拒绝」「追平后导出」「跨回看边界」这四类此前判定看不见的状态；runner 的通过判定不再把「读到 0 列」算作通过。
- 工作区的 8 个被跳过的移植用例要么转绿，要么每个有总账行与负责人。

### 非目标

- 不重开 v2p5 S01–S07、P1-20、P1-34、P1-38 的现行收口状态与 SC／LS／EC 现行验收。
- 不合入 84 分支整体，只移植其中已被证明的做法（F01 的 `catchUp.lag`、AUDIT-01 的区间闭包）。F04 不可直接移植（84 依赖候选没有的 `batchRead`），按 P1-34 §11 自行实现。
- 不做治理类长期改进（`it.skip` 须挂总账 ID 的 lint、端口对账表、套件到受守源码路径的映射）：错题本 §6 标「未开」，交付后再议。登记 6 个未登记根测试与恢复 `it.skip` 时逐个挂总账行属于本 Plan 范围（Task 1、Task 7）。
- 不做客户环境、Helm／K8s、amd64 出包、客户部署。

> **历史计划说明（2026-11-19 复评后）**：下文原 Task／前置表记录上一批计划与当时证据，不构成新的执行指令。未完成或被证伪项现由 P1-57 承接，确认前不得继续实施。

### Task 2 F02 慢拒绝不得判超时（P1-20 §8）

- 内容：超时只认显式超时信号；显式拒绝一律继续降级探测；探测共享调用预算；预算内真超时为终态；预算封顶的超时记 `deferred`。
- 范围：只改外部目录探针路径，用专用分类器；**不得全局删除或改写 `columnScanTimedOut` 的既有兜底**，普通 MySQL 单表与 `schema-wide` 不变（P1-20 §8.2 C6）。
- 验证：EC-14–EC-17 转绿（EC-15 为读取层断言：压缩预算、结果必须是 `deferred`；EC-16 为应绿对照；EC-17 每个边界值后接成功探针）；P1-20 既有 EC-01–EC-13 保持通过。

### Task 3 F04／F03 预算耗尽后必须有进展，单表不得静默成功（P1-34 §11）

- 内容：**服务端保持候选的硬上界**（每次调用只有第一条 columns 语句可用满单表超时，其后受剩余预算约束；**不得**以「尚无终态」放宽超时，Codex 终审 LS-B1）；单表预算耗尽返回 `deferred`（HTTP 200）而不是空成功；客户端按批次减半并在单表连续两次 deferred 后给出失败项；任何批次都有披露。
- 前置：新增用户可见句子「表「x」这次没有读完，请稍后重试。」须先登记 `webui/docs/00-product-terminology-standard.md`，再写 UI 文案。
