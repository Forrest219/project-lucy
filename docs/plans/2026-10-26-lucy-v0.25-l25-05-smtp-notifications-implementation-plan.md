## 1. 分阶段实施

### S1 配置与 outbox（本轮）

| 改动文件 | 内容 |
|---|---|
| `webui/server/notifications/profile.ts`（新增） | profile／password／CA 的严格解析与校验；封闭错误码；拒绝内联密码 |
| `webui/server/notifications/runtime.ts`（新增） | 启动期一次加载并缓存的运行时视图；关闭时不读密码文件；脱敏状态投影 |
| `webui/server/notifications/outbox.ts`（新增） | `notification_outbox` 表与索引（**由通知自身初始化路径创建**）、入队去重、pending 上限、过期转 dead、保留期清理、事故行查询 |
| `webui/server/notifications/state.ts`（新增） | 通知自身故障的封闭错误码（不改变审计结果） |
| `webui/server/notifications/health-events.ts`（新增） | 审计健康转换 → outbox 的**同步、无副作用**适配器；恢复事件要求事故行已持久化 |
| `webui/server/notifications/init.ts`（新增） | 启动初始化：建表 → 读配置 → 订阅健康事件；失败只关闭通知本身 |
| `webui/server/proxy/audit-write-health.ts` | **F-13 抖动抑制**：稳定窗口（连续 3 次或持续 60 秒）后才升级为事故／恢复；转换事件订阅 |
| `webui/server/admin/notifications.ts`（新增） | owner-only 只读状态端点（不含 host／username／from／收件人／secret） |
| `webui/server/index.ts` | 启动装配：监听端口前初始化通知；注册状态路由 |

| 测试文件 | 覆盖 |
|---|---|
| `webui/server/__tests__/notifications-l25-05.test.ts`（新增） | SMTP-01～04／07～09／13／15／19／21 的 S1 口径 + F-13 抖动抑制 |

### S2 SMTP worker 与 API（未开始）

- SMTP 库选型：**许可证、维护状态、lockfile、SBOM、amd64 离线镜像**必须先落定（Spec §12）。
- worker：单 worker、单封在发、5 秒轮询、连接 10 秒／总发送 20 秒、有界退避、租约与崩溃重领、at-least-once。
- `POST /api/admin/notifications/test`（owner，202 queued）与 `GET /api/admin/notifications/:id`。
- 固定模板与 Bcc；`requireOwner` 文案参数按 Spec §7 二选一执行。
- 依赖选型未落定前**不得**手写 SMTP 协议或 shell 调用 sendmail。

### S3 交付接线（未开始）

- Helm：`smtp.enabled=false` 默认；只读 ConfigMap 挂 profile、独立 `existingSecret` 挂密码；values 禁止 `password`；缺 Secret／内联密码／非法值 render 失败；`extraEnvFrom` 不得覆盖固定文件路径。
- Compose 示例、系统手册（配置与排障）、依赖与 SBOM、升级回滚 Runbook。

### S4 真实验收（未开始）

- 客户目标 SMTP + linux/amd64 K8s 的测试、事故、恢复、重试与重启证据；环境不足保持 `blocked`。

## 2. F-13–F-17 在实现中的落点

| 发现 | 落点 |
|---|---|
| F-13 抖动抑制 | `audit-write-health.ts` 的稳定窗口：连续 3 次失败或持续 60 秒才升级为事故；恢复同理；一次事故共用同一 `incidentId` |
| F-14 建表责任与 audit schema 版本 | `outbox.ts` 的 `ensureNotificationOutbox()` 由通知自身初始化路径调用，不依赖 admin 句柄是否已打开；`audit.sqlite` 的独立版本机制在 S3 随迁移一并登记 |
| F-15 两类 503 | S2 的 `POST /test` 实现时按 Spec §6 伪代码区分 `NOTIFICATION_UNAVAILABLE` 与 `NOTIFICATION_QUEUE_UNAVAILABLE` |
| F-16 403 文案 | S2 决定复用 `requireOwner` 既有文案，或加可选文案参数并列入回归范围 |
| F-17 重新启用后历史行 | S2 的 worker 领取逻辑按 `expires_at` 与收件人快照处理 |

## 3. 风险

| 编号 | 风险 | 处置 |
|---|---|---|
| R-05 | 通知初始化失败拖垮启动 | `initNotifications()` 全程 try/catch，失败只关闭通知；登录／MCP／审计不受影响 |
| R-06 | 审计健康事件在高频写入下误报 | 稳定窗口 + 连续计数；抖动不产生事件（见测试） |
| R-07 | 秘密泄漏 | 密码只来自独立 Secret 文件；profile 内联密码被拒；状态摘要不含 host／username／from／收件人 |
| R-08 | outbox 与其它审计写入耦合 | outbox 在既有 `audit.sqlite`，不新建库；写失败只记通知故障 |

---

## 4. 实施边界

- 本轮**不连接任何 SMTP 服务器**，不打开出网连接，不发信。
- 不改 `security.sqlite`／安全库 schema 版本；不改 MCP／登录／权限合同。
- 不新增依赖（SMTP 库留到 S2 选型）。
- 不执行浏览器测试（仓库默认约束）。
- 不宣称 SMTP-01–26 任何一项验收通过。
