# Lucy v0.25.0 Formal Release Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 把 `lucy-v0.25` tip 经 CI 绿灯合入 `main`，打 annotated tag `v0.25.0`、创建 GitHub Release、回填发版台账，并在合流后从 `main` 开 `lucy-v0.30` 产品线。

**Architecture:** 遵循 [`docs/runbooks/lucy-release-train-workflow.md`](../runbooks/lucy-release-train-workflow.md) 的 P0→P1→P4→P5 顺序：先修 tip 门禁，再 PR 合流（merge commit、禁 squash），再 tag / Release / 台账，最后开 `lucy-v0.30`。客户交付包与 `productionReady` 与「意图 tag」解耦——无 GH 放行链（无 `lucy-protected` runner）时，允许像 `v0.20.0` 一样 `deliveryPackage: null` + 显式 `noDeliveryReason`，但不得谎称可生产放行。

**Tech Stack:** GitHub PR/Actions、`VERSION` 治理、`docs/releases/v0.25.0.json` 台账、`gh release`、可选本地 `scripts/gates/build-k8s-delivery-package.sh`。

## Global Constraints

- 产品版本本波保持 **`0.25.0`**；不在合流 PR 里切到 `0.30.0`。
- 合流通道：PR `lucy-v0.25` → `main`；**禁止直推 `main`**；**禁用 squash**（保留提交粒度与 `BUILD_REVISION` 可追溯）。
- Required checks：`spec-and-webui`、`docker-smoke`、`k8s-static`、`k8s-upgrade-gate` 必须绿才可合。
- 本地 `main` 当前落后 `origin/main` **287** 提交；任何本地操作前先 `git fetch` + `git pull --ff-only`。
- `lucy-v0.25` 相对 `origin/main`：**超前 26 / 落后 1**（落后仅 PR #61 merge commit）。
- 仓库无 `lucy-protected` self-hosted runner → GitHub `real-e2e` → `customer-release-readiness` → `release-package` 链不可完成；台账必须如实写 `notExecuted` / `failed` 原因。
- 从 `v0.20.0` 下一产品版本起，若台账写 `productionReady: true`，必须有 `webui-ux-review` 指向 `docs/releases/ux/0.25.0.md` 且结果块为 passed。本计划默认：**先完成意图发布（tag + Release + 诚实台账）**；`productionReady` 仅在 UX 走查与制品身份齐备后才置真。
- 规则与回复不复述密码；凭据只读桌面路径。
- 开 `lucy-v0.30` 必须从**合并后的** `origin/main` 切，不得从未合完的 `lucy-v0.25` tip 切。
