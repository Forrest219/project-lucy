维护质量的人在 WebUI 里做四件事：写评测用例、看一次运行、看趋势、把日志收成用例。下面每项能力都落在其中一页上，做完之后这一页的操作变了。

两套客户日志用来说明提问的人实际碰到什么。本文不新增题目。

这四页都在客户自己的 Lucy 里完成。Lucy 当前不接入大模型。一次评测运行编译用例里写明的指标、维度、过滤和截止日期，对着客户自己的库重新执行，再对照表。维护的人不需要在集群上安装 Agent，也不需要模型密钥。问句原文给维护的人读。模型会不会理解这句问话，留到 Lucy 自己能接模型之后。

评测用例页今天已经能下载套件、上传运行结果，并用套件哈希决定这次结果进不进趋势。理想路线沿用这个收口。跑批程序随 Lucy 交付，在能访问客户库的环境里执行。

## 客户走完一轮

维护质量的人在客户的 Lucy 里设计题、收回结果。跑批发生在能访问客户库的环境，可以是同一个人手动执行，也可以是客户自己的定时任务。

### 线上：设计与维护

一条评测用例有两层，都在「评测用例」里改。

- 问法写给人看，保持「本月」「昨天」「某个业务期间」这种说法。
- 可执行的部分写明：要哪个指标、按什么维度和粒度、必须带上哪些条件、哪两条查询应当对得上（例如按日加总等于按月，部分等于合计）。

题目从两条路进来。维护的人按已发布的语义直接写。现场反复没拿到表、或反复带错条件的查法，在「现场提问」里审定后收进来，措辞由人改完再保存。过滤值和客户版本字符串不自动进用例。

每次保存形成套件的一个版本，页面给出套件哈希，并可以下载 Eval YAML。语义发布变了，相关用例标成待复核。人还没有确认之前，这些用例不进入下一轮的通过率。

### 线下：跑批

维护的人下载当前这份套件，或由定时任务取同一份。跑批时给出截止日期。程序对每一条用例做四步：

1. 把问法里的相对时间按截止日期绑成窗口。
2. 按用例里的指标、维度、过滤编译查询。
3. 在客户库里执行。
4. 对照两类事情。结构：能否编译、列齐不齐、粒度有没有变粗、身份条件在不在、要的业务指标有没有出现。勾稽：用例写明的两条查询，结果是否一致。

新数据进来导致数字变化，记为数据变化，这一条仍算通过。列、粒度或过滤条件变了，记为答错了。编译失败、指标没绑上、分组或语句错误，记为没答出来。

跑批写出一份结果文件，带套件哈希、截止日期，以及每一条的结论和原因。这份文件不经过 Agent，也不访问模型。

### 上传：收回运行

回到「评测用例」，上传这份结果，先预检。

- 套件哈希与线上当前版本一致：归档为一次评测运行。通过率按「该给出答案的用例里答对了多少」计算，没答出来不进入分子和分母。这次运行进入运行历史和趋势监控。
- 哈希不一致：线下改过题，或线上已经另存了一版。这次结果不进入通过率和红线。维护的人把线下改动同步回线上用例，重新跑批再上传；只想留档时，归档为本地变体。

然后打开这次运行。答错了去核对语义或用例里的表期望，没答出来去补指标绑定或修正分组。改完用例会得到新的套件哈希，下一轮跑批再上传。

## 1. 今天打开这些页面，完成不了什么

提问的人在对话客户端里问「本月 / 昨天」的投放或损益，期望看到一张带平台、国家，或预测版本、业务期间、实际/预测标志的表。国际增长侧一次成功查询经常超过 100 行。财务侧同一个指标组合有 64 次因为还没绑到数据源而失败，用户看到的是报错。财务侧还有 2,062 / 2,560 次查询把指标写成表达式，名字最多的是行数。脚本客户端几乎都成功，对话客户端大约两成失败。

维护质量的人在现有四页上看不到这些差别。

| 页面 | 今天能做的 | 卡住的地方 |
|---|---|---|
| 运行历史里的一次运行 | 看 PASS / FAIL、失败断言、Expected / Actual 的 JSON | 分不清用户拿到了错表、只拿到行数，还是根本没拿到表 |
| 评测用例编辑器 | 在「问题 & 期望」「SQL 断言」「结果断言」里写断言 | 问法是相对时间，答案是一张表；编辑器要求写成死日期和一条标量 |
| 安全评测候选 | 从拒绝日志抽取，审定后收成安全评测用例 | 指标没绑上、分组写错、知识检索失败不会出现在这里 |
| 趋势监控 | 看一条通过率，对照黄线 / 红线 | 通过率把「没答出来」和「答错了」算在一起；也看不见对话侧和脚本侧的差别 |

## 2. 四项能力

### 2.1 运行明细用提问的人的结果来写

打开一次运行，每一行主列回答：这次用户拿到了什么。

| 主列 | 维护的人接着做什么 |
|---|---|
| 答对了 | 不用打开 |
| 答错了 | 展开后看到差在哪一列、粒度有没有变粗、期间 / 版本 / 实际或预测标志有没有对上。轨迹里可以先查行数；用例要的是花费或收入，最后只交出一行行数，这一行是答错了，说明写「没有交到这个指标」 |
| 没答出来 | 展开后看到原因：指标还没绑上、分组写错、语句错误、上游校验没过、知识检索失败。这一行有自己的计数 |
| 拒答成立 / 先澄清再答 | 拒答时能看到点名的缺口，并且最终文本里没有确定数字。该先问清楚的条件出现在第一轮 |

页头的通过率只统计「该给出答案的用例里，答对了多少」，加上拒答成立和澄清后再答对。没答出来的行留在列表里，分子分母都不算它。打开本能力之前的运行，仍显示原来的通过率。

和另一次运行对比时，沿用运行历史里已有的说法：新增失败、已修复。新增失败指这次变成答错了，或该拒答却给了数字。没答出来单独列出，不叫新增失败。

权限拒绝继续只出现在安全评测候选，不进这次运行的业务明细。

### 2.2 评测用例按提问方式和答案表来写

「问题 & 期望」成为主编辑区。

- 问题保持用户的说法，例如「本月各平台花费」「某个业务期间的收入」。运行时选择截止日期。这次运行的页头展示绑定后的窗口。换一天重跑，问题原文不动，窗口变。
- 期望写成用户应看到的表：哪些列必须在、按什么粒度、必须带上哪些条件（日期窗口、平台、国家、预测版本、业务期间、实际或预测标志）。多出来的列仍算答对。缺列、粒度变粗、条件对不上，运行明细写答错了，并指出哪一项。
- 标明这题要回答的业务指标。只交行数时，运行明细按 2.1 写答错了。

SQL 断言和结果断言仍在，给需要看语句的人。主路径不再要求先写一条标量。

### 2.3 反复卡住的提问，可以收成评测用例

质量评测下增加一页，和安全评测候选并列。安全评测候选仍只处理权限与数据隔离。新页处理提问的人反复没拿到表、或反复拿到不合条件的查询。

这一页的一张卡片用业务语言写，例如：「查收入时，这个指标还没绑到数据源，近两天又出现了。」卡片上有角色、最近出现时间、次数，以及用户看到的是报错还是一张表。语义版本放在次行，供维护的人对照当前发布。

操作和安全评测候选同一套：待审定、忽略、收成评测用例。收成之后打开评测用例编辑器，问题草稿按查询形状预填（指标、维度、过滤字段），人改完措辞再保存。过滤值、客户版本字符串、问句原文不自动写入。

抽取规则，维护的人在页面上能看懂失败原因：

- 日志包不完整时，页面说明「这份日志不完整，未抽取」，列表不增加卡片。
- 同一语义版本下，同一种查法跨两天，或同一种失败出现两次，才出现卡片。权限拒绝不出现在这页。
- 一次成功调用没有结果值，不生成「这就是标准答案」的卡片。
- 一次推断问询里调用次数过高时，按查法拆成多张卡片。没有调用的推断问询不出现。

### 2.4 趋势监控把「现场卡住」和通过率分开

趋势监控保留现有的最新通过率、黄线、红线。通过率仍只来自评测运行，口径跟 2.1。

同页增加「现场」区块，只读、按该 domain 绑定的角色过滤：

- 对话客户端和脚本客户端各一行：调用量、报错占比、拒绝占比。
- 报错按人能读的原因计数：指标还没绑上、分组写错、语句错误、知识检索失败。
- 点一条原因，打开 2.3 的列表并带上这个原因。

现场区块不改通过率，不把黄线或红线点亮。脚本客户端大量成功时，对话客户端那一行仍单独显示大约两成的报错。

## 3. 顺序

维护的人要先读得懂一次运行，后面两页才有句子可用。

1. **运行明细**先做。通过率口径随这一页一起变。
2. **评测用例编辑器**和运行明细同一轮。否则从现场收进来的草稿仍只能写成标量。
3. **现场提问页**等运行明细的说法稳定后再开，卡片理由和运行明细用同一组词。
4. **趋势监控的现场区块**可以和运行明细并行；点进现场提问页的链接等第 3 步再接。

10 月 11 日方案里的四臂消融仍是夹具，不进这些页面。8 月 26 日的连续跌破落地后，红线只看 2.1 的通过率。

## 4. 验收

验收按页面操作写。

| 场景 | 操作 | 页面上看到 |
|---|---|---|
| 指标没绑上，没有表 | 打开这次运行 | 该行是「没答出来」，原因是指标还没绑上。页头通过率不含这一行 |
| 表的预测版本或实际/预测标志不对 | 打开这次运行 | 该行是「答错了」，展开写明哪个条件不对 |
| 用例要花费或收入，最后只交行数 | 打开这次运行 | 该行是「答错了」，说明是没有交到这个指标 |
| 数字对，但命中了禁止写法 | 打开这次运行 | 主列仍是答对了；次列标明语句不合规。通过率计这一行 |
| 本功能之前的运行 | 打开运行历史 | 仍是原来的通过率 |
| 问题写「本月」 | 选两个不同的截止日期各跑一次 | 问题原文相同；两次运行页头的窗口不同；列和粒度的期望不变 |
| 上传一份不完整的日志包并抽取 | 打开现场提问页 | 页面说明未抽取，列表不增加 |
| 同一指标没绑上，在同一语义版本出现两次 | 打开现场提问页 | 有一张待审定卡片。安全评测候选里没有它 |
| 权限拒绝 | 打开两页 | 只在安全评测候选 |
| 一次问询里有大量调用 | 打开现场提问页 | 按查法拆成多张卡片 |
| 审定并收成用例 | 从卡片进入编辑器 | 草稿可改；保存前不带过滤值和客户版本字符串 |
| 脚本调用大量成功，对话调用约两成报错 | 打开趋势监控 | 现场区块两行分开。最新通过率和红线不变 |

## 6. 本轮不做

- 不新增、不改写评测题目。
- 不把四臂消融放进运行参数或页面。
- 不用模型判分做发布是否通过的依据。
- 不从成功调用自动生成标准答案。
- 不让现场区块的报错占比触发趋势监控的黄线或红线。
- 不把评测运行做成调用外部 Agent 或大模型。仓库里现有的 Agent 适配器仍只给研发本机；客户页面上的「运行」走上面的编译和重新执行。`noop` 适配器是跳过执行，不代替这条离线运行。
