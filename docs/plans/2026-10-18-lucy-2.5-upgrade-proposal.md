## 0. 这次实际看到的

Cloudflare OS 用新注册的 `lucycheck` 走完引导，进入了首页、Skills、Gatekeepers、连接 MCP Server 的弹窗、Workspaces。

Lucy 容器是 healthy，但停在「创建首个所有者」。当前是客户部署模式，没有配置引导密钥，进不了治理台。Lucy 界面用的是同一套演示环境在 v0.17.0、尚未要求登录时截下的画面：系统概览、连接概览、使用概况、业务 Skill、Agent、角色权限、访问日志、MCP 调试台。概览里的 MCP 地址是 `http://127.0.0.1:57881/mcp`，和现在容器映射的代理端口一致。

以上保留初次对标时的历史观察。v1.11 补充的 L25-11 来自 2026-10-20 另一轮已登录调查：运行页显示 `v2.0.0 / 135b2a8-dirty`，本地读取源码 HEAD 为 `a9eb574b435b813fb18af490d2c03181f5b9d9e9` 且工作区有改动。两者不视为同一构建，镜像身份、关键文件摘要和证据限制见 L25-11 Spec §1；不将本次已登录观察追溯为早期五项展示改造的实机验收。

## 1. 两边的首页各是什么

Cloudflare OS 首页是一句 “What are we working on?”，下面一个对话框，模型处显示 “No agent”。场景卡是做幻灯片、接邮件触发流程、写文档。Workspaces 的推荐起点是 Workspace Docs、Slides、Sheets。Gatekeepers 是一排外部服务卡片，点 MCP Server 会说明：读直接发生，写要等人批准，守门人位于 MCP 服务器和 Gadget 之间。

Lucy 的系统概览是运行状态、待处理事项和 MCP 接入地址，旁边是「复制 MCP 配置」「打开 MCP 调试台」。侧栏是连接、语义、Wiki、Skill、发布、评测、Agent、角色、访问日志。没有提问框。

所以 2.5 不把 Lucy 做成对话框，也不做文档、幻灯片、表格，也不做外部服务目录。Lucy 继续把受治理的 MCP 交给外部 Agent。治理台展示改造见 §2；可选 SMTP 与单点登录另记在 §2.1，不改变登录主键。客户升级 E2E 自动化记在 §2.2，Hive 直连见 §2.4，语义资产批量维护见 §2.5，审计运行时增量另行登记，分别安排。§2 的展示范围不代表整个 v2.5 仅做 WebUI。

## 2. 建议做的 5 项展示改造

前四项都是现有页面上的展示；L25-08 是访问治理组新增的一个独立页面。都不新增运行时能力：权限怎么裁、预算怎么停，沿用已经在跑的引擎。

### L25-01 Agent 和角色页改成能看懂的授权

现在角色权限页是四张计数卡加一张表：`demo_readonly` 写着「3 个 source · 1 个 conn」「10 个工具」。Agent 页是 Token 数和近 7 天调用次数。看完不知道这个 Agent 能读哪几张表。

Gatekeepers 的弹窗值得借的是信息结构，不是服务列表：一句话说明能做什么，一张资源卡，再加一句边界说明。Lucy 的对象是连接、Schema 和表。

Agent 详情和角色编辑增加：

- 一句话。例如：可读 2 个连接、13 张表中的 6 张；行级策略按分公司。
- 资源卡片。连接 → Schema → 表，标出继承自角色还是单独授予。
- 工具按查询、读取语义、读取 Wiki、写入分组。
- 「在 MCP 调试台预览」带上当前 Agent。调试台现在要手选 Agent、模式和 `lucy_query` 的 JSON，预览仍然是单次允许或拒绝。

验收：不打开 YAML，能说出这个 Agent 能读哪些表。摘要和调试台对同一张表的允许或拒绝一致。

### L25-02 访问日志把一笔问询读完

访问日志列表已经有问询时长、关联调用数和「涉数据表」。表名是截断的，例如「dataforai.superstore 等 13 个」。预算用尽没有单独的状态。问询预算引擎已经是 20 次数据工具或 120 秒。

点开一笔问询，展示完整的表清单、轮次、耗时，以及是否「问询预算已用尽」。不新做预算规则。

验收：列表里那笔「等 13 个」的问询，点开后能看到全部表名。人为打满预算的问询，详情里出现用尽状态。

### L25-03 使用概况把已经算出来的数讲清楚

使用概况已经有近 7 天的 Agent、Token、表调用排行。不新增配额拦截，不显示金额。

当前「Token 凭证与活跃」卡片是一条横杠，并写着「活跃 Token 数超过配置数，数据异常」。2.5 把这张卡改成能对上账的数字：配置了几个 Token，其中几个在统计期内有调用。对不上时写明差在哪，而不是只标数据异常。

表排行里的长名字保持可辨认，悬停或展开能看到完整表名。

验收：这张 Token 卡的两个数字能从 Token 页和访问日志对上。排行里被截断的表名能看全。

### L25-04 业务 Skill 增加负责人

业务 Skill 页已经有域、已发布、版本和校验通过，比 Cloudflare OS 那个空的 Skills 搜索框完整。2.5 只加一列负责人，并在配置审计里留下是谁改的。不把这页改成技能市场。

验收：一条已发布 Skill 能指定负责人，配置审计能看到这次修改。

### L25-08 访问关系图

Agent 页和角色页都是列表视角，一维的、逐项的。要回答「这个 Agent 和别的 Agent 共享了哪些表」「哪个角色的授权大面积闲置」「哪张表被访问了但当前没有对应授权路径」，需要一张关系视角的全局图。

访问治理组新增独立页面「访问关系图」，用一张图把 Agent、Token、角色、连接、表放在一起：

- 授权面是骨架。Agent → 角色 → 连接 → 表，边宽表示这条路径上有多少条授权关系，父子之间的数字必须对得上。
- 访问面叠加在同一批边里，内核宽度表示统计窗口内真正发生过的访问条数。内核空着的边是「有权限但没人用」；内核超出骨架的边是需要复核的线索，不是结论。
- Token 不进主干。凭证不携带授权，所以 Token 作为凭证清单挂在 Agent 下面，显示状态和调用次数。按 Token 过滤只影响访问面，授权面不动。
- 图上的数字和 Agent 详情页、角色页必须同源，两处对得上。
- 同时提供表格视图，键盘可达。折叠和降级都要显式说明，不能用空图冒充正常结果。

验收：打开这一页，能说出哪个 Agent 共享了最多的表、哪块授权在闲置、哪张表有访问但没有对应授权路径。同一张表在图上、Agent 详情页和 MCP 调试台三处的允许或拒绝一致。

实现细节见 [`webui/docs/187-access-relation-sankey-spec.md`](../../webui/docs/187-access-relation-sankey-spec.md) v0.2-draft（初稿，待评审）。

## 2.1 另行记入 2.5，尚未写成功能 Spec

2026-10-18 xingchen 确认：可选 SMTP 与单点登录可以作为 2.5 的功能，先记录，不在本建议书里授权实现。当前登录保持账户 id 与密码。找回密码仍是：还有其他所有者时由其重置；全部凭据丢失时按系统手册做 break-glass。自托管默认仍无出网 SMTP。企业安全 Spec（`docs/specs/lucy-20261018-enterprise-security-and-real-e2e-spec.md` §1.1）本期继续不做这两项。

### L25-05 可选 SMTP

客户在自己的网络里提供发信配置。Lucy 不自建邮箱。没配 SMTP 的部署保持现在的行为。

发信只用于客户选中的通知，例如许可证或审计提醒。SMTP 不是登录条件，也不把账户 id 改成邮箱。不提供「忘记密码」邮件。

验收留到功能 Spec：未配置时登录与 break-glass 与现在一致；配置后只有选定的通知会发信，登录页不出现邮箱找回。

### L25-06 单点登录

对接客户已有的身份源（OIDC）。密码和找回留在身份源。Lucy 仍保留本地账户 id，用于创建首个所有者和全部凭据丢失时的 break-glass。所有者与运维的职责不变。多因素认证留在身份源，不在 Lucy 里另做一套。

验收留到功能 Spec：身份源可用时，所有者与运维按身份源登录后的职责与本地账户一致；身份源不可用时，本地账户 id 仍能完成引导和 break-glass。

## 2.2 v2.5 交付工程需求备忘

### L25-07 客户升级 E2E 自动化

**状态：待落地，非门禁。** 2026-10-19 Forrest 确认记入 v2.5 规划，供后续实施。本条不授权立即开发，也不新增当前 PR、CI 或客户发布的前置条件；现有检查继续按原规则执行。未来是否提升为门禁另行决定。

将固定旧版到候选版的升级演练自动化，覆盖 Docker、K3s、K8s 的实际交付形态。复用现有 H3/H4 与 OPS-01 的能力，补齐真实旧版资产、业务行为和安全状态的前后验证。详细范围、16 个场景、核心流程、证据设计与分阶段任务见[客户升级 E2E 实施方案](2026-10-19-upgrade-e2e-implementation-plan.md)，以该方案维护实施细节。

拟实施能力：

- 公共执行器及三种部署形态的适配，固定旧镜像与最终候选镜像身份。
- 兼容性预检、一致性备份、独立恢复验证及版本对应的回滚方法。
- 原账号、有效 Token、权限、Wiki/Skill、查询结果与历史审计的连续性验证；已撤销凭据和会话在恢复后仍不可用。
- 故障注入、中断重试及幂等性检查，记录停机与恢复耗时。
- 独立手动运行入口和脱敏结构化报告，区分失败、环境不足与尚未实现，不直接生成发布放行证据。

**版本分工：v2.0 做交付验证，v2.5 做自动化建设。** v2.0 使用已有脚本配合人工完成客户实际版本的试升级、备份恢复、业务验收和回滚验证，保存结果并提供操作手册。只有验证发现兼容性缺陷时才修改程序，不为本次交付新增升级 E2E 框架。v2.0 验证结果和实际问题可作为 v2.5 自动化用例的输入。

未来完成标准：同一候选镜像在适用部署形态上完成旧版升级及恢复旅程，报告可追溯到实际实例和镜像身份，业务与安全断言均有可复查结果。先按非门禁任务运行；本条不预设其成为任何版本的发布阻断条件。

## 2.3 审计可靠性、准确性与链路追踪运行时契约（L25-09）

**状态：设计基线已冻结（2026-10-20）；未授权代码实现或发布。** 2026-10-20 经审计报告 v1.1 批准，S01–S08 纳入 v2.5，由 Kimi 起草、Codex 审阅，主 Spec 为 [`lucy-20261020-v2p5-audit-increment-spec.md`](../specs/lucy-20261020-v2p5-audit-increment-spec.md) **v1.0-frozen**（target_release=v2.5；U1–U12 最终值已冻结，见主 Spec §15/§17）。本条只登记与 §2 五项展示改造的关系，不重复其内容。

## 2.4 Hive 直连（L25-10）

**状态：纳入 v2.5，方案待评审；先不开发。** 2026-10-20 Forrest 要求按“不改 KTX 源码”的边界设计，重点核查语义编译复用与贯通验证。实施细节以 [Hive 直连实施方案](2026-10-20-hive-direct-connection-implementation-plan.md) v0.1-draft 为准。

- **接入目标**：HiveServer2；Lucy 持有 Hive 配置和 JDBC 执行适配器，不把 Hive 冒充 MySQL/Postgres，不向 KTX 配置写入未知 `driver: hive`。这与 Doris/SelectDB 外部 Hive Catalog 是不同能力。
- **编译复用结论**：已静态核查 `@kaelio/ktx@0.16.0` 随包 Python 接口可接受完整 `sources + query + dialect=hive`，独立返回 SQL/plan；KTX CLI/MCP 的数据库驱动路径没有 Hive。接口可复用不等于 Hive SQL 已验证，时间分组、资产合并、强制行策略及关联聚合是优先验证点。
- **实施顺序**：先固定依赖与客户匹配环境，做编译/JDBC 隔离验证；再贯通“配置→元数据→Manifest/overlay→发现→Lucy Proxy 权限和预算→编译→Hive 执行→审计→返回”；最后完成管理台、失败分支和离线升级交付。
- **与现有范围的关系**：本条新增数据源适配与执行路由，沿用既有 ACL、行策略、问询预算及 L25-09 审计合同，不重做这些引擎，不修改 KTX。§2 五项展示、L25-07 和已冻结 L25-09 的各自状态不变。
- **完成口径**：指定 HS2/认证/传输/依赖组合通过编译、执行、治理和交付验证后才能登记支持；当前 V01–V17 全部未执行。登记仅授权方案保存，不授权代码、验证脚本、镜像构建、真实连接配置、部署或发布。
