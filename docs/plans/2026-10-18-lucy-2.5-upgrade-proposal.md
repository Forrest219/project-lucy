## 0. 这次实际看到的

Cloudflare OS 用新注册的 `lucycheck` 走完引导，进入了首页、Skills、Gatekeepers、连接 MCP Server 的弹窗、Workspaces。

Lucy 容器是 healthy，但停在「创建首个所有者」。当前是客户部署模式，没有配置引导密钥，进不了治理台。Lucy 界面用的是同一套演示环境在 v0.17.0、尚未要求登录时截下的画面：系统概览、连接概览、使用概况、业务 Skill、Agent、角色权限、访问日志、MCP 调试台。概览里的 MCP 地址是 `http://127.0.0.1:57881/mcp`，和现在容器映射的代理端口一致。

以上保留初次对标时的历史观察。v1.11 补充的 L25-11 来自 2026-10-20 另一轮已登录调查：运行页显示 `v2.0.0 / 135b2a8-dirty`，本地读取源码 HEAD 为 `a9eb574b435b813fb18af490d2c03181f5b9d9e9` 且工作区有改动。两者不视为同一构建，镜像身份、关键文件摘要和证据限制见 L25-11 Spec §1；不将本次已登录观察追溯为早期五项展示改造的实机验收。

## 1. 两边的首页各是什么

Cloudflare OS 首页是一句 “What are we working on?”，下面一个对话框，模型处显示 “No agent”。场景卡是做幻灯片、接邮件触发流程、写文档。Workspaces 的推荐起点是 Workspace Docs、Slides、Sheets。Gatekeepers 是一排外部服务卡片，点 MCP Server 会说明：读直接发生，写要等人批准，守门人位于 MCP 服务器和 Gadget 之间。

Lucy 的系统概览是运行状态、待处理事项和 MCP 接入地址，旁边是「复制 MCP 配置」「打开 MCP 调试台」。侧栏是连接、语义、Wiki、Skill、发布、评测、Agent、角色、访问日志。没有提问框。

所以 v0.25 不把 Lucy 做成对话框，也不做文档、幻灯片、表格，也不做外部服务目录。Lucy 继续把受治理的 MCP 交给外部 Agent。治理台展示改造见 §2；可选 SMTP 与单点登录另记在 §2.1，不改变登录主键。客户升级 E2E 自动化记在 §2.2，Hive 直连见 §2.4，语义资产批量维护见 §2.5，审计运行时增量另行登记，升级候选验证环境见 §2.7，行权限管理见 §2.8，分别安排。§2 的展示范围不代表整个 v0.25 仅做 WebUI。

## 2. 建议做的 5 项展示改造

前四项都是现有页面上的展示；L25-08 是访问治理组新增的一个独立页面。都不新增运行时能力：权限怎么裁、预算怎么停，沿用已经在跑的引擎。

### L25-01 Agent 和角色页改成能看懂的授权

**状态：P1-2 设计完成、需求审查已签核通过，暂不开发。** 主 Spec 为 [Agent 与角色授权摘要](../specs/lucy-20261025-v0p25-access-authorization-summary-spec.md)；ASV-01–14 全部未执行。只读复用有效权限与 dry-run，不改变授权或运行时裁决。

现在角色权限页是四张计数卡加一张表：`demo_readonly` 写着「3 个 source · 1 个 conn」「10 个工具」。Agent 页是 Token 数和近 7 天调用次数。看完不知道这个 Agent 能读哪几张表。

Gatekeepers 的弹窗值得借的是信息结构，不是服务列表：一句话说明能做什么，一张资源卡，再加一句边界说明。Lucy 的对象是连接、Schema 和表。

Agent 详情和角色编辑增加：

- 一句话。例如：可读 2 个连接、13 张表中的 6 张；行级策略按分公司。
- 资源卡片。连接 → Schema → 表，标出继承自角色还是单独授予。
- 工具按查询、读取语义、读取 Wiki、写入分组。
- 「在 MCP 调试台预览」带上当前 Agent。调试台现在要手选 Agent、模式和 `lucy_query` 的 JSON，预览仍然是单次允许或拒绝。

验收：不打开 YAML，能说出这个 Agent 能读哪些表。摘要和调试台对同一张表的允许或拒绝一致。

### L25-02 访问日志把一笔问询读完（P0-4）

**状态：与 L25-03 合并为审计只读对账展示 Spec，设计完成、待需求审查，暂不开发。** 主 Spec 为 [审计只读对账展示](../specs/lucy-20261024-v0p25-audit-reconciliation-view-spec.md)，V01–V12 全部未执行。

点开一笔问询，展示完整表身份清单、轮次、调用／尝试、已知耗时，以及是否有真实凭据支持「问询预算已用尽」。统一使用 L25-09 S01／S05 的主状态、计量单位、筛选与 S；不新做预算规则，不把候选归属或未知数据补成确定事实。

### L25-03 使用概况把已经算出来的数讲清楚（P0-4）

**状态：与 L25-02 共用上述 P0-4 Spec，设计完成、待需求审查，暂不开发。** 不新增配额拦截，不显示金额；Token 指 API 访问凭证，不是模型 token 用量。

「Token 凭证与活跃」卡片改为配置 Token 数与窗口内活跃 Token 数，并列出已配置未活跃、活跃但当前配置不可见、停用／删除和身份未核验等差异原因，不再只标「数据异常」。表排行保留完整连接／Schema／表身份；API、UI、CSV 同源同 S，可对账。

### L25-04 业务 Skill 增加负责人

**状态：P2 独立 Spec v0.3-pm-signoff 设计完成、需求审查与 PM 签核均已通过（2026-10-26），暂不开发。** 主 Spec 为 [业务 Skill 负责人](../specs/lucy-20261025-v0p25-skill-owner-spec.md)，SKO-01–16 全部未执行；设计不解除既有交付阻断。

业务 Skill 页已经有域、已发布、版本和校验通过。0.25 只加负责人元数据、总览列、编辑与预检，并在配置审计里留下负责人前后值和实际操作者。负责人是人员或团队的自由文本标签，不是登录账户、所有者角色、授权或通知主体；不把这页改成技能市场。

验收：一条已发布 Skill 能指定、修改或清除负责人，配置审计能看到这次修改；完整口径为 SKO-01–16。

### L25-08 访问关系图

**状态：P1-3 设计完成、需求审查已签核通过，暂不开发。** 主 Spec 为 [访问关系图](../../webui/docs/187-access-relation-sankey-spec.md) v0.3-requirements-review；SC-01–14 全部未执行。

Agent 页和角色页都是列表视角，一维的、逐项的。要回答「这个 Agent 和别的 Agent 共享了哪些表」「哪个角色的授权大面积闲置」「哪张表被访问了但当前没有对应授权路径」，需要一张关系视角的全局图。

规划在访问治理组新增独立页面「访问关系图」，用一张图把 Agent、Token、角色、连接、表放在一起：

- 授权面是骨架。Agent → 角色 → 连接 → 表，边宽表示这条路径上有多少条授权关系，父子之间的数字必须对得上。
- 访问面叠加在同一批边里，内核宽度表示统计窗口内实际发生的去重访问路径数，调用次数另计。内核空着的边是「有权限但没人用」；内核超出骨架的边是需要复核的线索，不是结论。
- Token 不进主干。凭证不携带授权，所以 Token 作为凭证清单挂在 Agent 下面，显示状态和调用次数。按 Token 过滤只影响访问面，授权面不动。
- 图上的数字和 Agent 详情页、角色页必须同源，按表集合并集对账，不能把授权路径数当成去重表数。
- 同时提供表格视图，键盘可达。折叠和降级都要显式说明，不能用空图冒充正常结果；缺调用当时快照时只保留需复核并披露覆盖率。

验收：打开这一页，能说出哪个 Agent 共享了最多的表、哪块授权在闲置、哪张表有访问但没有对应授权路径。同一张表在图上、Agent 详情页和 MCP 调试台三处的允许或拒绝一致。

## 2.1 另行记入 v0.25 的功能（各条 Spec 状态见下）

2026-10-18 xingchen 确认：可选 SMTP 与单点登录可以作为 v0.25 的功能，先记录，不在本建议书里授权实现。当前登录保持账户 id 与密码。找回密码仍是：还有其他所有者时由其重置；全部凭据丢失时按系统手册做 break-glass。自托管默认仍无出网 SMTP。企业安全 Spec §1.1 的非目标只允许由独立 Spec 签核形成有边界例外；L25-06 已于 2026-10-25 完成签核，L25-05 已于 2026-10-26 完成 PM 签核，二者均未授权实现。

### L25-05 可选 SMTP 通知

**状态：P2 可选能力，独立 Spec v0.3-pm-signoff 设计完成、需求审查与 PM 签核均已通过（2026-10-26），暂不开发。** 主 Spec 为 [可选 SMTP 通知](../specs/lucy-20261025-v0p25-smtp-notifications-spec.md)，SMTP-01–26 全部未执行；设计不解除既有交付阻断。

客户在自己的网络里提供发信配置。Lucy 不自建邮箱。没配 SMTP 的部署保持现在的行为。首批只支持审计账本不可用／恢复提醒和所有者发起的测试邮件，不恢复已移除的部署许可，不虚构其他事件来源。

SMTP 不是登录条件，也不把账户 id 改成邮箱。不提供「忘记密码」邮件。通知经持久 outbox 异步发送，排队不等于送达，at-least-once 可能重复；完整口径为 SMTP-01–26。

### L25-06 单点登录

**状态：独立 Spec v0.2-requirements-review 设计完成、需求审查已签核通过，暂不开发。** 主 Spec 为 [OIDC 单点登录](../specs/lucy-20261025-v0p25-oidc-single-sign-on-spec.md)，OIDC-01–26 全部未执行；设计签核不解除既有交付阻断。

对接客户已有的身份源（OIDC）。OIDC 凭据的认证、找回与多因素认证由身份源承担；Lucy 本地密码仍由所有者重置，作为降级与恢复路径，至少保留一名启用中且具有本地密码的所有者。Lucy 保留本地账户 id，用于创建首个所有者和全部凭据丢失时的 break-glass；所有者与运维的职责不变，不在 Lucy 里另做一套 MFA。

功能 Spec 验收矩阵覆盖：身份源可用时，所有者与运维按身份源登录后的职责与本地账户一致，本地密码登录仍可使用；身份源不可用时，本地账户 id 与密码仍能登录，并可完成引导和 break-glass。

## 2.2 v0.25 交付工程需求备忘

### L25-07 客户升级 E2E 自动化

**状态：P1-5 设计完成、需求审查已签核通过，暂不开发，非门禁。** 本条不新增当前 PR、CI 或客户发布的前置条件；现有检查继续按原规则执行。未来是否提升为门禁另行决定。

将固定旧版到候选版的升级演练自动化，覆盖 Docker、K3s、K8s 的实际交付形态。复用现有 H3/H4 与 OPS-01 的能力，补齐真实旧版资产、业务行为和安全状态的前后验证。正式设计见 [客户升级 E2E 自动化 Spec](../specs/lucy-20261025-v0p25-upgrade-e2e-automation-spec.md)，UPG-01–16 全部未执行；[实施方案](2026-10-19-upgrade-e2e-implementation-plan.md)保留上游设计依据。

拟实施能力：

- 公共执行器及三种部署形态的适配，固定旧镜像与最终候选镜像身份。
- 兼容性预检、一致性备份、独立恢复验证及版本对应的回滚方法。
- 原账号、有效 Token、权限、Wiki/Skill、查询结果与历史审计的连续性验证；已撤销凭据和会话在恢复后仍不可用。
- 故障注入、中断重试及幂等性检查，记录停机与恢复耗时。
- 独立手动运行入口和脱敏结构化报告，区分失败、环境不足与尚未实现，不直接生成发布放行证据。

## 2.7 升级候选验证环境（L25-13）

**状态：P1-6 设计完成、需求审查已签核通过，暂不开发，非门禁。** 该路线是**验证通道，不是交付通道**：原地升级仍是客户现场主线，本条不替代它。本条是 L25-07「独立恢复验证」的细化，编号、范围与发布属性随 L25-07。

- **做什么**：用现役实例的**一致性备份**，在隔离环境启动候选镜像，验证迁移正确性、业务连续性与审计连续性，产出脱敏报告。不切流、不承接客户流量、不作为客户部署形态。

- **两条实现硬约束**：① 验证环境必须**以空卷起步、先整卷覆盖再启动**，否则会得到「新模板 + 旧文件」的混合态——容器健康检查会通过，但结构是错的；② 含 `.ktx-ui/security.sqlite` 时备份必须 **quiesced**，热备份可能丢已提交事务并复活已吊销 Token。
- **依赖**：环境构造复用 `intent=install` 入口；实施前按当时代码重新核验失败关闭、安装样例与说明，历史方案的待做状态不当作当前事实。本条不重复实现或放宽该合同。
