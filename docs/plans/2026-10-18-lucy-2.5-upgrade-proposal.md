## 0. 这次实际看到的

Cloudflare OS 用新注册的 `lucycheck` 走完引导，进入了首页、Skills、Gatekeepers、连接 MCP Server 的弹窗、Workspaces。

Lucy 容器是 healthy，但停在「创建首个所有者」。当前是客户部署模式，没有配置引导密钥，进不了治理台。Lucy 界面用的是同一套演示环境在 v0.17.0、尚未要求登录时截下的画面：系统概览、连接概览、使用概况、业务 Skill、Agent、角色权限、访问日志、MCP 调试台。概览里的 MCP 地址是 `http://127.0.0.1:57881/mcp`，和现在容器映射的代理端口一致。

## 1. 两边的首页各是什么

Cloudflare OS 首页是一句 “What are we working on?”，下面一个对话框，模型处显示 “No agent”。场景卡是做幻灯片、接邮件触发流程、写文档。Workspaces 的推荐起点是 Workspace Docs、Slides、Sheets。Gatekeepers 是一排外部服务卡片，点 MCP Server 会说明：读直接发生，写要等人批准，守门人位于 MCP 服务器和 Gadget 之间。

Lucy 的系统概览是运行状态、待处理事项和 MCP 接入地址，旁边是「复制 MCP 配置」「打开 MCP 调试台」。侧栏是连接、语义、Wiki、Skill、发布、评测、Agent、角色、访问日志。没有提问框。

所以 2.5 不把 Lucy 做成对话框，也不做文档、幻灯片、表格，也不做外部服务目录。Lucy 继续把受治理的 MCP 交给外部 Agent。2.5 要补的是治理台上已经有数据、但打开页面还是看不懂的那几处。可选 SMTP 与单点登录另记在 §2.1，不改变登录主键，也不属于这四项展示改造。

## 2. 建议做的 4 项

都是现有页面上的展示。权限怎么裁、预算怎么停，沿用已经在跑的引擎。

### L25-01 Agent 和角色页改成能看懂的授权

现在角色权限页是四张计数卡加一张表：`demo_readonly` 写着「3 个 source · 1 个 conn」「10 个工具」。Agent 页是 Token 数和近 7 天调用次数。看完不知道这个 Agent 能读哪几张表。

Gatekeepers 的弹窗值得借的是信息结构，不是服务列表：一句话说明能做什么，一张资源卡，再加一句边界说明。Lucy 的对象是连接、Schema 和表。

Agent 详情和角色编辑增加：

- 一句话。例如：可读 2 个连接、13 张表中的 6 张；行级策略按分公司。
- 资源卡片。连接 → Schema → 表，标出继承自角色还是单独授予。
- 工具按查询、读取语义、读取 Wiki、写入分组。
- 「在 MCP 调试台预览」带上当前 Agent。调试台现在要手选 Agent、模式和 `lucy_query` 的 JSON，预览仍然是单次允许或拒绝。

验收：不打开 YAML，能说出这个 Agent 能读哪些表。摘要和调试台对同一张表的允许或拒绝一致。

### L25-02 访问日志把一笔问询读完

访问日志列表已经有问询时长、关联调用数和「涉数据表」。表名是截断的，例如「dataforai.superstore 等 13 个」。预算用尽没有单独的状态。问询预算引擎已经是 20 次数据工具或 120 秒。

点开一笔问询，展示完整的表清单、轮次、耗时，以及是否「问询预算已用尽」。不新做预算规则。

验收：列表里那笔「等 13 个」的问询，点开后能看到全部表名。人为打满预算的问询，详情里出现用尽状态。

### L25-03 使用概况把已经算出来的数讲清楚

使用概况已经有近 7 天的 Agent、Token、表调用排行。不新增配额拦截，不显示金额。

当前「Token 凭证与活跃」卡片是一条横杠，并写着「活跃 Token 数超过配置数，数据异常」。2.5 把这张卡改成能对上账的数字：配置了几个 Token，其中几个在统计期内有调用。对不上时写明差在哪，而不是只标数据异常。

表排行里的长名字保持可辨认，悬停或展开能看到完整表名。

验收：这张 Token 卡的两个数字能从 Token 页和访问日志对上。排行里被截断的表名能看全。

### L25-04 业务 Skill 增加负责人

业务 Skill 页已经有域、已发布、版本和校验通过，比 Cloudflare OS 那个空的 Skills 搜索框完整。2.5 只加一列负责人，并在配置审计里留下是谁改的。不把这页改成技能市场。

验收：一条已发布 Skill 能指定负责人，配置审计能看到这次修改。

## 2.1 另行记入 2.5，尚未写成功能 Spec

2026-10-18 xingchen 确认：可选 SMTP 与单点登录可以作为 2.5 的功能，先记录，不在本建议书里授权实现。当前登录保持账户 id 与密码。找回密码仍是：还有其他所有者时由其重置；全部凭据丢失时按系统手册做 break-glass。自托管默认仍无出网 SMTP。企业安全 Spec（`docs/specs/lucy-20261018-enterprise-security-and-real-e2e-spec.md` §1.1）本期继续不做这两项。

### L25-05 可选 SMTP

客户在自己的网络里提供发信配置。Lucy 不自建邮箱。没配 SMTP 的部署保持现在的行为。

发信只用于客户选中的通知，例如许可证或审计提醒。SMTP 不是登录条件，也不把账户 id 改成邮箱。不提供「忘记密码」邮件。

验收留到功能 Spec：未配置时登录与 break-glass 与现在一致；配置后只有选定的通知会发信，登录页不出现邮箱找回。

### L25-06 单点登录

对接客户已有的身份源（OIDC）。密码和找回留在身份源。Lucy 仍保留本地账户 id，用于创建首个所有者和全部凭据丢失时的 break-glass。所有者与运维的职责不变。多因素认证留在身份源，不在 Lucy 里另做一套。

验收留到功能 Spec：身份源可用时，所有者与运维按身份源登录后的职责与本地账户一致；身份源不可用时，本地账户 id 仍能完成引导和 break-glass。

## 3. 看到了、但不放进 2.5

| 真实界面 | 处理 |
|---|---|
| Cloudflare OS 首页对话框和三张场景卡 | Lucy 不负责问。系统概览继续做运行状态、待办和 MCP 地址 |
| Workspace Docs / Slides / Sheets | 另一类产品。Lucy 的交付面仍是语义、Skill 和以后的 Live Report |
| Gatekeepers 里的 GitHub、Slack、Notion、任意 MCP Server | Lucy 自己是数据侧的 MCP，不做成向外连接一切服务的目录 |
| MCP 弹窗里的「写操作等人批准」 | 要改代理的返回。2.5 不动引擎 |
| Skills 页的「+ Add」空库 | Lucy 的 Skill 治理表已经更完整，不照着空库重做 |
| 问数页、模型网关、配额拦截、Live Report | 要么要新引擎，要么要 Lucy 开始负责问 |
| 用邮箱当登录主键，或由 Lucy 发「忘记密码」邮件 | 登录主键仍是账户 id。发信配置见 L25-05，只做可选通知 |

## 4. 限制

- Lucy 治理台这次没能登录。首个所有者还没创建，引导密钥也没配置。上面关于 Lucy 页面的判断来自这套演示环境的 v0.17.0 截图，不是登录后的当场点击。
- Cloudflare OS 的 `admin` 账户密码不在这次会话里。界面是用 `lucycheck` 看的，所以没有看到管理员的模型网关和站点设置。
- 没有在 Cloudflare OS 里配置模型，因此没有重走对话、审批和幻灯片生成。那些仍以 2026-10-18 的实机截图为准。
