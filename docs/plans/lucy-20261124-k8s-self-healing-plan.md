## 目标

K8s 下，声明故障域内的假活在冻结预算内自动恢复；持续故障下集群侧可读、可处置且不宣称自愈；不重现 liveness 误杀。正式验收每一环都有 B 层 K8s 合同台上、同一最终候选镜像的证据，不由 Docker 结果外推；改前基线与 dry-run 只作对照，不能抵扣正式证据。

### 延期熔断：pre-X3 dry-run（OQ-5）

- **触发**：步骤 4 完成后 X3 仍阻塞超 2 个工作日，或步骤 4 完成时 X3 无明确 48 小时内合入 ETA；**由委托人判定触发**，委托人可提前触发。
- **范围判据**：用例触发若必须经过看门狗失败判定，或结论依赖其阈值与时序，则排除。SC-01–07 排除；SC-08／09／10／11 **各拆半纳入**，逐条切分见 Spec §5「OQ-5 dry-run 切分」（SC-08 纳入 `watchdog_started` 启动读写自检与持久化 I/O 语义，排除须真实 STUCK 触发的部分；SC-09 纳入 `delete pod`／`helm rollback` 与观察记录，排除自退出 75 排空；SC-10 纳入 Chart 渲染与负例、双向新旧混合降级核对、`upgrade→rollback→re-upgrade` 编排与 PVC 挂载，只验 Pod Ready，排除单一 digest 闭合与完整 SC-07 oracle；SC-11 纳入注入测程自验，排除 UAT 全真 PASS 终态）。
- **隔离**：临时镜像独立 tag 并记录 digest；`runs/` 文件标 `pre-X3-dryrun`；INDEX 与勾连表不得出现 PASS 或 PASS WITH GAP；**不抵扣**步骤 7 任何一项；需步骤 4 已获开发授权并另获测程授权。
- **汇合**：X3 合入后，步骤 4 须 rebase 并重跑 `stuck-watchdog.test.ts` 与 P1-81 回归，再按步骤 6 构建单一最终 digest 并全量跑步骤 7。
- **代价**：P1-83 为 P0，收口等待 P1-75；dry-run 只能提前排雷，不能提前收口。

## 浏览器验证

不适用：本条不改变用户可见 WebUI 表面，主体是集群侧探针、Chart 与进程恢复取证。测试台中「恢复后管理页展示读与管理写、Live Report 固定 URL」的判定仍按仓库约定使用真实前台浏览器并即时计时，与 API 耗时分列，不得用 `/api/...` 200 代替页面通过；纯 MCP 与 K8s 集群侧部分不强制浏览器。

## 验收

Spec SC-01–SC-11 加测试台 `runs/`。不以 Docker 跑次替代；不以重启后恢复或手工 `kubectl rollout restart` 关单；自愈事件必须有证据；合同台通过不等同客户环境通过。

文档同句；UAT 必做项在 K8s 合同台全真 PASS；缺口按约定登记；**≠ 可上线**；客户出包与现场验收另行授权。
