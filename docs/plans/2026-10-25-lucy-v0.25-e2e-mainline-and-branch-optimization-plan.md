## 1. 实施目标与顺序

按依赖分为六波：

```text
W0 统一编号、事实源和独立覆盖清单；关闭 F-01／F-02
  └─ W1 修复唯一 J25-01 的真实连续主线
       ├─ W2 P0 深度旁线：SEM / ACCESS / OBSERVE / LOG25
       ├─ W3 P1 与 CONN 旁线：RTP / RTV / ASV / ACM / HIVE / CON25
       └─ W4 LIFECYCLE：UPG25 / RVC25 隔离执行与真实环境验证
            └─ W5 文档、selector、impact map 收敛及门禁评审输入
```

W2、W3、W4 可在文件所有权和运行资源隔离明确后并行；任一外部能力未解锁只阻断对应证据维度，不重排或伪造其他项的状态。

**优先交付顺序是 W0 → W1。** W0 可立即启动，但 F-01／F-02 未在 W0 内关闭前不得退出 W0 或进入 W1。先证明最高频真实旅程，再扩深度矩阵，避免继续增加平行主线或仅堆叠接口用例。

## 2. 全局执行纪律

### 2.1 文件与工作区

1. 本仓库可能有其他未提交改动；只修改本波明确拥有的文件，禁止回滚、覆盖或格式化无关文件。
2. 提交时按路径显式暂存，不使用 `git add -A`／`git add -u`；共享文件由主持者统一修改。
3. 临时运行产物、隔离副本、审计输出放 `inbox/`；正式 Spec、Plan、测试 contract 与测试代码按本 Plan 落位。
4. 不读取或打印真实秘密内容；客户私有附件、引导密钥、Token 和数据库密码不进入 Git、构建上下文、公共上传目录或测试产物。
5. 不修改 KTX 源码；连接、编译或方言适配问题优先在 Lucy 代理层、适配层和配置中解决。

### 2.2 浏览器与运行范围

- 本 Plan 明确批准的浏览器范围仅为各波列出的**桌面 Chromium 真实 E2E**；不新增移动窄屏测试。
- 本文评审通过不等于要求立即跑全量。实际执行按波次、环境能力和独立授权推进。
- 本地脚本必须兼容 stock macOS bash 3.2；客户镜像仍是 linux/amd64，必须遵守既有 G1–G4 等硬门禁。
- 不以 Docker Compose 结果替代当前正式 Kubernetes 客户交付证据。

### 2.3 独立清单、状态与报告

独立 v025 manifest 分为 `existingCatalogMappings`、`newScenarios`、`journeys` 三组，不扩展或修改冻结 catalog。既有 255 项只保存原 `executionId`、`ownerBranch` 与跨域引用；其 `executors`、`requires`、`assert`、`artifacts`、`gold` 继续以冻结 catalog 为唯一真源。新增执行项使用同一词汇：

```yaml
executionId: string
sourceSpec: string
sourceRequirementId: string | null
ownerBranch: CONN | SEM | ACCESS | OBSERVE | AGENT | LIFECYCLE
priority: P0 | P1 | branch
executors: string[]
requires: string[]
assert: string[]
artifacts: string[]
gold: string | null
```

schema 读取和校验直接复用 `scripts/e2e/lib/schema.mjs` 的 `validateAgainstSchema()`；不得另造 `requiredEvidence`／`environment` 与 `executors`／`requires` 竞争。J25-01 在 `journeys` 中保存 `stages[]` 和三个 UX-01 catalogEvidenceIds，不拆成八个 executionId。

运行结果与静态清单分离，每个 executionId 分别保存：

```yaml
executionId: string
runId: string
instanceId: string
candidateDigest: string
status: passed | failed | blocked | not_run | not_applicable
blockedReason: environment | delivery | capability | implementation | null
sourceStatus: string | null
executorResults: object
evidenceRefs: string[]
```

禁止把 `blocked`、`not_run`、`not_applicable` 或单一层级通过聚合成完整功能通过。实现完成、验收通过、客户交付通过在报告中始终分列。

### 4.3 主线代表夹具

- 数据库：隔离 PostgreSQL，固定时间窗与可独立计算的指标。
- 管理对象：每 run 唯一的 connection、Role、Agent、Token；不复用其他 run 的可写对象。
- 语义：只维护回答问题所需的最小指标／度量与业务 Wiki；业务 Skill 仅在主问题真实需要时纳入。
- 问题：一个高频首问＋一个自然指代追问；多客户端、空／NULL／0、错误和预算留 AGENT。
- 审计：至少关联本 run、Agent、Token、调用的规范源键和生效版本。

### 4.4 验证层级

1. 静态／单元：selector 与阶段描述完整，无被禁止的 API 写入替代，状态不可跨 run；三类反作弊断言各自有负例。
2. 真实服务：隔离 PostgreSQL、真实 KTX、真实 Lucy、桌面 Chromium、一个已批准真实 Agent。
3. 发布候选：具备 Wave 0b 后，在同一 linux/amd64 单副本候选 digest 上重跑，并进入既有证据链。

建议命令以实际 package script 为准，不在环境不足时强行执行：

```bash
node --test scripts/e2e/__tests__/j01-state.test.mjs
node --test scripts/e2e/__tests__/mainline-scenarios.test.mjs
npm run e2e:real:prepare -- --run-id <run-id> --mode local
npm run e2e:real:management -- --run inbox/e2e/<run-id>/run.json
npm run e2e:real:agent -- --run inbox/e2e/<run-id>/run.json
```

### 4.5 退出标准

- 同一 run 的 J01-01–08 全部有真实证据，首问与追问匹配 typed gold。
- 没有任何关键 UI 写步骤由直接 API 替代，没有由协议调用替代真实 Agent；防泄露、防代答、防换题均独立通过。
- 审计对账能回到本次调用及版本，产物通过完整性和泄漏检查。
- 缺真实能力时保持 `blocked`／`not_run`，不得用 mock 记通过。
- 既有冻结 catalog 兼容检查通过，未改分母。

1. **身份与选择**：V01–V04，覆盖双连接／双 Schema 同名表、跨页选择、30 表往返、依赖闭包。
