## 目标

把 2026-11-05 实跑（RTV25-06）暴露的「按表反查出现孤儿路径、关系图计数与反查路径数不一致」这条**语义层／视图数据完整性**缺口，收敛成一条可验证的功能合同：

1. **清点并归因**：反查有、关系图无的孤儿表逐条清点，每条落到**三选一**归因（残留引用／已删对象／命名漂移）；归因不明走失败关闭。
2. **同快照口径**：反查与关系图读**同一份快照**；不同代就不出数，而不是呈现混代数字。
3. **一致呈现**：孤儿在两处的处置一致（要么都不计入路径数，要么都计入并带标注），且计数不混用。

本条**只治一致性，不治授权、不重建对象**：不新增／删除／改名任何语义层对象，不改 RTV25 合同口径。

## 开工前置

开工前必须全部满足，缺一项即停：

1. **开工授权**：PM 评审通过本 Spec 与本 Plan，并明示授权实现。**未授权前 S0–S6 全部不得开始**——S0 含「登记术语新码」（写 `webui/docs/00-product-terminology-standard.md`）这一真实写操作；取证与术语登记须由 PM 单独明示授权。
2. **实跑证据到位（硬前置）**：**孤儿路径归因的真实证据（实跑产物）不在仓内时，须先取得该证据再开工。** 具体要求：
   - 取得 2026-11-05（或等价的一轮）RTV25-06 实跑产物，含：反查 `GET /api/admin/row-policy/views/tables` 的表集合、关系图 `GET /api/admin/access-map` 的表节点集合、两侧的 `configVersion` / `policyVersion` / `capabilityDigest`。
   - 取得目标实例上 `lucy-ops` 的**运行期**四份事实：Manifest 物理表集合、连接块 `enabled_tables` 集合、source map 命中集合、**身份映射集（`sourceName` ↔ `physicalTable` ↔ `schemaDisplay`）**。⚠️ 第四份是 M3 可判定的前提——`SourceMapEntry` 只有 `physicalTable`／`sourceName`／`schemaDisplay`（`acl.ts:268-279`），**无别名集**；缺它，M3 命中时只能落 `undecidable`，归因能力残缺。
   - **已有证据不得当作缺失**：`inbox/e2e/final-rds-20261105/v025/RTV25-06.json` 的 `executorResults.B.detail` **已含孤儿键清单**（被截断），可作部分起点（Spec U1a）；本前置要求补齐的是**确实未取得**的部分：两侧快照身份（U1b：`configVersion`／`policyVersion`／`capabilityDigest`）与上述四份运行期事实。
   - 若该产物无法取得，**本条不得开工**：Spec 的 U1–U4 处于「未核实」状态，在此状态下实现等于按候选机制（M1–M4）猜口径。须由 PM 决定是「补做一轮实跑取证」还是「推迟本条」。
3. **术语登记**：三个归因码（`stale_reference` / `deleted_object` / `naming_drift`）与 `undecidable` / `orphan` 先登记进 `webui/docs/00-product-terminology-standard.md`。
4. **口径确认**：由实跑产物确认池内「关系图计数与反查路径数不一致」中的「路径数」具体指授权路径数还是访问路径数（Spec U4），并据此锁定 `ORPHAN_PRESENTATION_MODE` 的初值与 D6 的计数断言口径。
5. **冻结边界确认**：确认本条**不改** `webui/docs/187-access-relation-sankey-spec.md` 与 `docs/specs/lucy-20261025-v0p25-row-policy-templates-and-view-spec.md` 的合同字面量，也不改 `docs/specs/lucy-20261104-lucy-ops-manifest-upgrade-heal-spec.md` 的资产自愈合同；如需改动，另行走合同变更流程。
6. **写权限确认**：确认本条只读三份运行期事实，**不写**语义层目录、Manifest、overlay 与连接块（D7）。

## 风险

| 风险 | 说明 | 缓解 |
|---|---|---|
| 无实跑证据即开工 | U1–U4 全为「未核实（证据不在仓）」时，实现会退化为按候选机制猜口径 | 开工前置第 2 条设为硬前置；取证失败即停，由 PM 决定补跑或推迟 |
| 误删仍在用的语义层对象 | 归因若把在用对象误判为「已删对象」，据以清理会打断真实查询 | 本条**不清理**（D7）；SC-07 摘要前后比对；归因只产出诊断不产出动作 |
| 快照口径漂移 | 两侧各读各的快照，混代数字被呈现为一致 | D4 出数前提；SC-03 不同代即不可用 |
| 归因错误导致大面积不可见 | `exclude` 模式下若误判大量表为孤儿，关系图骤然变空，会被读成「授权都没了」 | SC-01 归因唯一性；SC-05 计数不混用；`exclude` 必须同时给出 `orphanReport`（剔除量与归因分布） |
| 口径两处不一致 | 两处各选一套处置模式，孤儿从「可见不一致」变成「不可见不一致」 | D5 单一全局常量；SC-04 两处同构断言 |
| 计数混用被当成修复 | 把「去重表数」改成「授权路径数」能让数字对上，但违反既有明文合同 | D6；SC-05；引用 187 §4.2「同源不等于同数」原文 |
| 归因明度受限于源 map 别名 | 源 map 不保留身份别名时，命名漂移只能交叉推断，精度下降 | RES-04 登记为残余；SC-06 允许证据链更短但不得为空 |
| 与其它批次争同一文件 | 本条可能动 `webui/server/admin/access-map.ts`／`row-policy-views.ts`／`counting.ts` | 开工前对照批次地图确认归属；同一文件同一时刻只允许一个写入方 |

## 回滚

- S1–S3 为响应装配与归因逻辑，回滚＝还原对应提交；本条不写语义层目录、不写连接块、无数据迁移。
- 术语标准登记项在回滚时同步撤回。
- `ORPHAN_PRESENTATION_MODE` 回滚时须回落到「治理前」呈现（即两处各自原样），不得留下半开状态。
- 本条不产生任何生产数据写入，故无数据回滚步骤。
