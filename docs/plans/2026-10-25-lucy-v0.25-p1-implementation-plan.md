### 2.2 跨波次必须一致的三个合同（W0 定义，各波次只读引用）

1. **快照身份**：`{configVersion, policyVersion, sourceMapVersion, capabilityDigest}`。来源：P1-1 §3.3、P1-2 §2.1、P1-3 §6.2 三处字段名与语义必须逐字一致。
2. **计数口径**（F-02 收口）：
   - 表集合＝**规范源键四元组**去重（`sourceCountKey(conn, schema, table)`，既有函数 `webui/server/admin/permission-display.ts:95`）。
   - 授权路径＝`(Agent, Role, Connection, Schema, Table)` **五元组**存在性实例。
   - 访问路径＝窗口内至少一次允许调用的**去重五元组**。
   - 调用数＝独立计数，**跨 Role 汇总可能重复**，不得当全局调用数。

3. **行边界模型**：Agent 用 `FinalRows`；Role 只表示自身 `EffectiveRowGrant`；两者不得互换。

### 2.4 共享工作区并发污染与隔离验证协议

**事实**：本仓库的同一个工作区里同时有**外部 agent 在并行改代码**（Cursor Agent，PID 2942，cwd＝本仓库，已连续运行 4 天），它在 P0-4 审计对账线上留下未完成的改动（2026-10-25 10:05–10:10 连续写入 `audit-export-v2.ts`／`audit-reconciliation-routes.ts`／`reconciliation.ts`／`reconciliation-ports.ts`／`mcp-proxy.ts`，登记了 D-26／D-27）。

由此产生两个必须处理的后果：

1. **`reconciliation-ports.ts` 当前处于语法损坏状态**（9 个 TS1005／TS1359）。TypeScript 遇到语法错误时**不再执行语义检查**，因此共享树里 `npx tsc --noEmit` 只报这 9 条，**把其余既有语义错误全部屏蔽**。共享树上的错误计数在该文件被修好前**没有参考价值**。
2. **HEAD 的真实类型错误基线是 70 条**（在 `9b249f6` 的干净检出上实测）。此前 worker 简报里写的「68 条既有错误」是过期数字，**不得再作为判定基线**。

协议：

| 项 | 规则 |
|---|---|
| 基线来源 | 类型错误基线一律取 **`inbox/p1-verify/`**（`git archive HEAD` 的干净检出，`webui/node_modules` 软链到主仓）。HEAD 基线 = **70**。 |
| 隔离验证 | 验证波次把本波次文件复制进 `inbox/p1-verify/` 后再跑 `tsc`／`vitest`，**不依赖共享树的全局错误计数**。 |
| 判定口径 | 硬判据＝**我方文件在错误列表中不出现**，而不是「错误总数没变」。总数会被外部 agent 改动干扰。 |
| 所有权 | 外部 agent 正在改的 7 个文件（审计对账线 + `mcp-proxy.ts`）**不属于本轮 P1 范围，本轮一律不读改、不修复、不提交**。发现其损坏只记录，不动手。 |
| 提交 | 提交时**按路径显式 `git add`**，禁止 `git add -A`／`git add -u`，避免把外部 agent 的在制品扫进本轮 commit。 |
| 报告 | 测试报告中必须写明「共享工作区存在外部 agent 并发改动，本轮 type-check 与测试在隔离检出上执行」，不得声称共享树干净。 |

### 9.2 运行态模板展开：**与 W1 交接的合同不同，此处为裁决**

W1 的交接建议在 `proxy/identity.ts` `loadConfig()` 与 `proxy/acl.ts` `commitEffectivePolicyUnlocked()` 各加一行 `expandRowPolicyTemplatesInConfig(config).config`。**本轮不采用**，改为在 `proxy/acl.ts` 的 `compileRole()` 内展开选择器（`expandTemplateSelectorsForCompile`），理由是摘要不变式：

- `accessConfigDigest` 是**已提交配置**的摘要，而 `admin/access-config.ts:332` 用它校验回滚是否成功——比对的是**原始文件字节**的摘要。
- 若在配置被摘要之前展开，含模板的配置两侧摘要必然不等 → 一次成功回滚会被判成「回滚未验证」→ `markAccessRecoveryRequired` → **运行态全局降级、数据面拒绝服务**。
- 因此：**配置对象本身不重写**，摘要一律取原始口径；展开只发生在行策略编译器读选择器的那一刻（`acl.ts` 三处 `compileRole` 调用点：运行态编译、per-role 管理面编译、admin 预览链）。
- 展开失败按**具体 issue code** 失败关闭（`row_policy_template_unresolved` 等），绝不退化为「全部行」。
- **不引用模板的选择器逐字节透传**：既有配置的编译行为与失败原因码**完全不变**。为此 `admin/row-policy-templates.ts` 的 `expandRowPolicyTemplatesInConfig` 也改为只处理真正引用模板的选择器。

### 9.3 角色编辑器接入模板引用

- `admin/access-config.ts`：`YamlRowPolicy` 增加 `template?: string`，`predicates` 改为可选（引用模板时可缺省）。
