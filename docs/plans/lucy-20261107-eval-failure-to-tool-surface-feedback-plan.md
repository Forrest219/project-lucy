## 目标

把「Eval 能检出循环单查」与「工具面能因此变好」之间的断点接上，**只接一半是刻意的**：

1. **登记队列**：跑批里被 `budget: max_repeated_tool_input` 判定的循环单查，能被派生出一条可评审的候选条目（原始问句、重复输入指纹、调用次数、涉及工具、脱敏证据引用），进入人工评审队列。
2. **登记判定口径**：什么算「可批量」、什么算「不可判定」（失败关闭）、指纹怎么算、值怎么脱敏——全部写死在 Spec §3，评审时不必重新解释。
3. **明确不自动改工具面**：结论只能四类（升工具／补 skill／改 instructions／不处理），且只产出**待办登记**；真正改工具面是另一条 Spec 的事。

不做：不自动新增工具；不放松白名单 SQL；不让 Agent 临场写任意查询来「绕开」单查；不把队列候选直接写进 `evals/**` 回归集。

## 开工前置

开工前必须全部满足，缺一项即停：

1. **开工授权**：PM 评审通过本 Spec 与本 Plan，并明示授权实现。未授权前 S0 之后的任何步骤都不得开始。
2. **术语登记**：`bulk_candidate` / `undecidable` / `input_fingerprint` 先登记进 `webui/docs/00-product-terminology-standard.md`（新增机器名不先登记就实现，属术语违规）。
3. **基线取证 ＋ 零命中的前置排除**：在本机跑一次 `evals/agent_reliability` 跑批，保存 `.ktx-ui/eval/latest.json` 作为**红基线**，并确认该产物里**至少有一条** `budget: max_repeated_tool_input` 失败。

   ⚠️ **零命中不得直接判为「无循环单查」**——存在一个已知的「永不可能命中」成因：
   - 现行 yaml 断言写的是**短名** `tool: lucy_query`（`evals/agent_reliability/eval/agent-reliability-eval-cases.yaml:152`），
   - 而 runner 的计数键是 `call.name` 的**严格相等**匹配（`scripts/eval/eval-runner.mjs:806` `if (call.name !== tool) continue;`），
   - 跑批记录里的工具名**一律带 `mcp__ktx__` 前缀**（如 `mcp__ktx__sl_read_source`；单测即用全名，`eval-runner.test.mjs:277`）。
   - ⇒ 该断言**当前永不可能命中**，零命中**不构成**「没有循环单查」的证据。
   - 故零命中时**必须先排除工具名不同形**（比对断言里的 `tool` 与产物里的 `call.name` 全名），再判断是否真无循环。
   - 工具名对齐属 REQ-030-019（断言编排面）的合同变更（yaml 改全名），**不在本条顺手改**；本条只负责识别并报出该差异。

   **若排除工具名差异后仍一条都没有**（即 U1 成立：仓内无实跑命中证据），则本条不具备实施前提——须先由 PM 决定是「造一个专用夹具用例」还是「推迟本条」，**不得在实现里凭空造场景**。
4. **脱敏口径确认**：确认候选队列的规范化规则（值只留类型与长度占位、字段名保留）与 `docs/governance/eval-quiz-conventions.md` 及 `evals/agent_reliability` 的合成约定不冲突。
5. **依赖确认**：确认 REQ-030-019（G2，断言编排面）已收口或已排在本条之前——本条依赖「同一 filter 不得重复查」这条断言有人能写、有人能看见（Spec D8）。
6. **冻结边界确认**：确认本条**不改** runner 断言语义、既有失败文案与失败分类词表（Spec D3）；如需改动，另行走合同变更流程。

## 风险

| 风险 | 说明 | 缓解 |
|---|---|---|
| 候选队列变成自动改工具的暗门 | 队列一旦能触发工具面改动，跑批就会静默改变生产行为 | 结论只产出待办登记；SC-10 前后摘要比对；§7 明写「不自动改工具面」 |
| 脱敏泄漏 | 指纹若直接取原始输入而不去明文，或把 `toolCalls` 原样复制，队列会带出业务值 | 规范化逐元素去明文；SC-03 全文扫描；证据引用只到「调用序号 + 指纹」层 |
| 形状塌缩被当成真判定 | 复用失败文案的 `value=` 会把不同 filter 混为一谈 | 指纹重算；SC-04 指纹不等断言 |
| 不可判定被静默吞掉 | 不入队又不报出，会被读成「没有循环单查」 | 失败关闭；SC-05 断言 `undecidable > 0` |
| 无实跑命中证据（U1） | 仓内只有断言用例，没有真实命中产物 | 开工前置第 3 条：无命中即停下由 PM 决定，不得在实现里造场景 |
| 分类词表被改动波及既有合同 | 新增分类值会波及 `failure_classification` 列与允许清单 | 旁路设计，不动词表；SC-08 |
| 阈值过松导致候选泛滥 | 高频重试型用例会大量入队，评审成本上升 | 阈值按实测校准（S4）；条目只带摘要不带全量证据 |
| 与 REQ-030-019 争同一文件 | 两者都可能动 `scripts/eval/eval-runner.mjs` | 开工前对照批次地图确认归属；同一文件同一时刻只允许一个写入方 |
