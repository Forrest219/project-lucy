## 1. 范围与不做

| 做 | 不做 |
|---|---|
| Skill frontmatter 增加可选 `owner` 自由文本字段 | 不建负责人账户、不做账户改派、不做组织目录同步 |
| 总览列、详情字段、编辑字段、预检差异 | 不做负责人筛选、搜索、统计、审批流、技能市场 |
| 配置审计摘要带 owner 前后值 | 不改 `roles_allowed`／Role 工具／MCP 授权矩阵 |
| 损坏 owner 的显式披露与显式修复 | 不因 owner 损坏拒绝 Agent 读取既有 Skill |
| 补齐 Skill 写入在 terminal 失败后的文件回滚 | 不改既有审计库 schema、不新增表 |

## 4. 既有能力复用点（不重造）

| 复用 | 位置 |
|---|---|
| `roles_allowed` 的损坏披露同构模式 | `loader.ts` 的 `parseObjectAcl` → `roles_allowed_invalid`；owner 走 `owner.ts` 的 `parseOwner` → `owner_invalid` |
| 显式修复而非静默清除 | `writer.ts:294` 的 `skill_roles_invalid` 分支；owner 在其旁新增同构分支 |
| CAS 与乐观并发 | `writer.ts` 的 `assertExpectedVersion`（`file_version` SHA-256），owner 不另设版本号 |
| 预检无副作用 | `previewCreateSkillFile`／`previewUpdateSkillFile` 只组装，不写文件／审计／缓存 |
| 配置审计 intent／terminal | `admin/config-audit-write.ts` 的 `auditedWriteFile`；owner 只进 `oldSummary`／`newSummary` |
| 既有回滚缺口 | F-03：Skill writer 缺 terminal 失败后的文件回滚，**S1 必须补齐**（见 §5 风险 R-01） |

## 5. 风险

| 编号 | 风险 | 处置 |
|---|---|---|
| R-01 | committed terminal 失败后文件不回滚，写入与账本不一致 | S1 在 `writer.ts` 补「恢复写入前字节 → 尽力记 `rolled_back` → 恢复失败返回 500 并保留证据」；复用既有配置审计回滚测试模式 |
| R-02 | `owner` 破坏 `file_version` 之外的第二身份假设 | owner 不进 URI、不进身份；`file_version` 仍为整文件 SHA-256，改 owner 必然改版本号 |
| R-03 | 存量 Skill 出现新校验告警被判「校验失败」 | F-10 已钉死 `type:"warning"`，`valid` 不翻转；测试断言 |
| R-04 | 前端展示裸码 | F-11：后端只回码，前端映射表必须登记；测试断言响应体与映射表各一半 |
