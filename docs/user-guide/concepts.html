Concepts

核心概念速览

先理解概念，再相信答案。Lucy 的回答质量来自两件事：先把企业上下文编译成可维护资产，再通过受治理 MCP runtime 让 Agent 安全使用。

关键术语

概念含义用户应该关心什么
Context Compiler把数据库、BI、文档、人工口径整理成 Agent 可用上下文资产的过程。不要让 Agent 直接猜裸库；先维护上下文。
Governed MCP Runtime通过 MCP 暴露受权限、guardrail、审计和 eval 约束的数据工具。Agent 只能使用当前 token/role 可见的工具和数据。
Semantic Packschema、指标、维度、过滤条件、grain 和 join 路径的标准定义。优先要求 Lucy 使用标准口径。
Knowledge PackWiki、Skill、业务解释、owner/caveat 和使用禁区。用它解释“为什么这样算”和“哪里容易错”。
Query Pack可信查询范式、常见问题和后续 BI/dashboard query examples。优先复用可信查询路径，不模仿一次性探索 SQL。
Quality Pack质量评测、安全回归、audit trace 和纠错记录。验证模型会不会按正确方式做，并把错误沉淀为回归资产。
Semantic LayerSemantic Pack 的结构化实现，定义指标、维度、过滤条件和 join 路径。优先要求 Lucy 使用标准口径。
Measure可计算指标，例如 order_count、profit_margin。同名业务指标必须口径一致。
Fallback语义层暂时表达不了的问题，使用受控 raw SQL 补充。必须说明原因、假设和可追溯来源。
质量评测给 Agent 跑的机器评测题，是 Quality Pack 的一部分。验证模型会不会按正确方式做。
Quiz给人做的训练题。验证团队是否理解正确业务口径。
Data Drift底层数据变化导致结果值变化。不要把正常数据漂移误判为模型错误。

最容易误解的三件事

去重计数

订单数不是行数

明细表一笔订单可能有多行，订单数通常需要 COUNT(DISTINCT order_id)。

加权平均

平均折扣不是简单平均

折扣率通常要按销售额加权，避免小额订单扭曲结论。

比率口径

利润率不是逐行平均

标准利润率应使用 SUM(profit) / SUM(sales)。
