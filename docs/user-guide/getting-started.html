Getting started

Lucy 是一个知道“公司标准口径”的数据分析同事。

你可以直接用业务语言提问。Lucy 会优先查企业官方数据标准字典；如果问题超出字典，它必须讲清楚假设、限制和数据基准截止时间，而不是假装自己什么都知道。

会议里最适合问 Lucy 的三类问题

查公司认可的指标

例如销售额、订单数、利润率、客户数。适合在周会、月会、经营会上快速确认“现在到底是多少”。

拆出差异来自哪里

按区域、品类、年份、客户类型拆开看，找出谁在拉高结果、谁在拖后腿、哪里最值得复盘。

解释为什么这样算

当两个人报出的订单数或折扣率不一致时，让 Lucy 说明公司采用的计算方法，避免会议陷入口径争执。

哪些问题要谨慎问

场景原因正确处理
公司还没定义过的指标例如 LTV、复购间隔，如果官方字典没有收录，Lucy 不应临时编一个“标准答案”。要求 Lucy 明说“字典未覆盖”，再给出字典外安全探索的计算假设。
想让它直接改数据Lucy 面向分析和核对，不应该直接修改生产数据。只做只读查询；任何业务数据变更都走人工审批和系统流程。
模糊到无法落地的问题“业务好不好”没有指标、时间范围、对比对象和判断标准。补充你要看的指标、周期、分组，以及你想用这个答案做什么决策。

一个能直接拿去开会的问题

下周经营会上要讨论区域资源倾斜。请按区域和年份比较最近 4 年的销售额、订单数和利润率，指出销售额高但利润率低的区域。请在回答最后，附上你使用的【官方指标名】和【数据基准截止时间】，并诚实告诉我你有没有走字典外安全探索。

这个问题同时交代了会议目的、时间范围、标准业务指标、拆解维度和防御性要求，因此 Lucy 更容易给出能被复核的答案。
