Admin Guide

访问治理：角色、Agent 与 Token

Lucy 的数据面访问由三个对象决定：角色定义可复用的权限边界，Agent 是要对审计负责的接入主体，Token 是某台设备或客户端的接入凭证。三者分开治理，配置入口互不相同。

三个对象，三件事

对象它是什么在哪里配置什么时候动它
角色 可复用的权限边界：一组允许的连接、表范围与工具清单。 /admin/roles 权限边界要复用，或要统一收紧、放开一类使用者时。
Agent 接入主体与审计身份：这次调用是谁发起的。 /admin/agents 新增一个要对审计负责的人或机器人时。
Token 接入凭证：这台设备拿什么连上 Lucy。 /admin/tokens 或 Agent 详情 新设备接入、Token 凭据疑似泄露、需要轮换时。
一人一 Agent、一 MCP；同一 Agent 名下的多个 Token 权限完全相同，多 Token 只负责鉴权，不改变权限。要表达权限差异，请拆 Agent 或改角色，不要用不同 Token 区分。
两个常见误区：每台电脑建一个 Agent（审计碎片化），或每个 Agent 手搓一份权限（改权成本高、边界易漂移）。同一人多设备应当是一个 Agent + 多个 Token；权限差异应当落在角色上。

WebUI 登录账户与 MCP Agent / Token 是两套体系

Lucy 的控制面和数据面各有自己的身份，混用会同时踩到权限和审计两个坑：

维度WebUI 登录账户MCP Agent / Token
管什么 连接、语义资产、发布、评测、访问治理配置 数据面取数与语义资产查询
在哪管 /admin/admins /admin/agents、/admin/tokens
分级方式 只有所有者、运维两级，与数据面角色无关 由角色定义连接、表范围与工具清单
凭据形态 登录口令，配置里只存 scrypt 哈希，没有明文 Bearer Token，配置里只存 sha256 哈希
能否互换 不能。Agent 的 Token 不能登录 WebUI；WebUI 会话也不能当作 MCP 的 Bearer 凭据。
配置文件里的 role: admin 是历史写法，读入时等价于控制面的「运维」登录角色，与数据面的角色无关。数据面没有内置角色，每个角色都要自己显式定义。

治理入口

访问治理分组下的页面各自负责一层对象：

页面路径用途
角色权限/admin/roles管理角色的连接、表范围与工具授权，并预览权限范围。
Agent/admin/agents创建或禁用 Agent，绑定角色，查看该 Agent 名下的 Token 与最近调用。
Token 凭据/admin/tokens全局查看、签发与定向吊销 Agent 的访问凭据。
访问日志/admin/audit按问询记录和调用流水追溯访问行为、裁决原因与执行耗时。
MCP 调试台/admin/mcp-playground受控试调：检查这个 Agent 能不能连上、能不能查某张表。
配置审计/admin/config-audit查看 access.yaml 等配置的写入记录与变更内容。
登录账户/admin/admins管理 WebUI 登录账户（所有者 / 运维）。

配置的事实源是 webui/config/access.yaml，模板见 webui/config/access.yaml.example。页面上做的改动最终都落到这个文件，配置文件本身不入库。

角色配置

roles: 是一个映射（按角色标识取键），不是列表。一个角色的结构如下：

roles:
  kx_readonly:
    description: KX 财务数据只读问答
    allow:
      connections:
        - mysql-aliyun
      tableSelectors:
        - connection: mysql-aliyun
          schema: dataforai
          names:
            - kx_dim_company
            - kx_fact_financial_amount
        - connection: mysql-aliyun
          schema: dataforai
          prefix: kx_
      tools:
        - lucy_catalog
        - lucy_query
        - lucy_read_source
        - lucy_explain_query
        - lucy_freshness
        - lucy_begin_question

users:
  - id: finance_agent
    name: Finance Agent
    enabled: true
    roles:
      - kx_readonly
    tokens:
      - hash: sha256:<hex>
        label: laptop
        created: 2026-07-29
        expires_at: 2026-10-29T00:00:00Z
字段作用约束
allow.connections 这个角色能用哪些连接 连接必须真实存在
allow.tableSelectors 可访问的表范围 每项带 connection 与 schema，再加 names（指定表名）或 prefix（按前缀匹配）二选一；匹配到 0 个语义源会 fail-closed
allow.tools 这个角色能调用的工具清单 必须非空；写通配符会让整个角色解析失败

Agent 侧用 roles: 数组绑定角色（历史写法 role: <角色标识> 等价；两者同时出现会 fail-closed）。多角色的可见范围取并集，行级约束再与 Agent 自身的强制约束求交。

角色标识建议用业务含义（如 kx_readonly），并写清说明。页面上另有「参考模板」，只用于复制后改成正式角色，不要直接当线上权限源；正式角色都写在 access.yaml 里。角色被 Agent 引用时，先改绑定再删角色。

Agent 与 Token 凭据边界

  • 明文只出现一次：Token 明文在签发时返回一次，access.yaml 里只保存 sha256:<hex>。页面上的「复制 MCP 配置」只产出占位符模板。
  • 必须设置过期时间：expires_at 是必填项，管理页默认 90 天、最长 365 天。到期后 Proxy 鉴权硬拒绝 401（裁决原因 token_expired），不是软警告；到期后仍建议在页面显式撤销，避免配置残留。
  • 一设备一 Token：用标签或设备名区分，标签里不要放任何明文；明文不要进仓库、聊天记录、截图或业务 Wiki。
  • 撤销即刻生效：单条撤销在 /admin/tokens 行内操作；人员离职或整体轮换时，先在 Agent 详情撤销全部 Token，再禁用 Agent。
  • 上游内部凭据不出门：KTX_INTERNAL_TOKEN 只用于 Lucy Proxy 调 KTX 上游，不得分发给任何外部 Agent。
接入请求必须携带 Authorization: Bearer <token>。未携带、Token 不匹配、已撤销、已过期，一律返回 401。

离线接入模板与工具面见「MCP 接入参考」。

权限裁决链路

每次工具调用都会重新裁决一遍，链路是：

  1. 把请求里的 Bearer Token 做 sha256。
  2. 在 access.yaml 里匹配 Token 哈希；已撤销的 Token 直接拒绝。
  3. 比对 expires_at：到期或不可解析一律按过期处理。
  4. 解析该 Agent 绑定的角色，得到允许的连接、表范围与工具清单。
  5. tools/list 只返回可见工具；tools/call 再做一次工具、连接、表、原始 SQL、敏感元数据与并发裁决。
  6. 允许、拒绝、错误全部写入审计，并带上裁决原因。
裁决原因含义先查什么
agent_disabledAgent 已被禁用Agent 状态
token_expiredToken 已过期，或过期时间不可解析签发新 Token 并同步客户端配置
tool_forbidden角色没有授权这个工具角色的工具清单
tool_forbidden_global命中全局禁用工具清单defaults.deny_tools
table_forbidden:<表名>请求涉及的表不在授权范围角色的表选择器
raw_query_forbidden查询里传了原始 SQL改用语义查询工具
query_concurrency_exceeded单个 Token 的并发查询超限降低并发，或把批跑任务拆到独立 Agent
role_resolution_failed:<角色标识>角色配置解析失败角色配置本身

全部裁决原因与调用上下文在 /admin/audit 的调用流水里可查；调试台上的中文主行与机器码是同一份判定结果。

行级策略

行级策略是静态的表选择器级配置，挂在角色的表选择器上，用结构化谓词声明「这张表里哪些行对该角色可见」：

配置含义
row_access: all该表全部行可见（默认），不得再带行级谓词
row_access: scoped按谓词限行，至少要有一条谓词
  • 谓词只支持两种操作：等于（eq）与属于（in）。
  • 字段必须是该语义源的普通列或行级维度，禁止绑到度量名上。
  • 多角色的行授予取并集，再与 Agent 强制约束求交，得到最终行约束；保存前可用 dryRun 预览摘要与摘要值。
上游对强制谓词的拼接能力当前默认未证明。在未证明状态下，受行级策略保护的表用 lucy_query 取数会返回 row_policy_upstream_unproven，这是预期的安全拒绝，不是故障；受保护表上的 lucy_read_source、lucy_freshness、entity_details 会被 row_policy_requires_wrapped_tool 拒绝，只允许走已包装的查询路径。排障请用 lucy_explain_query，它在本地执行。

行级策略不是什么：不是动态 RLS、不是多租户隔离、也不是数据库原生行级安全。按人或按 Token 动态变化的策略尚未立项。

审计与留存边界

访问日志有两个粒度：问询记录看一次用户问询的整体链路，调用流水看单次工具调用的取证细节，两者通过问询 ID 关联。导出遵循当前筛选条件。

存储层位置存什么
热库（默认路径） .ktx-ui/audit.sqlite 生成 SQL 明文（仅语义查询的编译结果）、查询哈希、脱敏查询预览
查询原文冷存（可选） .ktx-ui/audit-cold/query-artifacts/ 查询原文加密副本；需要设置 LUCY_AUDIT_QUERY_KEY 才会写入
对象存储冷归档 对象存储 规划中，当前未落地
一个常被误解的点：90 天是 Token expires_at 的默认有效期，不是日志保留期。访问日志没有「默认保留 90 天」这回事。

热库里不写的东西：原始 SQL 攻击载荷、结果行、Token 明文。被拒绝的原始 SQL 也不会写进生成 SQL 列。

上线检查清单

1

连接与启用表范围先就绪

在 ktx.yaml 里配好连接与 enabled_tables（进入语义层的基础范围），并使用真实的只读数据库账号。只读是物理约束，不在权限模型里放开。

2

配置角色

在 /admin/roles 里定义连接、表范围与工具清单。工具要显式列举，不要用通配符。

3

创建 Agent 并绑定角色

在 /admin/agents 新建 Agent，选好角色后先看权限预览再保存。

4

签发 Token

在 Agent 详情签发 Token，设置 expires_at，明文立刻存进客户端凭据库。

5

配置客户端并冒烟

按「MCP 接入参考」配置接入地址与请求头，然后到 /admin/audit 确认这次调用被放行。

扩权后要新开 MCP session：旧 session 不会自动刷新可见范围，客户端会继续看到旧的范围并继续被拒。
