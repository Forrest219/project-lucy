Admin Guide

权限管理与访问控制

Lucy 在表级别控制 Agent 的数据访问范围。每个 Agent 身份只能看到被显式授权的表，未授权的查询在网关层被拒绝，不触达数据库。

访问控制模型

Lucy 的访问控制分为三个层级：

  1. Agent 身份认证 — 每个 Agent 接入需配置身份标识（API Key 或证书），Lucy 据此判断是哪个 Agent 在请求。
  2. 表级 ACL — 为每个 Agent 身份配置可访问的 schema.table 列表，支持通配符（如 dataforai.*）。
  3. 操作只读约束 — 所有 Agent 身份均只有 SELECT 权限，这是物理约束，不可配置放开。

内置角色

角色可访问范围适用对象
viewer被显式授权的表普通业务用户 Agent
analyst被显式授权的表 + 字典外安全探索BI / 分析师 Agent
admin所有表（只读）+ 语义层管理BI 管理员

表级 ACL 配置

表级 ACL 在 KTX WebUI 的「Settings → ACL」中配置。以下是 YAML 格式示例：

agents:
  claude-code-prod:
    role: analyst
    allow_tables:
      - dataforai.superstore_orders
      - dataforai.superstore_returns
      - dataforai.superstore_people
📋 ACL 变更会立即生效，无需重启服务。建议在低峰期操作，并在变更后运行 Eval 验证。

审计日志

Lucy 记录每一次查询请求的完整日志，包含以下字段：

  • timestamp — 请求时间戳
  • agent_id — 发起请求的 Agent 身份
  • tool_name — 调用的 MCP 工具名
  • generated_sql — 实际执行的 SQL
  • execution_time_ms — 执行耗时（毫秒）
  • row_count — 返回行数

日志默认保留 90 天，支持导出。

SSO 与企业身份集成

此功能正在开发中，预计在后续版本支持与企业 SSO（SAML 2.0 / Okta）集成，届时 Agent 可继承用户身份的 ACL 权限。
