连接你的数据源

Lucy 支持主流企业数据库。客户 headless 部署中，数据库连接、表清单、语义层、Wiki 和 Eval 都由 customer-config/ 配置包持续维护。

只读账号设置

强烈建议为 Lucy 创建专用只读账号，不要使用具有写权限的数据库账号。

MySQL

-- 创建只读用户
CREATE USER 'lucy_readonly'@'%' IDENTIFIED BY '<strong-password>';
GRANT SELECT ON your_database.* TO 'lucy_readonly'@'%';
FLUSH PRIVILEGES;

PostgreSQL

-- 创建只读用户
CREATE USER lucy_readonly WITH PASSWORD '<strong-password>';
GRANT CONNECT ON DATABASE your_database TO lucy_readonly;
GRANT USAGE ON SCHEMA public TO lucy_readonly;
GRANT SELECT ON ALL TABLES IN SCHEMA public TO lucy_readonly;
Lucy 物理上只使用只读账号。治理网关会拒绝任何包含 INSERT/UPDATE/DELETE/DROP 的 SQL，即使用户手动构造也会被阻断。

ktx.yaml 配置格式

在 customer-config/ktx.yaml 中配置连接。密码不要写入 YAML 明文，统一使用 file: 引用容器内 secret 文件。

MySQL / StarRocks（P1 gated）

connections:
  customer-db:
    driver: mysql
    readonly: true
    enabled_tables:
      - analytics.ceo_metric_snapshot
    host: db.example.internal
    port: 3306
    database: analytics
    username: lucy_readonly
    password: file:/data/lucy/.ktx/secrets/customer-db-password
    schemas:
      - analytics

PostgreSQL

connections:
  customer-postgres:
    driver: postgres
    readonly: true
    enabled_tables:
      - public.orders
    host: postgres.example.internal
    port: 5432
    database: analytics
    username: lucy_readonly
    password: file:/data/lucy/.ktx/secrets/postgres-password
    schemas:
      - public

表与语义层持续配置

customer-config/semantic-layer/<connection>/_schema/ 保存物理表 manifest，描述表名、字段、类型和基础描述；customer-config/semantic-layer/<connection>/<source>.yaml 保存人工 overlay，维护 grain、measures、segments、joins 和业务解释。

每次新增表、指标、Join 或 Wiki 口径后，运行配置包检查、reindex 和 validate，确保 Agent 能检索到最新语义：

npm run smoke:p0:headless-config -- --root customer-config --require-secret-files
docker compose -f docker-compose.yml -f docker-compose.customer-config.yml exec lucy \
  ktx --project-dir /data/lucy admin reindex --force --output json
docker compose -f docker-compose.yml -f docker-compose.customer-config.yml exec lucy \
  ktx --project-dir /data/lucy sl validate <source-name> --connection-id <connection-id>

常见问题

连接测试失败怎么办？

请检查：1）防火墙是否开放数据库端口；2）只读账号密码是否正确；3）账号是否有 SELECT 权限。

能同时连多个数据库吗？

可以。每个数据库作为独立 connection 配置，语义层文件按 semantic-layer/<connection>/ 目录隔离。
