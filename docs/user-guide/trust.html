Trust

企业数据开放给 Agent 前的可信网关

Lucy 是企业数据开放给 Agent 前的可信网关。智能系统不能只靠“看起来合理”。Lucy 通过语义层、质量评测、业务口径测试、回退来源注脚和漂移状态机，在数据被 Agent 消费之前校验口径、路径、边界与结果。

可信链路

语义层

先用标准指标和 join 路径，减少同名指标多口径。

质量评测

机器测 Agent 是否会按正确 SQL 结构、measure lineage 和结果断言回答。

业务口径测试

人类测业务团队是否理解正确口径，避免只让机器懂。

回退来源注脚

SL 不覆盖时，记录 raw SQL fallback 的原因、假设和 trace。

数据漂移

区分数据变化、schema 变化、逻辑回归和工具错误，避免把正常漂移误判为模型失败。

来源注脚与只读保证

答案可不可信，最终要能被复核。下面三件事是每个数据回答都必须交代的：

  • 来源注脚（Provenance Footer）：每个数据回答末尾附带的标准化元数据块，包含数据来源层级（语义层 / raw SQL）、表名、指标名、数据新鲜度（MAX date_field）和假设说明。会话里最常见的做法，是在问题末尾要求附上【官方指标名】和【数据基准截止时间】。
  • 只读保证：对数据源的所有访问均使用只读账号执行，物理上不可能发生写操作。
  • 审计链路：每次查询的完整留痕，包括查询时间、调用的工具、生成的 SQL、返回结果摘要和执行账号，用于事后审计与合规证明。

组织价值

Skill 固化分析主权

Skill 把资深分析师、财务负责人和业务专家的判断路径固化成 Agent 可重复调用的规程：明确分析目标、输入参数、推理步骤、输出格式，以及它依赖的指标和维度。通用模型给不出的是这些判断本身，而不是把它们写下来的能力。

Runner 构成免疫系统

Runner 不只是 pass/fail 检查，而是把异常分诊为 data_drift、schema_drift、logic_regression 或 tool_error，并判断关联 Quiz 是否 stale。
