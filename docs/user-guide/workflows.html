Workflows

把会议里的追问，改写成 Lucy 能稳定执行的任务。

不要从“功能入口”开始想。先想你要在会议里回答什么争议：数字是多少、差异在哪里、为什么这么算、这个答案能不能放心引用。

四个高频会议片场

1. 老板问：这个数到底是多少？

说清指标名、时间范围和筛选条件，并要求 Lucy 回答使用的官方指标名和数据基准截止时间。

2. 团队争：问题到底出在哪？

指定拆解维度，例如区域、品类、年份、客户类型，让 Lucy 排序并解释差异来源。

3. 两张表对不上：谁的口径对？

询问某个指标为什么这样算，让 Lucy 解释公司官方计算方法，并指出常见误算方式。

4. 字典里没有：还能不能查？

要求 Lucy 明示“官方字典未覆盖”，只在只读范围内做字典外安全探索，并列出计算假设。

可直接复制的任务模板

会议目标推荐问法
快速确认核心数字请统计 2023-2026 年总销售额、订单数和利润率。请在回答最后，附上你使用的【官方指标名】和【数据基准截止时间】，并诚实告诉我你有没有走字典外安全探索。
找出区域差异请按区域拆分利润率，指出最高和最低区域，并判断差异是否可能由销售额规模、折扣或品类结构造成。请在回答最后附上【官方指标名】和【数据基准截止时间】。
定位异常业务请找出累计亏损最严重的子类别，解释它的销售额、折扣率和利润之间的关系，并给出优先复盘顺序。若涉及官方字典外的计算，请明确说明探索假设。
复核口径争议请解释公司口径下“订单数”和“利润率”分别怎么计算，并指出会议里最容易出现的误算方式。最后请列出使用的【官方指标名】。
处理字典未覆盖问题请先判断这个问题是否已被企业官方数据标准字典覆盖。如果没有，请不要伪装成标准答案，只给出字典外安全探索方案、计算假设和不可直接决策的风险提示。

固定加在问题末尾的一句话

请在回答最后，附上你使用的【官方指标名】和【数据基准截止时间】，并诚实告诉我你有没有走字典外安全探索。

这句话的作用是让 Lucy 自动交代答案来源。你不需要懂底层系统，只需要确保每个关键数字都能被复核。
