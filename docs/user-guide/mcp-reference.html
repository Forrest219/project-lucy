MCP 接入参考

Lucy 以 HTTP 暴露 MCP 服务。Agent 必须携带 Bearer Token 才能连上；连上之后能调用哪些工具、能看哪些语义资产，由角色的工具清单和表范围决定。

协议与鉴权

  • 传输：HTTP，消息体是 JSON-RPC 2.0。
  • 鉴权：每个请求都必须带 Authorization: Bearer <token>。
  • 握手：先发 initialize，之后每次请求都要回传 Mcp-Session-Id。只读本地目录的工具不走上游，但取数工具要走上游，握手没做对会表现为「目录能看、查不了数」。
  • 客户端标识（可选，推荐）：带 x-lucy-platform 头，访问日志里能区分是哪个客户端壳发的调用。
请求必须携带有效 Token。未携带、Token 不匹配、已撤销、expires_at 到期，一律返回 401。这条链路没有匿名通道。

Token 的签发、过期与吊销规则见「访问治理：角色、Agent 与 Token」。

接入地址

接入地址分三层。写给 Agent 的地址只有第三层：

层取值说明
Listen LUCY_PROXY_HOST:LUCY_PROXY_PORT（容器内默认 7879） Proxy 进程自己绑的地址，不要写给 Agent
Publish compose 宿主端口映射（LUCY_PROXY_HOST_PORT）或 Ingress 对外暴露的那一层；改了端口要同步改下一层
Advertise LUCY_PUBLIC_MCP_URL（默认 http://127.0.0.1:7879/mcp） WebUI 与 Agent 的唯一事实源，客户端配置里写的就是这个
未配置 LUCY_PUBLIC_MCP_URL 时，WebUI 会显示本地开发 fallback，状态为 fallback，不计 MCP 就绪。此时请先补上对外地址再接入。

客户端配置

Claude Code 与 Codex 使用同一份 .mcp.json，走 HTTP 传输：

{
  "mcpServers": {
    "lucy": {
      "type": "http",
      "url": "<LUCY_PUBLIC_MCP_URL>",
      "headers": {
        "Authorization": "Bearer ${LUCY_AGENT_TOKEN}"
      }
    }
  }
}

通用 HTTP MCP client（Hermes 等）用同一份配置，客户端不支持 type 字段时省略它即可：

{
  "mcpServers": {
    "lucy": {
      "url": "<LUCY_PUBLIC_MCP_URL>",
      "headers": {
        "Authorization": "Bearer ${LUCY_AGENT_TOKEN}"
      }
    }
  }
}

本机 shell 里读取 Token（不要把明文写进仓库）：

export LUCY_AGENT_TOKEN="$(cat <PROJECT_ROOT>/.ktx/secrets/lucy-agent-token)"
页面上的「复制 MCP 配置」按钮只产出占位符模板，永远不会二次粘贴历史明文。生产或客户部署里，把 Token 放在 Agent 平台的 secret store，再通过环境变量或平台变量注入。

可用工具面

新接入的 Agent 推荐只暴露下面 6 个核心工具：

工具用途备注
lucy_catalog 列出当前 Token 可见的连接与语义资产，附安全查询示例 查询前首选
lucy_read_source 读取一个已授权的语义源（grain、字段、度量、关联） Proxy 转发到上游内部工具，Agent 只认这个稳定名
lucy_query 运行已授权的语义查询，取事实数据 禁止原始 SQL
lucy_explain_query 解释同一组参数会如何被授权与限流，不执行查询 排障用，不是常规 dry-run
lucy_freshness 返回语义源的新鲜度元数据 物理数据新鲜度不可用时会显式说明
lucy_begin_question 可选，上报自然语言问题，便于审计关联 可用 LUCY_ENABLE_QUESTION_TOOL=false 关闭
以 sl_ 为前缀的是上游 KTX 内部工具名，对 Agent 一律拒绝，无条件生效、不受角色配置影响。语义查询与语义源读取请走 lucy_query 与 lucy_read_source 这两个稳定包装名。

上下文类工具（wiki_search、wiki_read、lucy_skill_search、lucy_skill_read）只有角色显式列出才可见；元数据类工具（dictionary_search、discover_data）需要完整的敏感表授权才会放行。

lucy_query 参数规范

调用样例：

{
  "connectionId": "poc-mysql-aliyun",
  "measures": ["poc_ad_revenue_daily.ad_revenue"],
  "dimensions": [
    { "field": "poc_ad_revenue_daily.dt", "granularity": "month" }
  ],
  "segments": ["poc_ad_revenue_daily.domestic"],
  "order_by": [
    { "field": "poc_ad_revenue_daily.dt", "direction": "asc" }
  ],
  "limit": 20
}
规则写法原因
字段带来源限定 source.measure、source.field 裁决需要知道请求落在哪张表上
维度与排序用对象数组 [{ "field": "..." }]，不要传字符串数组 Proxy 会校验结构
排序方向字段名 direction，取值 asc / desc 写成别的名字不会被识别
过滤条件 字符串数组，或 { "field": "...", "op": "...", "value": "..." } 结构化对象 结构化对象由 Proxy 转成语义层可执行的过滤表达式
不传原始 SQL 不要出现 query / sql 字段 原始查询默认拒绝，裁决原因 raw_query_forbidden
结果条数 默认 LUCY_QUERY_DEFAULT_LIMIT，上限 LUCY_QUERY_MAX_LIMIT 防止一次拉回过大的结果集
并发 单个 Token 的并发查询上限 LUCY_QUERY_MAX_INFLIGHT 超限返回 query_concurrency_exceeded，这是按 Token 计的用户级限流
orderBy 是兼容别名，Proxy 会统一成 order_by。同一个请求不要同时传两套不同的排序，冲突会 fail closed。

查询顺序

查询顺序不写死在本页，而是由 Proxy 在 initialize 时按当前 Token 的实际权限动态生成并注入给 Agent：只列出这个 Token 可见的连接、语义源和示例。事实源是 webui/config/data-qa-instructions.md，它同时是动态生成失败时的中性 fallback。

  1. 用当前可见的目录工具确认连接和语义源。
  2. 用 lucy_read_source 看 grain、字段和度量。
  3. 用 lucy_query 取事实数据。
  4. 仅在已授权、且确实需要业务口径时使用 wiki_search / wiki_read。
简单事实查询走最短可验证路径：确认目录后直接 lucy_query，拿到事实行就作答。lucy_explain_query 只在查询被拒、或需要排查权限与限流时使用，不作为常规取数的前置步骤。

数据面还有一条硬约束：lucy_query 拿不到事实数据时，不要用 Wiki 上下文编造数值。

排障

现象常见原因处理
401 未带 Token、Token 不匹配、已撤销、已过期 核对客户端配置里的 Token；过期或疑似泄露就在 /admin/tokens 撤销后重发
400，提示必须先完成 initialize 工具调用早于握手，或客户端没有在每条请求回传 Mcp-Session-Id 确认客户端 SDK 的会话管理；先握手再发工具调用
query_concurrency_exceeded 同一 Agent 的并发查询超过配额 降并发、错峰，或把批跑任务拆到独立 Agent
table_forbidden / tool_forbidden 请求超出角色的表范围或工具清单 改角色；改完要新开 MCP session，旧 session 不会刷新可见范围
row_policy_upstream_unproven 表受行级策略保护，而上游强制谓词能力当前未证明 这是预期的安全拒绝，不是故障
目录能查、取数全失败 上游传输会话没被 Proxy 持有 先看 Proxy 日志与上游健康，再回到调试台做最小重现

两个排查入口：/admin/mcp-playground 做受控试调（预览裁决或试一次调用，不给正式 Agent 造凭据），/admin/audit 看访问日志里的裁决原因与调用流水。

凭据边界

  • Token 明文只在签发时出现一次，立刻放进客户端密钥库；配置里只落 sha256:<hex>。
  • 必须设置 expires_at：管理页默认 90 天、最长 365 天。到期后 Proxy 鉴权硬拒绝 401。
  • KTX_INTERNAL_TOKEN 不出门：它只用于 Lucy Proxy 调上游，不得分发给任何外部 Agent。
  • 上游内部工具名不外用：以 sl_ 为前缀的工具对 Agent 一律拒绝，角色配置也放不开。
