MCP 接入参考

Lucy 通过 Model Context Protocol (MCP) 向 Agent 暴露数据能力。以下是当前可用的所有工具及其调用规范。

协议概述

MCP 是 AI Agent 与 Context Server 之间通信的开放标准协议。Lucy 的 MCP Server 作为本地进程运行（或远端端点），Agent 在配置地址处连接。所有工具调用均为 JSON-RPC，通过 stdio 或 HTTP 传输。

Claude Code 的配置示例（.claude/settings.json）：

{
  "mcpServers": {
    "lucy": {
      "command": "ktx",
      "args": ["mcp", "serve"],
      "env": {
        "KTX_PROJECT": "/path/to/your/ktx-project"
      }
    }
  }
}
配置文件路径：Claude Code 使用 .claude/settings.json（项目级）或 ~/.claude/settings.json（全局）。Cursor 使用项目根目录的 cursor.json。

工具一览

工具名用途查询优先级
sl_read读取语义层定义（表描述、字段、Measures、Joins）Step 1（必须先调用）
sl_query使用语义层生成 SQL 并执行Step 2（核心查询工具）
wiki_search检索 Wiki 业务文档Step 2（与 sl_query 并列）
sl_validate验证语义层 YAML 格式合法性Eval 流程专用

工具详细说明

sl_read

返回指定 domain 的语义层结构，包含所有表、字段定义、Measures 和 Join 关系。每次查询前必须调用此工具，获取 canonical 表名和 Measure 定义，禁止直接猜测字段名。

{
  "tool": "sl_read",
  "params": {
    "domain": "dataforai"
  }
}

sl_query

基于语义层生成 SQL 并在只读连接上执行。返回结果集和实际执行的 SQL。禁止绕过此工具手写等价聚合 SQL。

{
  "tool": "sl_query",
  "params": {
    "domain": "dataforai",
    "measures": ["total_sales", "profit_rate"],
    "dimensions": ["region", "order_year"],
    "filters": ["is_deleted = 0"],
    "sort": [{"field": "profit_rate", "order": "ASC"}]
  }
}

wiki_search

全文搜索 wiki/*.md 文档，用于获取业务口径说明、Gotcha 规则和异常处理指引。

{
  "tool": "wiki_search",
  "params": {
    "query": "折扣政策 口径"
  }
}

sl_validate

验证语义层 YAML 文件的合法性，在 Eval 流程中使用。返回校验结果和错误列表。

{
  "tool": "sl_validate",
  "params": {
    "domain": "dataforai",
    "file": "semantic-layer/superstore_orders.yaml"
  }
}

查询优先级（强制）

Step 1  先查语义层（sl_read）
        → 获取 canonical 表名、字段描述、Measures、Joins

Step 2  再查 Wiki（wiki_search）
        → 获取业务口径、Gotcha、路由规则

Step 3  以上均不能覆盖时，才允许 raw SQL fallback
        → 必须标注：「以下基于 raw SQL，假设：…」
禁止跳过 Step 1 直接写 SQL。跳过语义层可能导致字段名错误、Measure 口径不一致或触发 Safety Contract 阻断。

认证与多租户

当前版本 MCP Server 通过本地进程绑定，无需额外认证。多租户身份认证（API Key 模式）正在开发中。
