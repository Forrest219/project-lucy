Lucy Headless 部署五步流程

首版客户交付采用 Docker Compose + customer-config 配置包。完成以下五步后，你的团队就可以通过 Agent 发起受治理的数据问答请求了。

准备工作

开始部署前，请确认以下条件已满足：

条件说明
Docker 环境Docker Engine / Docker Desktop 与 Docker Compose v2 可用
数据库账号目标数据库的只读账号（SELECT 权限，无写权限）
配置包目录基于 customer-config.example/ 创建客户 customer-config/
Agent 接入Claude Code / Codex / Cursor 其中之一已配置好
Git 仓库用于存储语义层 YAML 与 Wiki 配置文件

五步部署流程

1

连接数据源

在 customer-config/ktx.yaml 中配置只读数据库连接，密码使用 file:/data/lucy/.ktx/secrets/<name> 引用。当前 release-verified 路径以 MySQL 与 PostgreSQL 为主；StarRocks 属于 R1 P1 gated support，live certification 通过前不作为已验证数据源。详见「数据源接入」文档。

2

Schema 扫描

将物理表 manifest 放在 customer-config/semantic-layer/<connection>/_schema/。它描述表、字段、类型和描述，是后续 overlay 的基础。

3

完善语义层

在 customer-config/semantic-layer/<connection>/<source>.yaml 中维护 grain、measures、segments、joins 和业务描述；在 customer-config/wiki/ 中维护口径文档。每个 Wiki 文件必须有 title 与 summary frontmatter。

4

运行质量评测

配置完成后运行 npm run smoke:p0:headless-config -- --root customer-config --require-secret-files，再在容器内执行 ktx admin reindex --force、ktx sl validate 和一条只读查询。SOW/UAT 场景还应运行对应 eval/evidence gate。

5

接入 Agent

将 Lucy MCP Proxy 地址 http://<host>:7879/mcp 添加到 Agent 配置，并使用 webui/config/access.yaml 中 token hash 对应的一次性明文 token。不要把 KTX_INTERNAL_TOKEN 发给外部 Agent。

⚠️ 配置上线前必须通过 headless config、reindex、semantic validate 和相关质量评测 gate。修改语义层或 Wiki 后必须重新 reindex。

下一步

完成基础部署后，建议继续完善以下配置：

  • WebUI 使用说明 — 深入学习如何维护语义层、Wiki 和 Join 关系
  • 数据源接入 — 了解各数据库的详细连接配置和只读账号设置
  • 权限与 ACL — 配置 Agent 身份认证与表级访问治理
