AI 数据资产可信网关

企业数据可以安全地
交给 Agent 使用

Lucy 是企业核心数据资产面向 AI Agent 的可信网关与治理海关。它在数据被 Agent 消费之前，统一校验口径、权限边界、查询路径与评测结果，让企业敢于开放数据，而不是被迫在效率和风险之间二选一。

为什么需要 Lucy

企业不敢开放数据给 Agent 的三类根因

没有可信网关，AI 直连数据会把口径幻觉、越权风险和静默漂移一起带进业务决策链。

🎯

口径幻觉

数据库有数百个字段，Agent 难以准确将自然语言问题映射到正确的表和字段。"活跃用户"到底用哪个字段、什么时间窗口？没有语义层，Agent 只能猜。

⏳

静默漂移

Schema、业务定义和底层数据频繁变化。最危险的不是报错，而是"悄悄返回错误答案"——陈旧的指标口径会把隐性计算错误带进管理决策。

🔍

分析主权流失

即使数据标注正确，在巨大的搜索空间里 Agent 仍可能漏掉最相关的实体。没有结构化 Skill 和知识库，Agent 依赖通用模型泛化推理，而不是企业自己的领域判断。

功能模块

全链路 AI 数据资产治理

Lucy 不是单点工具，而是把数据资产安全暴露给 Agent 的治理链路：定义口径、固化知识、控制访问、记录审计、主动评测。

🗄️

多数据源接入

统一 DataSourceAdapter SPI，支持 MySQL 和 StarRocks（MySQL Wire Protocol 只读账号）。跨源 Join 是治理红线，不进入 Agent 自动查询路径。

P1 · StarRocks
📐

语义与知识治理

在 WebUI 中维护字段别名、业务定义、Wiki 文档和 Knowledge Base。所有变更落 KTX git 文件，以 KTX MCP Server 为唯一语义事实源。

已有 · M0–M5
⚡

Skill 管理

Skill 不是提示词技巧，而是企业分析主权的固化机制。它把资深分析师、财务负责人和业务专家长期形成的判断路径、指标解释、异常处理和追问策略，沉淀为 Agent 可重复调用的分析肌肉记忆。

增值服务 · M6
🔐

权限管理

Secrets Cabinet：Lucy 不读取、不展示、不提交 .ktx/secrets/ 中的密码与令牌。Eval Runner 通过 safety_contract 和 forbidden_ast 强阻断凭证路径、写操作和跨源 Join。

P1 · 表级 ACL
📋

访问日志与审计

每次 MCP 调用持久化记录 agent_id、SQL、返回行数、延迟和状态。SQLite 热查最近 180 天，历史数据归档对象存储永久保留。

P1 · 180 天+
📊

Eval 质量监控

Eval Runner 是 AI 数据中台的免疫系统：先编译安全红线，再校验语义、SQL 结构和结果断言，把异常分诊为数据漂移、schema 漂移、逻辑回归或工具错误。

P1 · 自动化门禁
工作流

端到端数据治理链路

从工程师在 WebUI 维护语义，到 Agent 获得高精准度的数据回答，中间经过完整的治理闭环。

① 数据工程师 · 治理控制台

在 Lucy WebUI 维护语义层（字段定义、measures、joins）、Wiki 业务知识、Skill 分析主权资产，配置 Agent 权限和 Token。

② KTX MCP Server · 语义事实源

将语义层、Wiki、Skill 封装为 MCP 工具集（sl_query、wiki_search、list_skills）。所有变更 git 版本化，可随时回溯。

③ Governance Gateway · 鉴权 + 审计

拦截所有 Agent MCP 请求：验证 Service Token → 检查表级 ACL → 通过后转发 → 异步写入审计日志（永久保留）。

④ 数据源层 · MySQL / StarRocks

只读 Service Account 执行受控 SQL。Agent 永远不直连数据库，所有查询经由 Gateway 代理，保证审计完整性。

⑤ AI Agent 消费 · 95%+ 准确率

Claude Code、Codex 等 Agent 通过 MCP 获取语义上下文、Skill 和受控查询接口，回答精准度稳定超过 95%，并附 Provenance Footer 注明数据来源。

产品对比

Lucy vs 传统 BI 工具

Lucy 不是 BI 工具的竞争产品，而是 Agent 时代的新类别——它服务的是 AI，不是人。

维度 传统 BI 工具 Lucy
服务对象 人类分析师 ✓ AI Agent（Claude Code / Codex 等）
输出形式 图表、报表、Dashboard ✓ 语义上下文 + 受控查询接口（MCP）
准确率保障 人工 QA，主观校验 ✓ Eval 自动化门禁，量化准确率趋势
权限管理主体 人类用户 / 角色 ✓ Agent 身份（Service Account + Token）
知识更新方式 手动修改图表和指标 ✓ 语义层 + Skill 版本化，变更自动触发 Eval
审计能力 用户操作日志（可选） ✓ 每次 Agent MCP 调用完整记录，永久保留
多数据源 各自建连接，语义各自维护 ✓ 统一 Adapter SPI，语义层跨源统一管理
边界声明

超出边界，强制阻断

清晰的边界是产品聚焦的保证。以下能力不在 Lucy v1.0 范围内，并由网关、只读账号和 Runner 安全红线共同约束。

超出边界，不实现

✕ 跨数据源 Join（联邦查询）
✕ 列级 / 行级权限（数据脱敏/过滤）
✕ SSO / LDAP / SAML 统一身份
✕ SaaS 多租户部署
✕ BI 可视化（图表 / Dashboard 给人看）
✕ 数据写操作（所有数据源只读）

安全红线进入 docs/eval-quiz-conventions.md 的 safety_contract：一旦生成 SQL 命中 UPDATE / DELETE / INSERT / DROP / ALTER / TRUNCATE 等写操作，Runner 必须判定为 logic_regression 并阻断流水线。
