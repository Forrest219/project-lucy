Data Agent 上下文编译器

企业上下文可以安全地
编译给 Agent 使用

Lucy 是面向中小企业的 data agent context compiler + governed MCP runtime：它本身不直接回答业务问题，而是在数据被 Agent（如 Claude Code / Codex / Hermes / Cursor）消费之前，把数据库、BI、文档、人工口径编译成可授权、可审计、可回归的 MCP 数据服务。

为什么需要 Lucy

企业不敢开放数据给 Agent 的三类根因

没有上下文编译层和受治理运行时，AI 直连数据会把口径幻觉、越权风险和静默漂移一起带进业务决策链。

🎯

口径幻觉

数据库有数百个字段，Agent 难以准确将自然语言问题映射到正确的表和字段。"活跃用户"到底用哪个字段、什么时间窗口？没有语义层，Agent 只能猜。

⏳

静默漂移

Schema、业务定义和底层数据频繁变化。最危险的不是报错，而是"悄悄返回错误答案"——陈旧的指标口径会把隐性计算错误带进管理决策。

🔍

分析主权流失

即使数据标注正确，在巨大的搜索空间里 Agent 仍可能漏掉最相关的实体。没有结构化 Skill 和知识库，Agent 依赖通用模型泛化推理，而不是企业自己的领域判断。

功能模块

从企业上下文到受控 MCP 服务

Lucy 不是单点工具，而是把数据资产、业务知识、可信查询和质量用例编译成 Agent 可安全消费的治理链路：定义口径、固化知识、控制访问、记录审计、主动评测。

🗄️

多数据源接入

统一 DataSourceAdapter SPI，首版支持 MySQL + PostgreSQL（只读账号）。StarRocks 进入 R1 P1 gated support：先支持 MySQL wire 只读目标源配置与证据路径，live certification 通过前不标记 release verified；Oracle 仍为 roadmap candidate。跨源 Join 是治理红线，不进入 Agent 自动查询路径。

P1 · StarRocks gated support
📐

语义与知识治理

在 WebUI 中维护字段别名、业务定义、Wiki 文档和 Knowledge Base，形成 Semantic Pack 与 Knowledge Pack。所有变更落 KTX git 文件，以语义层和业务文档作为可审阅事实源。

已有 · M0–M5
⚡

Skill 管理

Skill 不是提示词技巧，而是企业分析主权的固化机制。它把资深分析师、财务负责人和业务专家长期形成的判断路径、指标解释、异常处理和追问策略，沉淀为 Agent 可重复调用的分析肌肉记忆。

增值服务 · M6
🔐

权限管理

表级 ACL：工具级、connection 级与表级权限已可配置、可验证、可追溯（见 access.yaml）。Secrets Cabinet：Lucy 不读取、不展示、不提交 .ktx/secrets/ 中的密码与令牌；Eval Runner 通过 safety_contract 和 forbidden_ast 强阻断凭证路径、写操作和跨源 Join。

已有 · 表级 ACL
📋

访问日志与审计

每次 MCP 调用持久化记录 agent_id、SQL、返回行数、延迟和状态，写入 SQLite audit 日志，可配置、可验证、可追溯。

已有 · SQLite Audit
📊

Eval 质量监控

Eval Runner 是 Quality Pack 的核心：先编译安全红线，再校验语义、SQL 结构和结果断言，把异常分诊为数据漂移、schema 漂移、逻辑回归或工具错误。

P1 · 自动化门禁

产品对比

Lucy vs 传统 BI 工具

Lucy 不是 BI 工具的竞争产品，而是 Agent 时代的新类别——它服务的是 AI，不是人。

维度 传统 BI 工具 Lucy
服务对象 人类分析师 ✓ AI Agent（Claude Code / Codex 等）
输出形式 图表、报表、Dashboard ✓ 语义上下文 + 受控查询接口（MCP）
准确率保障 人工 QA，主观校验 ✓ Eval 自动化门禁，量化准确率趋势
权限管理主体 人类用户 / 角色 ✓ Agent 身份（Service Account + Token）
知识更新方式 手动修改图表和指标 ✓ 语义层 + Skill 版本化，变更自动触发 Eval
审计能力 用户操作日志（可选） ✓ 每次 Agent MCP 调用完整记录（SQLite Audit，可追溯）
多数据源 各自建连接，语义各自维护 ✓ 统一 Adapter SPI，语义层跨源统一管理
边界声明

超出边界，强制阻断

清晰的边界是产品聚焦的保证。以下能力不在 Lucy v1.0 范围内，并由网关、只读账号和 Runner 安全红线共同约束。

超出边界，不实现

✕ 跨数据源 Join（联邦查询）
✕ 列级 / 行级权限（数据脱敏/过滤，v1.0 不实现，列入长期 Roadmap，非永久排除）
✕ SSO / LDAP / SAML 统一身份
✕ SaaS 多租户部署
✕ BI 可视化（图表 / Dashboard 给人看）
✕ 数据写操作（所有数据源只读）

安全红线进入 docs/eval-quiz-conventions.md 的 safety_contract：一旦生成 SQL 命中 UPDATE / DELETE / INSERT / DROP / ALTER / TRUNCATE 等写操作，Runner 必须判定为 logic_regression 并阻断流水线。
