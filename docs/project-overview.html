分模块功能介绍

1 · KTX Semantic Layer — 语义事实源

定义"什么是对的"。将 MySQL schema 转换为可检索的语义事实，是所有精准率的基础。

Measure公式说明
weighted_discountSUM(discount*sales) / NULLIF(SUM(sales),0)加权折扣率，禁用 AVG
profit_marginSUM(profit) / NULLIF(SUM(sales),0)利润率，禁用 AVG
order_countCOUNT(DISTINCT order_id)订单数，禁用 COUNT(*)
avg_order_valueSUM(sales) / NULLIF(COUNT(DISTINCT order_id),0)客单价
total_sales / total_profitSUM(sales) / SUM(profit)销售额 / 利润总额
customer_countCOUNT(DISTINCT customer_id)去重客户数
total_quantitySUM(quantity)销售总件数
loss_row_countSUM(CASE WHEN profit < 0 THEN 1 ELSE 0 END)亏损明细行数

2 · Skills — 过程控制器

定义"怎样才能稳定用对"。两条加载通道：Claude Code 读 CLAUDE.md，MCP 客户端读 .ktx/prompts/，内容同源。Skills 权威源在 skills/。

Knowledge Skill（通用路由器）
强制三步优先级链，适用所有 domain。新增 domain 只需在 table-routing.md 追加一行，Skill 本身不改。
Domain Reference Docs（按需加载）
不是 Skill，是参考文档。domains/superstore/ 含 domain.md / pitfalls.md / discount-policy.md。未来每个 StarRocks 业务域新增一个目录。
Analysis Skills（跨 domain 复用）
折扣分析程序 / 利润拆解程序。分析方法写一次，superstore 和未来业务域都可复用，只是加载的 domain.md 不同。
Analytics Reviewer Skill
9 项审查清单，财务 / 跨表 JOIN / 领导汇报场景触发。发现错误时停止 → 重写 SQL → 重执行 → 注明修正。

关键 Pitfall（已覆盖）：

#错误写法正确写法数值差异
P1AVG(discount)SUM(discount*sales)/NULLIF(SUM(sales),0)15.54% → 13.98%（差 1.56pp）
P2COUNT(*)COUNT(DISTINCT order_id)10194 → 5009（差 2 倍）
P3AVG(profit/sales)SUM(profit)/NULLIF(SUM(sales),0)权重失真
P4WHERE profit > 0不过滤，亏损行纳入分母高估利润率
P5无 WHERE is_deleted=0所有查询加 is_deleted=0混入历史批次
P6裸表名 ordersdataforai.superstore_orders必须使用 schema 限定名
P7returned = 'Yes'returned = '是'源数据为中文

4 · Eval & Ops — 质量门禁

Eval 不是事后检查，是 Skill / 语义变更的发布前门禁。8 条 Eval Case 锚定在 batch superstore_20260617_120212。

superstore-discount-001
superstore_orders 的整体加权平均折扣率是多少？
forbidden: AVG(discount)
required: SUM(discount * sales) · NULLIF(SUM(sales), 0)
superstore-discount-002
各品类的加权平均折扣率？按折扣从高到低排序。
forbidden: AVG(discount)
required: SUM(discount*sales) · GROUP BY category
superstore-ordercount-001
superstore_orders 共有多少笔订单？
forbidden: COUNT(*)
required: COUNT(DISTINCT order_id) → 5009
superstore-profit-001
superstore_orders 整体利润率是多少？
forbidden: AVG(profit/sales) · WHERE profit > 0
required: SUM(profit) / NULLIF(SUM(sales), 0)
superstore-discount-003 / ordercount-002 / profit / filter
+ 3 条（高折扣利润率 / 分区域订单数 / is_deleted 过滤）
forbidden: AVG · COUNT(*) · 无 is_deleted 过滤
required: 对应正确公式

典型使用方法

A
数据问答（Claude Code）
在 project-lucy/ 目录下启动 Claude Code，CLAUDE.md 自动注入，Skills 生效。
# 启动（CLAUDE.md 自动加载）
cd /Users/forrest/Projects/project-lucy
claude

# 示例问题
Q: superstore_orders 的加权平均折扣率是多少？

# Claude 执行路径：
# 1. CLAUDE.md 注入 → semantic layer first
# 2. ktx sl read superstore_orders → weighted_discount measure
# 3. SQL: SUM(discount*sales) / NULLIF(SUM(sales),0)
# 4. 执行 → 13.98%
# 5. 输出 + Provenance Footer
B
语义层编辑（WebUI）
在浏览器中编辑 measures / segments / wiki，保存前 diff 预览，保存后自动 validate。
cd project-lucy/webui
npm run dev    # Vite 前端 :3000
npm run server # Fastify API :3001

# → 浏览器打开 http://localhost:3000
# → Catalog 查看 superstore_orders 的 9 个 measures
# → TableEditor 编辑 weighted_discount description
# → diff 预览 → validate 通过 → 提交
C
新增 Eval Case（发现新错误后）
追加到 knowledge/superstore/eval/superstore-eval-cases.yaml，用 forbidden_sql_pattern 锁住错误写法。
- id: superstore-new-001
  question: <用户发现的问题>
  forbidden_sql_pattern:
    - "<错误写法片段>"
  required_sql_pattern:
    - "<正确写法片段>"
  expected_result:
    metric: value
  snapshot_date: 2026-06-17
D
扩展新数据域
将新数据库 / 表纳入 KTX，重走 P0→P3 流程。
# 1. ktx.yaml 追加新表
# 2. ktx ingest mysql-aliyun
# 3. 审核 _schema/*.yaml，加 human override
# 4. 创建 per-table overlay（measures / segments / joins）
# 5. 创建 skills/<domain>/ Skill 目录
# 6. 更新 CLAUDE.md 路由规则
# 7. 写 Eval Cases（≥ 5 条）
