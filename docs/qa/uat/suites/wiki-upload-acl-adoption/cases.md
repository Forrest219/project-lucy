## 每例共用执行纪律

1. 先执行 R0；每例、每个矩阵子例用独立 key，或按 [fixtures](fixtures.md) 恢复完整正文／声明后重新读回文件版本。不得把上例的最终状态当作本例前置。角色与通道配置在一次候选中固定。
2. 在操作前记录 key、当前原始 Markdown 的 SHA-256、`allowed_roles` 声明形态与值、文件版本、上传原始体 hash、预期最终声明。前置不满足记夹具失败，禁止继续算 PASS。
3. 创建／恢复夹具单独列为 setup，不能当成上传或管理访问的实测成功。受测写入后通过 API 读回并与容器实际文件对照；拒绝须验证正文、声明与文件版本均未变。
4. 浏览器观察用户动作与按钮状态；API 参数只证明决议输入，不证明发生了用户点击。用例顺序可调整，结果必须不依赖顺序。
5. 任一合法非空写入成功后在该检查点执行 06，不能被下一次覆盖后的一次读取代替；每个检查点记录最终 ACL 与本次正文标记。

## 07 的差异矩阵与 E1–E7 证据

每个 M 子例初始均 `selection=null`、提交禁用、未发 commit；不是只对 M1 做断言。missing 与 empty 均无人可见，但声明规范键不同、应触发选择。

| 子例 | 当前声明 | 上传声明 | 方向／风险 |
|---|---|---|---|
| M1 | B | W | 加宽 |
| M2 | W | B | 收窄 |
| M3 | all | B | all→指定角色 |
| M4 | B | empty | 收窄到显式空 |
| M5 | B | missing | 收窄到未声明 |
| M6 | missing | empty | 同为无人可见但声明不同 |
| M7 | empty | missing | M6 的反向 |
| M8 | B | C | 角色替换；集合等长也必须识别差异 |
| M9 | B | all | 全角色风险确认 |

对每个 M，至少显式采用上传完成该分支（M4–M7 先完成空授权确认，M9 完成全角色确认）；再次独立准备 M1，分别显式保留和 `set=C` 并成功提交。各非空检查点执行 06；空授权按 D8 验拒绝并在 12 验恢复。API 的 01／02／08 成功不能替代这里的真实点击证据。

| 元素编号 | 必须记录的观察 |
|---|---|
| E1 | `/wiki` 可打开覆盖上传预检；独立管理访问入口可识别 |
| E2 | 初始解析与选择后重预检的加载状态可感知；等待期间不可提交 |
| E3 | stale／版本冲突后零写入，重新预检及必要确认后成功；请求失败有浮层内原因，取消重开／重新选文件后成功 |
| E4 | 保留／采用／重设实际成功，落盘与最终摘要一致；管理访问保存后列表 ACL 更新 |
| E5 | M1–M9 初始须选择；上传损坏声明禁采用但保留／重设可达 |
| E6 | 页脚确认一个 primary，取消／重选为次要；提交中防重复 |
| E7 | 现有、上传、最终摘要同时可见；未选时最终明确为待选择，选后与写入对应；missing 与 empty 可区分 |

## 10 的损坏声明矩阵

corrupt 夹具为**语法可解析的 YAML、字段类型非法**（例如 `allowed_roles: 42`），不把整份 frontmatter 语法错误混作本条 corrupt。

| 子例 | 独立前置与操作 | 预期 |
|---|---|---|
| K1 | replace：当前 B、上传 corrupt；尝试 `use_uploaded`，再在另一独立夹具显式保留 | 不可采用，API 为 `CONTEXT_ACL_INVALID` 且零写入；保留可成功，最终 B，正文按上传；06 验合法读 |
| K2 | replace：当前 B、上传 corrupt；显式 `set=C` | 写入 C，与预检一致；06 验合法读 |
| K3 | create：不存在目标、上传 corrupt；无保留动作；直接采用负控，再 `set=C` | 采用拒绝且目标仍不存在；重新设置后创建成功，06 验合法读 |
| K4 | replace：当前 corrupt、上传合法 W；分别独立保留与采用上传 | 保留后仍为原始异常声明，MCP 维持拒绝，不计作修复；采用后为 W，06 验合法读 |
| K5 | replace：当前 corrupt、上传 corrupt；分别独立保留与 `set=C`；另从 corrupt 用管理访问改为 C | 初始仍必须显式选择；保留维持拒绝，重设及管理访问均确有修复并可由 06 读到；corrupt 相同也不得自动放行 |

## 12 的确认与预检恢复子例

| 子例 | 独立操作 | 预期 |
|---|---|---|
| T1 | replace 最终 missing／empty／all 各一组，分别缺确认提交后补确认；确认后改换选择再返回风险值 | 缺确认 `wiki_upload_access_required` 且零写入；补确认后成功；选择变化清空旧确认，不能沿用 |
| T2 | 同一上传快速切换保留→采用→重设，制造预检响应乱序（组件可控延迟；全真 UI 证据用真实网络请求延迟） | 仅最后请求结果可提交，最终值为最后选择；旧响应不能覆盖摘要／解锁；成功后 06。组件结果不冒充全真网络证据 |
| T3 | 取得有效预检后，通过另一真实管理访问请求改变目标，再用旧版本提交；并单独制造一次真实预检网络失败 | 旧提交冲突且相对该次提交前文件零变化；保留原上传体和选择，重预检后确认可成功。网络失败不解锁旧摘要，Dialog 有原因，取消重开重新选择后成功 |
| T4 | 独立建 empty／missing／corrupt 当前页，从 WebUI 管理访问改为 C | 管理访问不依赖 MCP 能读原页；预检＋保存后 ACL＝C，06 验纯 MCP 搜索／读取成功 |

延迟／网络失败均限定 UAT 专用页面与测试客户端，不修改运行代码、不重启共享服务，不向客户环境施压；环境无法实现全真注入时相应子例保留 NOT RUN／GAP，不可由组件结果冒充。

## 06 的检查点

| 写入检查点 | 合法读取身份 | 必须包含的对照 |
|---|---|---|
| 01／07·保留 | B 中角色 | 只在 W 增量中的角色不可见／不可读 |
| 02／07·采用 | 最终声明中角色 | W→B 时 W 增量角色读拒绝、搜索不可见 |
| 05·管理访问 | W 增量角色 | 变更前拒绝，变更后可搜索／读本次正文 |
| 08／07·重设 | C 中角色 | 只在 B／W 且不在 C 的角色拒绝 |
| 09／10／11／12 的非空成功 | 各最终声明中角色 | 读到该子例独立正文标记；对最终 roles 的范围外角色仍拒绝 |
| 空授权或故意保留 corrupt | 无合法读取角色 | 验拒绝／搜索不可见；12·T4 恢复 C 后再验成功 |

all 状态按既有全角色语义验通道有效的 Agent；不制造「所有角色之外」的虚假角色负控。结果只在各检查点实际执行后填写。
