## UAT-PES-R0 — 环境门禁与事件循环臂

### 步骤

1. 冻结基线与最终（或 feature-off／on）`gitSha`、镜像 digest、资源限额；确认 **scale**。
2. 独立探测进程采样：`livez`、`GET /`、`GET /api/branding`、`GET /api/auth/status`（客户端发送时刻起算）。
3. **基线臂**：事件循环臂可用 [fixtures](fixtures.md) 的注入器作机制鉴别；越线后可停，但须 ≥ 3 个越线样本。
4. **最终臂**：事件循环压力来自**生产重工作臂**（Spec §3.1.1：H1 冷槽／并发展示构建＋scale 档审计读／导出），叠加**持续在途的真实 MCP 查询**；**完整持续 ≥ 3 min，不得因任何原因提前停**。
5. 读取事件循环延迟快照，与客户端账本一并留存。

### 期望

- 夹具与臂类型可复核；lean → `BLOCKED`。
- 基线上无任何生产重工作臂能复现越线 → 最终臂「生产重工作臂」判 `BLOCKED`＋差集登记；**不得以注入器通过冒充产品修复**，套件至多 PASS WITH GAP。
- 最终臂事件循环延迟 p99 ≤ 400 ms、max ≤ 800 ms；单个同步片段 ≤ 250 ms。
- MCP 臂只有单条合法查询、或某时刻无在途查询 → `BLOCKED`。

## UAT-PES-01 — 基线臂入口越线

### 步骤

1. 在**基线镜像或 feature-off 臂**上于 R0 窗口导出原始账本／HAR。
2. 核对同窗客户端：入口越线或 0-byte；`livez` 状态分列（同滞或仍绿均如实记录）。

### 期望

- 可复算对照失败；记基线 FAIL，不关缺陷冒充已修。
- 对照臂无法越线 → `BLOCKED`＋评估，不虚报 PASS。

## UAT-PES-02 — 最终臂首页 `primaryReady`

### 步骤

1. 最终臂混压在途。
2. 真实前台浏览器冷开 `/` **≥ 10 次**；记导航→TTFB→`primaryReady`（登录表单或主壳可见可操作；首屏 JS／CSS／Logo 完成）。
3. API／静态资源耗时分列；保留失败样本。

### 期望

- 满足 Spec §3.2／§3.5 判定口径；仅 HTML 可解析 → FAIL。

## UAT-PES-03 — branding／auth status

### 步骤

1. 混压下各 ≥ 60 次探测 branding、auth/status（及 logo）。
2. 双 Session 交错探测 status，确认无串身份。

### 期望

- 预算内完成；无 0-byte；无跨身份 `me`。

---

## UAT-PES-04 — 合法登录必成

### 步骤

1. 混压在途；健康认证存储。
2. 合法管理员凭据 `POST /api/auth/login`，**≥ 10 次**（每次独立 Session）。
3. 用新 Session 读一条受保护只读（如 `/api/auth/status` 含 me，或轻量 admin GET）。

### 期望

- 每次**成功签发**且受保护读成功；耗时在预算内；保留失败样本。
- 503／429／错误码冒充通过 → FAIL。

---

## UAT-PES-04b — 快路径安全负例＋既有认证回归

### 步骤

1. 混压在途，逐项验证并留存请求／响应摘要（脱敏）：
   - 错误密码 → 401，无 `Set-Cookie`，无 Session 行；
   - 跨站请求 → 按既有 CSRF 语义拒绝；
   - 超限 → 429；
   - 吊销／过期 Session → `auth/status` 的 `me` 为空；
   - `auth/status` 响应含 `Cache-Control: no-store`；
   - 注入 Session 存储／审计写入失败 → 不发 Cookie；
   - 非目标受保护 API（`/api/sources`、`/api/admin/*`）未带 Session → 仍被拒；
   - 同一 DRAINING 请求序列下，A／B／C 各路径状态码在基线臂与最终臂**一致**。
2. 运行既有回归（`webui/server/__tests__/`）：`webui-admin-auth.test.ts`、`webui-auth-rate-limit.test.ts`、`webui-session-revocation.test.ts`、`auth-failure-timeline.test.ts`、`process-drain.test.ts`、`branding.test.ts`。
3. OIDC／bootstrap 分支仅在夹具启用时加测，未启用记 SKIPPED 并写明原因。

### 期望

- 全部符合；任一项缺失或不一致 → FAIL。既有回归须全绿。

## UAT-PES-06 — 两臂同窗

### 步骤

1. 同混压窗：合法纯 MCP 问数（独立 SQL 核对）**与**已登录管理只读（正确内容）都尝试。
2. 逐臂判定为：**成功成交**，或 **≤ 10 s 内有界拒绝**（带可读 code 的结构化 4xx／5xx）。

### 期望

- 至少一臂**成功成交**。
- 另一臂出现超时、0-byte、无限挂起或非有界错误 → **FAIL**，无论首臂是否成功。
- 两臂皆仅拒绝 → FAIL。

---

## UAT-PES-06b — 停压重试

### 步骤

1. 06 中任一臂**未成功成交**时执行（已先证明其为有界拒绝）。
2. 停止混压臂；**同 PID** 对该臂有界重试。

### 期望

- 重试成功成交；`docker restart` → FAIL（不计自愈）。
- 06 两臂均成功 → 本用例 SKIPPED（记原因）。

---

## UAT-PES-07 — 运行时无重工作

### 步骤

1. 最终臂混压＋公开入口探测期间读取 Spec 约定的运行时计数／钩子。
2. CR 可附件，不得单独作为通过证据。

### 期望

- 公开快路径触发 MCP 上游发起、全量展示构建、重审计扫描**三类次数均为 0**；**无白名单例外**。

## UAT-PES-08 — 品牌缓存

### 步骤

1. 管理员更新 branding 文案或 Logo；立即未登录读。
2. 删除自定义 Logo／恢复默认；再读。
3. **外部修改**配置文件（绕过管理接口）；修改后**首读**。

### 期望

- 写后首读为新值；删除后无旧 Logo；**外部修改后首读即为新值**；无跨代次缓存。
- 外部修改用例不得跳过；做不到则对应缓存不得启用（Spec §3.4）。

## UAT-PES-09 — 反向洪水（可选；OQ-6 延期）

公开入口并发洪水下，合法 MCP 或管理读须有界失败或成交，不得无限挂死；不得靠关闭公开面换 MCP 绿。本期不挡出口；不得据此宣称双向隔离已验。
