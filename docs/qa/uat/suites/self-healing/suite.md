## 来源与定位

由 2026-11-24 [`f5e4b14d` 压力跑次](../interactive-read-resilience/runs/2026-11-24-codex-f5e4b14d-pressure.md)触发：停压约 134 秒后展示读仍 503、业务问数仍超时，`readyz` 30/30 为 200，仅重启恢复。

与相邻套件分工：

| 套件 | 管什么 | 本套件不重复 |
|---|---|---|
| `UAT-SUITE-INTERACTIVE-READ-RESILIENCE`（P1-75） | 压力下读路径不被打穿 | 本套件只在「已被打穿」之后验恢复 |
| `UAT-SUITE-CORE-AVAILABILITY` | 稳态可用性、FIFO 诊断路径恢复、排空 | 复用其 STD 档作误杀基线，不改其判定 |
| `UAT-SUITE-READYZ-MCP-LISTEN`（P1-46） | 启动窗口 | 本套件在启动后稳态 |

## 全真性

- 假活必须**真实构造**：重放 P1-75 的 T2 混压，或用受控资源压力（CPU 限额加并发读）。禁止用单测桩、打日志或手工改内存状态代替。
- 重启必须由 Docker 监管器或产品自身机制触发。**测试者手工 `docker restart` 不计自愈**，只作对照。
- 判定探针与被测进程分离，探针自身不得影响被测进程的 CPU 和事件循环。
- WebUI 管理页读按仓库约定使用真实前台浏览器，并与 API 耗时分列。纯 MCP 路径不要求浏览器。

## 持续节奏

| 时机 | 跑哪些 |
|---|---|
| 改前基线 | R0、01、02、03。预期 01 FAIL、03 FAIL；02 按实测登记。记录为基线，不是缺陷关单 |
| 含自愈候选 | R0、01–04 全套。同一最终镜像，至少 3 次独立假活构造，全部必做 PASS |
| 改动探针、`readiness`、compose `restart`、健康检查脚本 | 全套 |
| 发布取证前 | 并入出包前定向，与 CAV STD 档同镜像 |

## 阈值（草案，见 Spec OQ-2）

观察窗口 W＝60 秒；同实例恢复 T_A＝120 秒；探针联动重启 T_B＝180 秒（均从假活判定成立起算）。委托人裁定前按此执行，裁定后同步修订。

## 边界

- 只证明本机 Docker 单实例结果，不外推 K8s、多副本或客户拓扑。
- 样本不证明所有故障类型都能自愈；只覆盖已复现的「事件循环或展示快照长期不恢复」型假活。
- 不替代 P1-75 对压力跑次的 FAIL 判定。自愈成功不改写压力下合法问数超时的结论。
- INDEX：**NOT RUN**。
