# MCP 握手与 Agent 名册读取长尾夹具

## 1. 运行条件与档位

- 在本机独立 Docker compose 项目中使用单实例、隔离网络、专用卷和真实 KTX。准备独立 MySQL 或等价真实测试数据源。浏览器使用现有测试管理员，纯 MCP 使用单独测试 Token。来源全部合成，凭据通过已有的本地私密配置注入。
- 冻结改前 `322438a2` 或经核对的等价构建、实际镜像摘要和 KTX 版本。改后对照使用相同夹具、数据、资源、代理配置及观测手段。记录容器 CPU／内存限额、存储类型、缓存和事件循环状态。
- **G1 全局档，R0／01–06。** Lucy 2 CPU／2 GiB，复用[全局规模种子](../../scale-baseline.md)，以 500 Agent、200 正式角色、至少 2,006 张物理表、107 个可解析 Skill、百万条合成历史的[已有跑次](runs/2026-11-23-kscc-global-baseline.md)为下限。保留原 MySQL 两个业务连接、已知 Hive 宽表和真实权限展开。历史 1,403 个可见 Source 是合成 `demo_readonly` 的实际回执。正式 `lucy_admin` 从 G1 的配置与启用清单生成逐连接预期集合，测前冻结并与运行时独立核对。B0 小档只用于校准。
- **G2 同窗档，07。** Lucy 2 CPU／2 GiB，保留全局规模下限和审计、配置的真实开销，按下节重排为八个配置连接的偏斜目录及同账号并发维护场景。候选和基线用相同参数、数据库配额及反代路径。
- **G1 多页面回归，08。** 使用 G1 资源和八连接大 Manifest 交叉对照，按[多页面回归夹具](#多页面回归夹具)准备真实内容与故障控制。
- **冷读历史对照。** 可复跑 [P1-66 BAL-K1](../agent-roster-summary/runs/2026-11-20-codex-p166-docker.md#正式-bal-k1-首轮) 的 2 CPU／4 GiB 冷读反例，按 [P1-66 原档](../agent-roster-summary/fixtures.md) 的规模和门槛单独报告。P1-75 的 SC-04 用 G1，结果保留原档判断。
- **长时组合候选。** 复用[核心可用性正式档](../core-availability/retest.md) 的 1883 张表和 200,000 条起始审计历史，待 P1-13／R-CAV 接纳后按原门槛运行，既有重档失败独立保留。

字节统计以本机夹具的实际文件为准。成对执行冷读取／解析和同代次复用窗口，分别记录实际扫描的文件数、字节数、索引命中和阶段耗时。合成填充只验证字节变化的影响；文件内容结构同现场的差异写入证据。首轮正式功能和性能验收沿用已冻结的全局基准及原预算。

结构宽度诊断可运行 `node scripts/uat/seed-p175-structured-manifests.mjs <新输出目录>`。它在 demo 基础上生成 7 个合成业务连接的 Manifest、对应的真实 MySQL DDL、已启用表清单和独立查询核对值。合计 8 个业务连接、24 份 Manifest、1,443 个 Source，新增约 2.8 万个字段对象，分布在约 6.48 MB YAML 中。预检以数据库表与列数及正式 `lucy_admin` 的实际目录核对规模。用 2 CPU／2 GiB 及 1 CPU／2 GiB 各跑并发握手与页面冷读，分别记录前台响应、握手降级、事件循环和 CPU profile。诊断样本和正式 G1／G2 样本分列。

### 多连接与大 Manifest 交叉对照

| 可扫描连接布局 | 小文件对照 | 大文件分布 |
|---|---|---|
| 2 个合成业务连接 | 2 连接、小文件 | 2 连接、大文件 |
| 8 个合成业务连接 | 8 连接、小文件 | 8 连接、大文件 |

- 四档使用同一组有效合成 Source 和 24 份 Manifest，由只绑定正式 `lucy_admin` 的同一逻辑测试身份读取。2 连接档将同一组 Manifest 重分配到两个连接；8 连接档按已核验数量 `1／5／2／8／5／1／1／1` 布局。同一文件体积档在两种布局间保持文件总数、每份文件字节数和解析后的内容；只随连接归属调整所需的路由与授权绑定。以 `lucy_catalog` 回执和实际扫描范围核对连接数与 Source 数。2／8 是实验设置，现场的 8 是配置数。
- 大文件档取已核验样本的约 6.18 MiB 总量和约 2.24 MiB 单份峰值，8 连接档保留两个较重连接的集中分布。同一连接布局中，两档保持解析后的 YAML 对象一致，先量字节变化。列数、对象数量或结构变化另作单独对照。
- 固定测试身份的权限宽度、可见工具、Skill 集合、Overlay 数量及字节数、查询校验值、资源和并发。Overlay 尚缺现场数据，四档均采用同一套已登记的合成规模。每档记录本机实际文件数、字节数、最大文件与缓存状态。

### 多页面回归夹具

- 固定 G1 的 2 CPU／2 GiB、规模和 [八连接大 Manifest](#多连接与大-manifest-交叉对照)输入。用正常登录得到四个独立 WebUI 会话，另用正式 `lucy_admin` 和受限身份的纯 MCP 会话轮换跑查询。为概览预置可核对的系统状态、待处理事项与 MCP Endpoint，为其余三页分别预置已知 Source、Agent 和角色。提前封存预期内容及权限范围。
- 每轮焦点转给一个被测页，以独立浏览器上下文避免客户端上次成功数据影响本轮断言。预检完成后再准备服务端冷态。正常冷读组记录程内快照为空和当前核验正常，至少能区分 `sources`、`agent-permissions` 和 `role-list`。核验进入过期状态与构建开始、释放、结束均用同一进程可观测事件确认。
- 仅 D 和 P/C 两组分别扣留对应作用域的真实核验，让被测读进入已确认的核验逾期窗口并持续与至少 3 秒的受控慢阶段重叠。构建组只扣留真实 `sources` 冷态构建。局部控制保留真实 Promise、作用域和读路径，不伪造 HTTP 结果。通过发布／写入及代次记录证明窗口内无配置写入，验证无影响作用域的核验仍可正常推进。

## 2. 权限、冷态与故障控制

- 必备一个只绑定正式 `lucy_admin` 的合成 Agent，使用隔离环境签发的测试 Token。走现行内置角色的目录绑定与全局连接解析。按已配置业务连接、Manifest 和 `enabled_tables` 预先计算每连接应见的 Source 集合，并预置至少两个业务连接的已知查询结果。准备已在 Manifest 中登记但未启用的 Source，以及正常就绪的 `lucy-ops` 对照。记录本轮实际生效的角色 ID、连接和目录版本，原始 Token 留在本地私有配置。
- 该身份用于首轮全局规模档及全部四档交叉对照。受限身份用于撤权和授权隔离。前台治理操作用 WebUI 管理会话执行。

- 夹具包含两组授权交叉的问数身份、一个治理身份和一个无相应读取权限的身份。每个合法问数身份至少有一条可用真实查询和一个预设可核对的结果。收窄 A 的一部分权限后，A 仍有合法查询，B 可用范围保持可核对。包含两条连接上的独立目录和一个可经既有发现入口找到的描述或 Skill。
- 区分浏览器新上下文、服务端进程首次构建、代次失效首读、预热后读取和全新 MCP 会话。有效冷样本逐次证明目标槽或索引尚未构建，失效样本用正式保存或发布触发并提供代次变化证据。先完成目录／权限基准核对，再准备冷态和测程，避免预检或预热器替被测首读做掉构建。无冷态证据的样本保留在记录并独立标为缺证。OS 页缓存只记录观测状态。
- 改前诊断每组只改变一项。优先考查握手和 `lucy_catalog` 共用的目录读取及 Skill 文件扫描、授权过滤与上下文 ACL。分别比较代次有效和失效下的路径，并采集进程与文件系统指标，区分子阶段墙钟与实际工作时间。慢上游对照在隔离网络中使用保持真实 KTX 响应语义的可控转发条件，按响应头与响应体分别施加延迟。局部故障与自然负载分开标记。
- 每组配置固定开始条件和结束条件。用本机授予的测试 Token 和常规客户端超时设置，记录主动取消、连接断开及重连。恢复阶段通过解除受控条件或完成真实发布来观察，避免重启掩盖问题。

## 3. 证据字段

记录镜像和配置指纹、时区和单调时钟、样本分母、缓存与代次、相关阶段的开始／结束／状态、首字节与下载／渲染、用户结果、探针和资源指标。为一轮重试维护首次尝试和后续各次的独立回执。Chrome 保持真实桌面前台，默认 `1920×1080`。归档输出脱敏，保存安全关联键与规模汇总。原始客户日志、Token、Cookie、会话标识、业务参数和数据明细留在获授权的原取证环境。
