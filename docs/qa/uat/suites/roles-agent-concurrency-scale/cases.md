# Cases — 角色权限与 Agent 并发及规模

所有规模、时序、资源和预算以 [fixtures](fixtures.md) 为准，本文件不另复制数值。文档v1.0定稿，每个用例写明F58／F59／R选择器、基线／候选、档位、身份模式、样本数与失败。编号前缀UAT-RACS只用于本套件。

默认全文的联合J2／J5、系统采样和长稳态属于R；F58／F59按 [suite 分层矩阵](suite.md#验收分层矩阵) 仅执行指定模块子场景，其真实接口／事务证据可以用于功能SC。不得用F58或F59完成代替R整体PASS，也不得因R未跑阻止已具备全部SC证据的模块单独收口。

## 选择器与证据边界（执行登记）

| 选择器 | 覆盖 | 不算 |
|---|---|---|
| **F58-smoke／F59-smoke** | R0 登录／健康；RACS-01 字段分区切片；RACS-07×25；RACS-08 缓存；RACS-09 成交；RACS-10 同对象冲突一对；可选 RACS-12（需 MCP Token）。**现行口径＝API-only**，判定句须写明，**不得**主张名册页／primaryReady／WebUI 已通过（见 CONVENTIONS「WebUI：浏览器＋计时强制」） | 完整 01–16、2×／5× 造数、前台浏览器 E＋计时、审计历史、R 组合 |

## UAT-RACS-R0 — 身份、环境、基线与夹具有效性（必做）

### 前置

已明确授权后续测试执行，且隔离 Docker fixture、真实数据库、MCP 和登录凭据文件均可用；本轮文档授权不能替代该前置。

### 步骤

1. 记录 gitSha、gitDirty、镜像 digest、单进程／单副本、CPU／内存／卷、宿主与压测器资源；健康响应和制品来源一致。
2. 用真实接口准备同账号独立会话及不同账号会话；按现有限流分批登录，不降级或关闭鉴权，所有 Cookie jar 独立。
3. 校验 B／2×／5× 的实际连接、来源、正式角色、Agent、凭据、当前窗口与全部历史行数；包括分类、偏斜、无历史／旧历史用户，不能只验 seed 参数。
4. 冻结 asOf、fixture seed、oracle 摘要；oracle 从生成数据独立计算，不调用被测统计函数。现有后台投影／维护器真实追平后记录水位。
5. 读取两个实际列表并逐字段验证成功 payload；记录本机“无 WebUI 干扰”的纯 MCP 对照。校准状态和来源按 fixtures §6 填写。

### 期望与清理

前置有效后才能计性能；401／500／空权限结果不得算快速成功；缺实现、凭据、冷缓存证明等按实际标 BLOCKED，不 mock 凑绿。尚未执行时仍是 NOT RUN。保留本次独立 fixture，测试完成统一按 fixtures §7 清理。

## UAT-RACS-01 — 统计与权限结果等价（必做，B／2×／5×）

### 步骤

1. 各数据档分别读取默认完整 Agent API、新名册／统计分区及角色列表；7d／14d／30d 均测。
2. 对全部 Agent、全部统计字段与窗口／最新时间逐项比对独立 oracle；重点检查只在 90 天前使用的用户、同 ts 不同 id、窗口起止边界。
3. 核对协议／评测／默认业务／denied、全局与每 Agent 活跃凭据、到期与碰撞凭据；统计不可用时核对 null 和状态，不能替换成零。
4. 核对角色来源展开和 Agent 权限与同份 fresh 编译结果一致；权限数量相同但具体集合不同也算失败。

### 期望

所有数值、集合与语义一致；无配置用户、无历史用户、无匹配权限均诚实表达。对应 P1-58 SC-02／05／07；每个档独立出结果，不平均。

## UAT-RACS-02 — 窗口外历史增长与最热用户（必做）

### 步骤

1. 固定 B 的 Agent、窗口内行与名册，构建总历史 B／2×／5×；窗口外数据真实增加，最近使用的金样本不变。
2. 在同资源下测完整统计、窗口聚合和最近使用路径，记录 EXPLAIN、实际访问计数或可证明的读量、CPU 与耗时；热冷分开。
3. 单独读取最热用户；再把其最近一条放到窗口外验证“最新使用”不随统计窗口消失。

### 期望

窗口聚合不再遍历全部历史；最新时间单独保持语义。不能只根据出现 SEARCH 字样就判通过：必须给出计划与读量／实耗对应证据；5× 总历史下窗口聚合 p95 不超过 B 的 1.2 倍或增加 50ms（二者取宽），完整列表仍过本档预算。若最近业务时间路径仍随历史失控，记失败并回设计。对应 P1-58 SC-01／02／11。

## UAT-RACS-03 — 数据单维 D2／D5（必做）

### 步骤

1. 固定 B 会话与到达率，数据元组依次 2×／5×，不增加资源。
2. 按 fixtures 的预热、爬升、稳态、回落和三轮要求执行；角色与 Agent 各半，所有统计窗口均包含真实数据。
3. 分默认完整 API、新角色列表、roster、statistics、桌面 primaryReady 出分组报告。

### 期望

逐组满足对应档预算和 100% 正确读取；不能只让首屏返回快而永远不拉统计，也不能靠缓存空结果通过。对应 P1-58 SC-11，组合可用性另记共享 UAT。

## UAT-RACS-04 — 会话单维 C2／C5（必做，同账号／不同账号两轮）

### 步骤

1. 数据与开放式总到达率保持 B，只放大独立会话到 2×／5×，轮转发出同一计划请求。
2. 同账号模式每个 Cookie jar 经独立登录获得，不复制同一 Cookie；另一轮使用不同账号、至少两种已有权限级别。
3. 观察是否误互踢、跨身份结果共享或会话频繁刷新；鉴权不计入重试风暴。

### 期望

合法会话持续可读，按身份裁剪不串数据；共用账号不触发单会话互斥。所有请求仍鉴权，未登录拒绝与正常读取分列。对应 P1-58 SC-03／05、P1-59 SC-11。

## UAT-RACS-05 — 到达率单维 Q2／Q5（必做）

### 步骤

1. 数据与会话固定 B，仅将 Web 读、保存意图、MCP 读的计划到达率放大到 2×／5×。
2. 使用开放式调度，保存旅程执行真实预览与显式提交，单列实际 HTTP 放大率、客户端排队、超时和丢弃。
3. 独立观察发压器饱和；比较只读／读写混合两种子场景，按 fixtures 恢复后重跑。

### 期望

计划发出率有效、每个请求保留结果；服务变慢不能自动降低负载仍记 PASS。读取与保存成交分别过线，预期冲突不能冲抵读取错误。对应两个合同的局部性能与事务检查。

## UAT-RACS-06 — 联合 J2／J5（必做，三轮）

### 步骤

1. 同时放大 fixtures 定义的全部可缩放维度，2×／5× 各三轮，身份两种模式分别执行。
2. 角色／Agent 页面持续打开、筛选、切页、新建弹窗并读取统计；保留桌面 primaryReady 与网络记录。
3. 并发保存与纯 MCP 流量真实执行；独立进程每秒采样 livez／readyz、事件循环、CPU、RSS、WAL、重启、在途数与构建合并数。

### 期望

各路由、窗口、身份组满足 fixtures §5；没有普通窗口 5xx、丢写或无界排队。报告明确这是向量联合倍率，不将每维 5× 写成总体工作量恰好 5×。探针和 MCP 是组合发布观察，不用它们代替模块结果。

## UAT-RACS-07 — 同键构建合并与真实失效（必做，J2／J5）

### 步骤

1. 在独立 fixture 清空展示进程缓存或启用新的配置代次，统一屏障同时发起本档会话数的同键角色读取。
2. 记录实际编译上下文／来源构建次数；再发不同身份裁剪、含模板开关和不同项目键请求。
3. 用真实接口修改启用范围／角色／行模板，另通过专用卷外部文件编辑触发核对；验证旧结果跨代次不回填。
4. 回滚一次失败写入并重读，确认最终展示与正式配置一致；不替换 HTTP 成功响应。

### 期望

同键只构建一次，异键不错误合并；变化与回滚后无旧授权假“有效”。请求失败和取消后在途状态归零。对应 P1-58 SC-03–05。

## UAT-RACS-08 — 统计新鲜度、分区失败与恢复（必做，J2／J5）

### 步骤

1. 打开名册，记录统计时间；通过真实 MCP 产生可识别的新调用，5 秒内与过期后分别读取。
2. 点击立即刷新，核对跳过已完成缓存，返回新观察水位与正确窗口；进行一次配置写入，确认旧版本统计不拼接新名册。
3. 通过隔离副本的真实文件权限／连接故障让审计读取失败，名册配置和权限路径保持可读；确认统计不可用而名册可搜索、进详情。
4. 恢复审计读取，点击重试；验证筛选、指标与名册重新一致，不重启整容器来冒充正常恢复。
5. 在独立慢查询样本中真实让统计读取耗时处于5–10秒之间；正确结果仍返回最初请求、显示真实统计时间且不进缓存，不能TTL到期后反复重算。此样本只验TTL逃生，不能混入正常性能组替代既有延迟预算。

### 期望

不把旧 asOf 改成当前时间；失败不造零；错误区有重试；合法治理任务能继续。若当前实现无法独立构造审计失败，写 BLOCKED，不用网络 mock 代替。对应 P1-58 SC-06–09；覆盖读取 Spec E1–E18，正式浏览器证据独立引用。

## UAT-RACS-09 — 无关对象并发保存与成交（必做，J2／J5）

### 步骤

1. 多会话读同一整份文件基线；成对修改不同 Role、不同 Agent、无引用关系的 Role 与 Agent，各至少 100 对。
2. 先分别提交，后用屏障同时提交；命中真实发布占用时保留草稿，用户显式重试，重新校验后提交，不自动重放。
3. 按 operationId、配置最终值、绑定 after、运行时确认和审计终态核对每个意图；角色和 Agent 的无关字段均保留。
4. 交错同账号与不同账号，记录真实完成延迟及未完成意图，不只统计成功返回。

### 期望

无关对象不因旧全文件版本制造假目标冲突；发布占用可恢复，最终无覆盖丢失。成交率与时间达到 fixtures §5，吞吐只数真实 committed。对应 P1-59 SC-01／06／10–12。

## UAT-RACS-10 — 同对象冲突、删除与草稿恢复（必做，J2／J5）

### 步骤

1. 多客户端读同一 Role／Agent，修改同一授权字段后并发提交，各至少 100 对。
2. 成功者保持；冲突者查看基线／我的修改／当前值，刷新当前值，验证草稿不丢，再重新预览、显式确认后提交。
3. 加入目标先被删除、同 ID 创建、源角色复制、角色被引用后删除等时序；旧草稿不能复活已删对象。
4. 验证没有强制覆盖入口，未知字段、有序行策略与 legacy version 均正确处理。

### 期望

同对象一成功一明确冲突，草稿可恢复并最终完成合法修改；不存在静默字段合并／覆盖／ID 复活。热点意图成交达到 fixtures §5，不以全部拒绝当作可用性通过。对应 P1-59 SC-02／03／10／13，覆盖并发编辑 Spec E1–E28。

## UAT-RACS-11 — 预览依赖变化与权限收紧（必做，J2／J5）

### 步骤

1. A 预览编辑 Agent，B 修改它引用的角色／行模板／来源范围；A 再提交。
2. A 预览删除 Role，B 新建对它的有效引用；A 提交删除。
3. A 准备保存期间，以既有合法管理路径禁用测试账号或撤销其会话；同时保持另一未受影响账号进行合法操作。
4. 恢复合法测试主体，重新登录／预览后完成原本允许的修改；不降低 ACL 或关闭门禁。

### 期望

变化必须要求重新预览或按既有授权拒绝，禁止旧确认扩大权限；未受影响用户可以继续操作，恢复后的合法路径成交。依赖变化与无关对象变化明确区分。对应 P1-59 SC-04／05／07，P1-58 SC-05。

### F59／R共同必验的依赖正反例

每行分别在同账号独立Cookie与不同账号执行，保存前后的目标对象版本、实际依赖集合、previewEffectDigest、candidateConfigDigest与裁决均记证据；摘要本身不是正确性oracle，最终对象和权限集合另行核对。

| 子项 | 实际变化 | 预期 |
|---|---|---|
| 11-D01 | 目标已知字段改变；另改一个被保留的未知字段 | 两种都冲突；未知字段不能从摘要消失 |
| 11-D02 | 改引用角色／行模板／constraints，保持来源数量相同但替换具体集合 | 重新预览，不被同数量蒙混 |
| 11-D03 | 分别改编译闭包内与闭包外来源／启用表／默认策略／分类输入 | 闭包内重新预览；闭包外效果不变不假冲突 |
| 11-D04 | 无关角色或Agent的描述改变 | 目标修改可完成，新整配置保留双方变更 |
| 11-D05 | 预览删除后新增引用；ID退休／模板保护变化 | 按既有保护拒绝，重预览不能绕过 |
| 11-D06 | 新调用使计数增加但门禁等级／影响面不变 | fresh重评但不只因原始计数增加冲突 |
| 11-D07 | 新调用或敏感范围变化触发门禁跨阈值 | 重新预览／依法拒绝，旧确认不可复用 |
| 11-D08 | 原主体禁用／会话撤销，另一主体仍合法 | 原主体提交拒绝，另一主体仍能成交 |
| 11-D09 | 仅lastSeen、调用统计或时间变化 | 对象版本不变；不产生假目标冲突 |
| 11-D10 | tools集合重排；有序规则换序；未知嵌套值／数组改变 | 仅有明确集合语义者等价，其他改变版本且不丢字段 |
| 11-D11 | 创建／复制目标由缺席变存在；复制源改变 | 不覆盖已存在对象，源变重新预览 |

其中“必须拒绝”与“必须不得拒绝”的成对样本都要有；若不能构造真实触发路径，记BLOCKED，不能只看摘要函数单测代替F59接口证据。

## UAT-RACS-12 — 无 WebUI 身份的纯 MCP 共存（必做，J2／J5）

### 步骤

1. MCP 客户端只持 fixture Token，不携带 WebUI Cookie，完成 initialize、tools/list 和真实小表只读查询。
2. 在联合 Web 读写负载下持续读取固定小表，结果与独立数据库 oracle 核对；相同数据档先测无 Web 干扰对照。
3. 收紧受测目标权限，验证应拒绝的请求被拒绝；保留未受变更影响主体与表继续真实读取。
4. 走当前产品允许的重新授权／新合法范围流程后，再证明合法读取恢复；不要求额外宿主或管理员身份。

### 期望

未受影响合法请求正确完成并过绝对／相对时延预算；新约束生效同时合法路径可成交，不以批量 403／拒绝作为成功吞吐。此项是组合发布取证，不倒推两个功能合同已收口。

## UAT-RACS-13 — 慢盘冷缓存与热稳态（必做，J2／J5）

### 步骤

1. 在专用测试 VM／隔离设备确认限速生效、夹具页缓存确实冷；记录证明，不执行共享宿主全局清缓存。
2. 从同一 fixture 快照启动，记录首次 ready、启动／维护任务与列表首次读；启动 SLA 回链已有冷启动合同，不自行改探针。
3. ready 后执行联合 J2／J5，分别记录冷阶段与热稳态，三轮独立重复。
4. 同窗观察 readyz／livez、MCP、正常业务与错误；不能只证明容器 Running。

### 期望

满足 fixtures §5 慢盘档预算，探针、正确性与丢写门槛不放宽。无法施加或证明冷缓存／限速则该项 BLOCKED，热盘通过不冒充慢盘通过。

## UAT-RACS-14 — 网关错误、局部写失败、响应丢失与恢复（必做，J2／J5）

### 14-A — 局部真实HTTP错误（F58及R）

专用反向代理仅对被测读请求短时切断上游，取得实际HTML 502／503；不修改成功体，不要求整站故障。浏览器捕获状态／Content-Type，并与真实JSON BUSY、401／403／409区分。恢复该请求上游后读取须成功，其他区域可用，读重试次数与总时长有界。

### 14-B — 操作回执与丢响应（F59及R）

1. 真实提交后仅阻断返回响应，用配置与持久intent／terminal证明提交时序；UI保存结果待确认，仅GET核对operationId。
2. 按并发Spec §4.1检查旧schema无改动、同一config_change_log行由pending到committed，可信requestId未被客户端operationId覆盖，racsReceipt经真实脱敏／序列化／终态更新后字段完整。
3. 同operationId同账号同内容再次请求不得重复落盘；同号不同内容拒绝；不同账号不得认领／窥探；账号显示ID重用但UID不同仍无原操作查询权。owner仅按既有权限查询，不可伪装原提交者重放。
4. 已提交后另一个用户再改同一对象；查询旧operationId只返回历史提交版本，不把当前值配成旧after或声称旧版本仍生效。
5. 缺记录、旧记录缺回执、pending、恢复未确认均unknown；有明确failed／rolled_back且恢复已核实才not_committed。均不得自动重放写请求；核对有界，手动核对与fresh重新预览路径可达。

### 14-C — 局部事务失败与合法恢复（F59及R）

使用隔离卷真实写权限／磁盘失败及现有可控接口构造配置写失败、运行时确认失败和审计终态失败；每个失败点证明没有假成功、重复提交或未确认的残留。恢复后显式重读、预览、确认，合法修改确实提交。不能用“返回了预期错误”替代恢复成交。

### 14-D — 跨进程重启与连续审计恢复（仅R）

在隔离实例真实中断并重启，保留同一审计卷；对已持久terminal核对历史结果，对仅有intent核对unknown／恢复流程。另用独立副本模拟审计缺失或恢复到旧备份的证据不足情形，禁止声称仍可认领未知旧操作或复用旧操作号重写；只读核对不依赖进程内存。该场景属于系统恢复，不倒挂F59功能收口。

### 期望

网关页不再显示 JSON 解析错误；读重试有界、写不重放；本次提交终态有证据才成功，无法证明则 unknown 并有可达恢复。故障窗口具名，恢复后必须真实读取和保存成功；故障注入中的预期非 2xx 不冒充普通稳态成功。对应 P1-58 SC-09、P1-59 SC-07–09／12；系统重启是共享 UAT，不替代局部事务门禁。

## UAT-RACS-17 — 校准“当前用户 2～5 倍”的覆盖主张

### 步骤

1. 收集经授权只读统计或脱敏回传，按 fixtures §6 冻结当前数据规模与繁忙窗口的会话、Web 读、保存意图、MCP 速率；记录采样时间、构建与覆盖范围。

3. 任一维有效 B 增大，重建相应档并重跑受影响的单维／联合／恢复／长稳态用例；相同候选与资源，不只改结果表数字。

### 期望

## 判定与清理

每个选择器、档位和轮次分别记录PASS／FAIL／BLOCKED；该选择器必做未跑不得合并PASS。正常稳态5xx、统计错误、丢写、越权、无逃生恢复任一成立即FAIL。只通过拦截分支而没有恢复成交同样FAIL。F58／F59可各自交付SC证据，R仍须完整2×／5×和故障／长稳态；未跑R不得只凭功能子集更新全套PASS。

测后按 fixtures §7 清理并核对生产／共享 demo 未被触碰，正式跑次记录清理结果。所有失败保留原始证据；修改合同或阈值必须有版本与评审记录，不能回写旧跑次为通过。
