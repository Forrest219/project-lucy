## 2. 倍率定义与设计下限

冻结向量 `B = (connections, manifestSources, enabledSources, roles, agents, tokensPerAgent, rows30d, rowsAll, sessions, webReadRps, saveIntentRps, mcpReadRps)`。**每个已校准维度**取 `max(下表下限, 经证据冻结的当前值)`；未测维度标 `design-floor`。保存倍率覆盖的是用户提交意图，含 dryRun／确认所需请求的实际放大率另记，不把一次保存旅程算一次 HTTP。

| 维度 | B 设计下限 | 2× | 5× | 来源性质 |
|---|---:|---:|---:|---|
| 连接数 | 8 | 16 | 40 | 历史观测下限 |
| Manifest 总来源表数 | 263 | 526 | 1315 | 历史总表下限，衡量来源映射构建成本 |
| 已启用来源表数 | 259 | 518 | 1295 | 历史已选表下限，衡量有效授权范围；与总表分母不混用 |
| 正式角色数 | 20 | 40 | 100 | 设计下限；参考模板另算，不替代正式角色 |
| Agent 数 | 100 | 200 | 500 | 规划下限 |
| 每个 Agent 配置凭据 | 3 | 3 | 3 | 固定 3；总凭据 300／600／1500，避免随 Agent 倍率重复乘算 |
| 当前 30 天内原始调用行 | 200000 | 400000 | 1000000 | 既有演练规模下限 |
| 全部历史原始调用行 | 1000000 | 2000000 | 5000000 | 设计下限，含上行窗口行；另有 800000／1600000／4000000 窗口外历史 |
| 独立会话数 | 5 | 10 | 25 | 设计下限；同账号独立登录 Cookie／不同账号各跑一轮 |
| WebUI 列表读取到达率 | 2 次/秒 | 4 次/秒 | 10 次/秒 | 设计下限，开放式发压，不因服务慢自动降速 |
| 保存意图到达率 | 0.1 次/秒 | 0.2 次/秒 | 0.5 次/秒 | 设计下限，真实预览→显式提交；HTTP 数量单列 |
| 纯 MCP 合法读取到达率 | 1 次/秒 | 2 次/秒 | 5 次/秒 | 设计下限；不是 initialize 洪泛 |

倍率是**向量逐维倍率**，并非总计算量线性倍率。数据与会话同时 5× 可能产生更高组合压力，报告必须写明，不能简称“总负载恰好 5 倍”。统计窗口固定 7d／14d／30d；每档分别测，不能只放大库却让窗口内行数不增长。

单维用例固定其余维度为 B：D2／D5 只放大数据元组，C2／C5 只放大会话，Q2／Q5 只放大三类到达率。J2／J5 同时放大所有可缩放维度。突发档只把 J5 的请求速率再翻倍，不将其记作另一份普通 5×通过。

## 3. 造数与独立 oracle

1. 只在专用 Docker 数据卷／前缀 `uat_racs_` 数据源造数；固定 seed 与 asOf，按实际冻结时间生成相对时间，保留整个跑次相同夹具。真实 SQLite／ACL／API，不 mock 核心解析。
2. 30 天调用分布：近 7 天 50%，第 7–14 天 25%，第 14–30 天 25%；窗口外历史明确落在 31–365 天。额外添加窗口起止边界前后各一条、同毫秒不同 id、无历史用户、只在 90 天前使用的用户。
3. 80% 调用集中在 20% Agent，最热单用户至少占窗口内行数 20%，并不少于既有 3163 行大用户闭包规模；其余均匀分散。不得只造均匀、每人几条的小库。
4. 原始调用组成：默认使用 60%、协议事件 25%、默认排除评测探针 15%；默认使用中 10% denied，其余成功。按现有合同定义 Golden 分类表，独立生成器先输出预期，禁止导入被测聚合函数来算 expected。缺少分类必填列就判 fixture 无效。
5. 凭据含正常、到期、吊销与跨用户前缀碰撞；角色含零引用、多角色、行策略、无效引用、宽范围授权与不重叠范围。专门保留一个未受变更影响的纯 MCP 主体及一张可核验的小表。
6. 来源表覆盖 8 基础连接、多个 Schema、普通与宽授权角色；通过真实 Manifest／来源映射构建，不能复制同一名称让 hash 去重后缩小规模。
7. 初始结构和受测策略从专用 fixture 写入；测前维护器／投影完成并验证当前窗口有效覆盖。另有 13 号用例刻意测试冷启动／补算并发，其负载与证据分开，不把后台未就绪误算成列表查询性能。
8. seed manifest 保存实际 COUNT、按窗口／用户／类别计数、source／role／credential 数、SQLite 页数／文件大小、金样本摘要；原始日志数与实际有效数据均要检查，不看“计划造了多少”。

## 4. 资源、身份与负载时序

| 项目 | 约束 |
|---|---|
| Lucy | 单实例、单进程、2 vCPU、4 GiB 内存；基线与候选完全同资源，禁止 5× 时加 CPU／副本 |
| 数据卷 | 专用隔离卷；至少 40 GiB 可用，或实际夹具＋WAL峰值＋2 份快照的空间上界，取大者；测前测后都记录 |
| 压测器 | 独立宿主进程或独立容器，不共用 Lucy 的 CPU 配额；压测器饱和使跑次无效，不能归罪产品或记 PASS |
| 浏览器 | 1920×1080 单一桌面视口；API 发压与桌面交互并行，最多 5 个用于 UI 观察的浏览器上下文，其余独立会话可用真实 HTTP |
| 凭据 | 只记录仓库外凭据文件路径；登录经真实接口，各会话独立 Cookie jar；报告不含原文 |
| 登录准备 | 不修改认证限流；成功登录总源限流仍存在，按实际限流窗分批准备、等待，所有会话准备完毕再计时；负载期间不反复登录 |
| MCP | 使用专用 fixture Token，经真实 Proxy 连接；准备后反复合法只读调用，未授权调用只在具名安全用例出现 |
| 慢盘档 | 同 CPU／内存，读写 30MB/s、读 300／写 100 IOPS；记录实际生效值与设备，不能只写 docker 参数即认为生效 |
| 冷缓存 | 使用可证实的专用测试 VM／设备页缓存清理或隔离冷读方式；不对共享宿主全局 drop_caches。无法证明冷缓存时该档 BLOCKED，不改称冷启动通过 |

单维和联合档：预热 2 分钟、线性爬升 1 分钟、稳态 10 分钟、回落恢复 2 分钟；每档独立 3 轮，每轮从相同 seed 快照恢复。J5 另做 60 分钟长稳态，其中第 20 分钟与第 40 分钟分别 60 秒速率突发；三轮 J5 普通档与长稳态均必做。

读取流量角色列表与 Agent 列表各 50%；Agent range 按 7d／14d／30d＝50%／25%／25%。新 UI 拆分后按一次进入旅程统计 primaryReady，同时分别记录 roster／statistics HTTP；不通过少发统计减少逻辑工作量。保存目标 80% 独立对象、20% 热点同对象；冷热／同账号／不同账号分开分组，不能混成一个平均值。

开放式计划到达率冻结，记录计划、发出、完成、丢弃、排队等待；实际发出率须达到计划99%，未发出不能从延迟分母消失。每次HTTP默认10秒超时；读请求最多1次额外重试，额外重试和退避总预算5秒，首次有效查询不因5秒缓存TTL被中止；整个读取旅程最多15秒，超时分别记录且计失败。保存旅程按下述10／30秒成交预算继续记录，不能把单次HTTP超时当整个意图结束并从分母剔除。到达时间至响应结束为端到端，包含退避；超时样本记录真实截止时长，不删样本。

F58／F59 仅取 suite 分层矩阵指定的局部场景，不套用整个开放式 R 流量；R 的上述时序与2×／5×强度保持不变。测试执行者可以复用同一跑次的证据，但不得因复用删掉矩阵的必验组合。

## 5. 验收目标与基线冻结（文档定稿，不是已达标能力）

本表绝对线保留为候选的可证伪目标；必须在同资源、同seed／数据档、同身份与负载选择器下先取得有效改前响应基线，再对照候选。相对闸沿用P1-13：同档p95同时恶化超过20%且超过50ms即失败。绝对线与相对闸同时满足；无有效200／正确payload的改前组只报告“无有效基线”，不能算虚构改善百分比。达不到则FAIL回设计；改变目标须版本化、具名评审及委托人明确接受，不能追样本改数值。5×不改为仅观察，正确率、权限与丢写门槛不放宽。

| 指标 | B | 2× | 5× |
|---|---:|---:|---:|
| 两个默认列表 API 热态 p95（含完整统计） | ≤200ms | ≤500ms | ≤1000ms |
| 新角色列表／Agent roster API 热态 p95 | ≤200ms | ≤300ms | ≤500ms |
| 新统计 API 热态 p95 | ≤200ms | ≤500ms | ≤1000ms |
| 第一次冷读／快照失效后有效读取 max（正常盘） | ≤1000ms | ≤2000ms | ≤3000ms |
| 桌面名册 primaryReady p95 | ≤1000ms | ≤1500ms | ≤2000ms |
| 无冲突保存正式提交 p95（不含人工思考／预览等待） | ≤2000ms | ≤3000ms | ≤5000ms |
| 统计缓存复用 | 读取开始后≤5秒，显示原始统计时间，强制刷新绕过已完成缓存 | 同左 | 同左 |
| 正常档有效读取成功率／数据正确率 | 100%／100% | 100%／100% | 100%／100% |
| 配置丢失／静默覆盖／重复正式提交 | 0 | 0 | 0 |

这些预算只用于本套件明确硬件与夹具，不替换 P1-13 既有 fixture 的 200ms／500ms 门禁，也不承诺客户单机 SLA。每条路由、窗口、身份模式逐组过线，不能靠合并平均掩盖慢组。

R组合档的发布取证硬要求：livez p99 ≤400ms、max <1000ms；readyz 每次 <3000ms；容器非故障注入重启数0；MCP合法调用全部正确完成，p95 ≤max(同数据档无WebUI干扰对照×1.2, 对照＋50ms)，且绝对p95 ≤2000ms。连续失败指livez／readyz各自连续3次采样超时；该失败事件必须0次，不通过放宽探针预算获得通过。该段不倒挂成F58／F59功能收口要求。

慢盘档：待真实 ready 后，读取 API p95 ≤3000ms、primaryReady p95 ≤5000ms，livez p99／max 与 readyz 预算保持上段不变；启动耗时只记录并回链既有冷启动合同，不在本条重新定义升级启动 SLA。慢盘标准放宽仅限读取响应，不放宽正确性、权限、探针与丢写要求。

同对象冲突或发布BUSY必须在1000ms内给明确反馈；它们属于预期事务结果，不计成功保存。R联合吞吐要求：独立对象保存意图至少95%在10秒内经用户显式重试后确认提交，热点冲突意图至少95%在30秒内经重新预览与显式确认完成；未完成意图不得用“已正确拒绝”替代成交证明。F59局部事务不以R的吞吐比例收口，但每一对被拒绝的合法修改仍必须在重读／重预览后真实完成。

R使用可复现的“显式用户步骤模型”：首次预览后100ms内提交；BUSY后等待1秒、fresh重读／预览，再由测试客户端执行一个单独记录的确认动作；目标冲突后读取三方值、选择保留本次已预先冻结的修改，再预览与确认。HTTP传输层重试POST／PATCH／DELETE始终关闭，不能靠库自动重放。交互耗时与上述步骤全部计入意图端到端10／30秒分母；目标每次确实改变才算成交。人工桌面场景另测可达性，不拿人工思考时间混入吞吐。

发布窗口吞吐为串行，不承诺对象级并行写盘。报告必须给窗口持有时长、占用拒绝、完成吞吐与利用率；J5的0.5次/秒意图下，若平均窗口持有时长接近或超过2秒，说明容量紧张，必须如实FAIL／回设计，不能靠只记录成功者掩盖饥饿。

长稳态 60 分钟不得出现内存／WAL／在途队列持续无界增长：回落后 2 分钟在途数归零，队列不残留；RSS 相比同档预热后稳定基准增长不超过 20%，WAL 峰值和检查点需给曲线与回收证据。越线不能删尾部样本或直接抬阈值。

## 6. 当前负载校准与证据边界

RACS-17 只需经授权的只读统计或脱敏人工回传，无需客户写操作、生产压测或集群部署。当前数据计数记录采样时间与版本；流量取最近 7 天中有代表性的至少 30 分钟繁忙窗口，基准取 1 分钟桶的峰值会话／读速率／保存意图／MCP 速率；不足代表性时标明覆盖范围并保留缺口。

取不到当前数据时，suite 可先执行设计下限，但报告必须分开：`localScaleVerdict`（下限倍率的实际结果）、`currentMultiplierCoverage`（未核实／已校准，及缺失维度）。17 是当前倍率主张的必要条件；不得以历史 263 表、20 万演练行推定其他维度的现网负载。后续当前值高于下限，必须提高 B 并重跑相应 2×／5×，禁止降低倍率或只改报告数字。

## 7. 清理

记录测试创建的对象、Cookie jar、Token 文件路径与容器／卷前缀；撤销 fixture 专用 Token，删除临时代理规则与测试对象，销毁独立卷或保留具名只读快照。禁止删生产数据或共享 demo 卷；清理失败写跑次，不带凭据归档。
