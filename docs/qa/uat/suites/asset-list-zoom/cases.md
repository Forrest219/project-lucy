## UAT-ALZ-R0

### 前置

- lean：`npm run demo:upgrade`（或栈已 healthy）。
- WebUI／MCP 端口以实际映射为准（默认 55176／57881）。
- 管理员凭据不入库。

### 步骤

1. 确认容器 healthy。
2. 前台浏览器打开 WebUI 并登录。
3. 记录 `gitSha`／档位 lean／端口。

### 期望

环境可用后方可跑 01–12。若实现未落地，后续用例 **BLOCKED** 并写明原因。

## UAT-ALZ-01

### 前置

- 目标连接下 ≥2 个 Schema 且合计表行足够可见分组（夹具见 fixtures）。

### 步骤

1. 打开 `/connections/enabled-tables`（1920×1080）。
2. 记录导航→表工作台可见计时。
3. 断言同时仅一个 Schema 组展开表行；切换展开另一组时上一组表行消失。

## UAT-ALZ-02

### 步骤

1. 在展开组内数可见表行：默认 ≤5。
2. 点击「显示更多」，可见行增加 5（或至剩余不足 5）。
3. 在前台浏览器会话内（Playwright `page.evaluate` 或 DevTools console）断言：`data-testid` 有界区域内表行节点数 ≤ 当前可见上限，窗外无表行节点（不得仅 CSS 隐藏；jsdom／vitest 不得作为该断言的执行环境）。

## UAT-ALZ-03

### 步骤

1. 确认过滤总量 >5 时工具条附近有系统内搜索引导。
2. 输入仅存在于非首屏的表名片段。
3. 断言目标可勾选／可见；全程不使用浏览器 Ctrl+F。

## UAT-ALZ-04

### 步骤

1. 构造或筛选使过滤总表行 ≤50 但仍有 ≥2 Schema。
2. 断言仍单组展开（废止旧全展开）。
3. **必做**：刷新页面，观察表工作台 loading 期间不得出现「缺 Manifest」类假阴性文案（P1-80 三态诚实不被家族 A 重写削弱）。
4. （可选深度项）若可注入 tables pending／error 对照：不得出现假阳性缺 Manifest。

## UAT-ALZ-05／06

### 步骤

1. 打开 `/catalog`，范围 `connection`／`schema=all`（或等价「全部」）。
2. 断言右表同时只展开一组；组内默认 ≤5。
3. 搜索可用；记录计时。

## UAT-ALZ-07／08

### 步骤

1. 打开 `/connections`：表清单未默认展开。
2. 若 Schema >20：默认可见摘要 ≤20 +「显示更多」。
3. 展开某 Schema 库内表：默认 ≤5；单元格或页内可搜索。

## UAT-ALZ-09／10

### 步骤

1. 打开角色详情表授权（names 模式；候选 >50 的夹具）。
2. 断言单页候选表行 ≤50；可翻页。
3. 搜索表名并勾选；已选计数不因翻页清零。
4. 过滤后总量 >50 时，断言表授权区可见系统内搜索引导文案（SC-14）。
5. 展开已选摘要：若已选表名行 >50，断言摘要区分页且单页 ≤50（Spec E14）；lean 下不可达时，本步由 Task 5 单测证据支撑并在跑次注明。

## UAT-ALZ-11

### 步骤

在启用表或角色搜索不可能命中的字符串；断言空态引导改关键词。

## UAT-ALZ-12

### 步骤

汇总本跑次所有 WebUI 用例：每条有前台计时，并与同窗 API 耗时分列写入跑次。缺计时 → 该条 BLOCKED。

## UAT-ALZ-13（可选）

### 步骤

打开 Agent 权限预览；若表名行 >50，断言分页或等价有界；搜索可用。
