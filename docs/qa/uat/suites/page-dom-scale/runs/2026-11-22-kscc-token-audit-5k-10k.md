## 夹具和审计留痕

从独立 demo 的 2 条凭据开始，通过真实管理 API 向两个 Agent 各签发 100 条。四档始终保持同一 202 条凭据，标签、所属 Agent、状态和到期时间的清单摘要一致。0 和 1,500 条在本轮重新测量，便于对照。[上轮 0／300／1,500 行跑次](2026-11-22-kscc-token-audit-history.md)。

复用其中 20 条凭据，通过真实 MCP 会话执行共 7,500 次 `connection_list` 和 2,500 次 `lucy_catalog`。本轮造数使用最多十条相互独立的串行通道，每通道实际工具请求起点最小间隔 503.4 ms。造数每 30 秒核对健康。每档关闭 MCP 会话，连续两次核对实际审计总量一致，再开始浏览器测量。业务成功调用和实际落盘条数相同，无协议行计入。最高档两个 Agent 各 5,000 行。所有记录为本轮近期真实访问，7 天和 30 天窗口计数相同。

每档七个前台样本，冷导航和首次站内进入各用一个新浏览器上下文。热回访三轮，搜索命中 1 条，清空恢复 202 条。每轮前后均确认可见且有焦点，计时终点为指定行与预期条数可见后的绘制帧。API 使用同轮页面请求的墙钟，200 且业务成功。冷进入指浏览器冷进入，服务端保持在运行状态。

## 清理和 Spec／开发评估

200 条测试凭据全部通过真实 API 吊销，清单恢复基线 2 条。隔离容器测量期间未重启，测后回收容器、网络和卷，专用私有文件已移除；共享 demo 指纹未变。
