## 通用判定规则

1. 真实 Agent 最终答案必须与本问 typed gold 和真实服务端查询对账；只有文字答案或无关查询不算 PASS。
2. 基线成功的请求在 POST 出现新增 deny、error、空信封、原非空变空或预期指标缺失均 FAIL。
3. 基线应拒绝的请求在 POST 变为允许、返回越权数据或泄露受限身份均 FAIL。
4. 任一必需轮次、客户端、尝试或样本缺失即分母不完整；禁止只保留最快／成功样本。
5. 本任务不重建 Docker；环境不满足记 BLOCKED，不以 mock、单测或临时镜像冒充全真。

## UAT-COMPAT-03／04 — 连续追问

### 步骤

1. 在一个真实 Agent 会话中问「查询 2025 年 11 月会员收入」。
2. 同会话追问「那 12 月呢？」。
3. 同会话追问「再按区域拆分」。
4. 同会话追问「和上月相比呢？」。
5. 对每轮保存最终答案、真实请求 ID、用户墙钟与 MCP／服务端耗时。

### 期望

- 各轮分别保留 11 月、12 月、区域维度与环比语义；不得每轮重新开始无关旅程。
- 所有合法轮次成交；出现 `source_ambiguity_gate`、上下文丢失、无真实查询或超时均 FAIL。
- 客户没有「区域」维度时使用其实际私有基线中的等价维度，不在公开仓库写客户字段值。

## UAT-COMPAT-06 — 多库

### 步骤

1. 在同一授权身份下分别询问连接 A 与连接 B 的既有指标。
2. 要求基于两次已授权结果做对比。
3. 用无 B 权限身份重复，确认不泄露 B。
4. 发起产品不支持的跨连接混查，观察拒绝与下一步。

### 期望

- 合法分别查询与对比成交，不发明跨连接 join。
- 无权限身份不得看到 B 的数据或受限身份；混查提示按连接拆分。

## UAT-COMPAT-09 — 事故负控与修复后

1. 若已存在未修复旧版实例，先执行同形首次 query；预期旧版 FAIL，证明用例能抓住事故。
2. 在修复候选上以泛化业务词 begin，再首次查询已明确唯一来源的指标。
3. 客户层用既有 WorkBuddy／MCP 配置与 Token 重放实际会员收入基线。
4. 记录首次结果，不允许先 deny 再重试凑绿。

## UAT-COMPAT-11／12 — 耗时

每轮记录 `turnWallClockMs`、`mcpClientRttMs[]`、`serverDurationMs[]`、重试与 `unattributedMs`。trace span 缺失时不编造阶段耗时；600 秒技术终止线不是体验合格线。绝对与相对阈值严格按 Spec D11–D15。
