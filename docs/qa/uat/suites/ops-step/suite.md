## 全真性

本机 demo Docker。IT 运维路径用容器标准输出，不登录。Lucy 运维路径用真实前台浏览器，视口 1920×1080，导航到列表可见的时间与接口耗时分列。两个既有准备表结构入口分别记录错误区域可见时间与读字段 API 耗时；启用表保存记录点击保存到反馈可见时间与真实 PUT 耗时，不能用其他页面的计时代替。

挡板只在 `LUCY_OPS_STEP_UAT=1` 时存在。先验证关闭态 404，再开启执行 01–08。故障注入必须调用真实操作、真实写者和真实页面，不得返回预制日志、用 mock 替代业务操作或用阅读代码代替跑次。

## 判定

现行判定见 [INDEX](../../INDEX.md)。前台补跑覆盖 UAT-OPS-STEP-04／05 的前台与持久化路径。

- 每个日志断言必须绑定当次 `op_id` 和日志游标，不得用相同步骤名的旧行凑证据。
- 每个故障注入都要记录恢复结果；靠重启伪装故障修复不得判 PASS。SC-14 的重启只用于验证历史持久化与进程代次，不作为修复手段。
- 真实进程自动化可证明序列化边界、1 小时截断和 8 MiB 滚动，但须保存命令、版本和输出；不得以缩小设计值后的测试替代实际能力。
- 生产诊断成功场景托住 2000 ms；10000 ms 场景验既有 5000 ms deadline 中止。管理台长观察使用显式独立生命周期的真实采集器，不发布生产快照、不放宽生产时限，不证明生产诊断可活过 5 秒。
- error／short 注入不能代替真实满管道背压，只读目录不能代替已有文件追加失败。须有实际写机制、服务 PID／UID、独立监督计时及故障生效证据；文件消费者阻塞时还须证明 1 MiB 队列上限和精确丢行。
- 51 表两批验 HTTP 200＋HTTP 400 混合取号；52 表另验两次 HTTP 200。API 单表原句与客户端汇总原句分别保持，两个准备入口均显示操作号。
- SC-12 按五种操作分别列证据，使用起止审计水位、真实 event_type／stage／JSON 属性；明确禁止 stage=ops_step_journal，但不以不存在列、旧数据或其他正常同名 stage 冒充阴性证据。

## 边界

- 通过只说明步骤名被写下来、写账降级可见。不说明探针卡死、事件循环占满或读字段失败已被修复。
- 问数主路径必须仍能完成（08）。只证明「步骤写出来了」而问数失败，整套不得 PASS。
- 运维操作自身可以按既有合同写正常审计；SC-12 只禁止运维步骤账混入 `access_log` 或 `access_trace_span`。
- 生产诊断被既有 5000 ms deadline 中止后，生产快照 `freshness` 变 stale 是既有服务语义，不是本功能引入；跑次必须显式接受该现象，不得当成“生产健康面无影响”。
