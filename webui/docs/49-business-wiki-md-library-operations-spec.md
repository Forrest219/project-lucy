## 1. 背景

M42 将 `/wiki` 从基础 Markdown 编辑器推进为业务 Wiki 工作台，但 2026-08-01 浏览器核查显示，该页面仍保留了过多“在线编辑器”思路，和真实运维主路径存在偏差。

用户反馈和核查结论集中在九类问题：

1. 顶部面包屑 `语义建模 / 业务 Wiki / global/discount-policy.md`、`复制链接` 和文档路径信息重复。
2. Wiki 内部侧栏出现 `表目录`，点击会跳转到 `/`，属于严重信息架构错误。
3. `业务 Wiki` 在页面内重复出现，削弱层级感。
4. 目录结构没有清晰表达“目录，再到目录下文档”的文档库心智。
5. 搜索占位文案 `搜索标题、标签、sl_ref...` 暴露开发字段，普通用户无法理解。
6. 访问 `/wiki` 默认打开 `折扣率口径（Discount Rate Policy）`，不适合作为模块入口。
7. 文档详情页首屏存在大面积空白，正文被挤到页面核心区域下方。
8. 编辑态中的 `专注编辑`、`文档信息` 对当前用户主路径价值有限，并且专注编辑存在布局塌陷风险。
9. 真实用户更常见的操作是下载 Markdown、上传 Markdown 覆盖，在线手工编辑应降级为辅助能力。

本 Spec 基于以上事实，将 `/wiki` 从“在线工作台”调整为“Markdown 文档库 + 文件级运维操作”。

## 2. 产品定位

`/wiki` 的主心智应是：

> 运维人员管理业务 Wiki Markdown 文件的文档库，可以按目录浏览、搜索、下载、上传覆盖，并在需要时做少量在线编辑。

因此页面优先级调整为：

1. 浏览目录和定位文档。
2. 下载当前 Markdown。
3. 上传 Markdown 新建或覆盖现有文档。
4. 查看渲染后的文档正文。
5. 在线编辑作为低频辅助入口。

## 3. 目标

- `/wiki` 默认进入文档库首页，不自动选中 `global/discount-policy.md`。
- 左侧 Wiki 区域清晰表达文件夹和 Markdown 文档层级，移除错误的 `表目录` 链接。
- 顶栏和文档 Header 降噪，避免重复展示路径、模块名和复制链接。
- 详情页压缩无价值留白，让正文更早进入首屏。
- 提供一等的 `下载 Markdown`、`上传 Markdown`、`上传覆盖` 流程。
- 将在线编辑降级，不再把 `专注编辑`、`文档信息` 暴露为主要按钮。
- 修复或移除已知的专注编辑布局塌陷风险。
- 所有新文案遵守产品术语标准和浏览器翻译防御。

## 4. 非目标

- 不实现富文本编辑器。
- 不引入多人协同、评论、审批流或版本历史。
- 不改变 `wiki/` 的物理存储根目录和现有 Markdown 文件格式。
- 不把业务 Wiki 与 Schema Manifest、semantic overlay 的上传入口混在一起。
- 不在本轮引入外部对象存储或远端 CMS。

## 5. 信息架构

### 5.1 默认入口

访问 `/wiki` 时展示“业务 Wiki”文档库首页，而不是自动打开第一篇文档。

首页内容：

- 左侧：Wiki 目录树。
- 右侧：当前目录的文档列表或空状态。
- 主要操作：`上传 Markdown`、`新建文档`。
- 可选说明：只说明当前目录下文件数量、最近修改时间、可上传 `.md` 文件。

默认不显示 `折扣率口径（Discount Rate Policy）`。该文档仅在用户从目录树或搜索结果中选择后打开。

### 5.2 左侧 Wiki 区域

左侧应只承担“搜索 + 文件树”职责：

- 移除 Wiki 内部的 `表目录` 链接。
- 移除只读路径输入框或路径 chip。
- 顶部保留一个搜索框，占位文案为 `搜索文档标题、标签、关联表...`。
- 目录树以文件夹为第一层，例如 `global`。
- 文档在目录下展示，使用 Markdown 文件图标和短标题。
- 文件名、路径、数据库对象名必须加 `translate="no"` 和 `notranslate`。
- 当前选中文档只高亮一次，不在同一侧栏重复展示路径。

搜索命中时仍保持目录上下文，不应把所有结果平铺成不知所属目录的列表。

### 5.3 顶栏

顶栏只保留模块级上下文和主操作：

- 页面标题：`业务 Wiki`。
- 副标题：`管理业务口径、指标说明和分析 Playbook 的 Markdown 文档。`
- 根路径 `/wiki`：右侧显示 `上传 Markdown`、`新建文档`。
- 文档详情：右侧显示 `下载 Markdown`、`上传覆盖`、`更多`。
- `编辑` 放入 `更多`，或作为次级按钮显示，但不应高于下载/上传。
- 移除默认可见的 `复制链接`。
- 移除顶部面包屑中的 `global/discount-policy.md`。文档路径只在文档 Header 的轻量元信息中展示。

## 6. 文档详情页

### 6.1 Header 降噪

文档详情 Header 应压缩为：

- 文档标题。
- 一行元信息：路径、关联表数量、最近修改时间。
- 最多 3 个关联表 chip，超过 3 个显示 `关联 11 个语义实体`，点击或悬停展开。

不要在同一个视口内重复展示：

- `业务 Wiki` 模块名。
- 完整路径。
- 文档标题。
- `复制链接` 主按钮。

### 6.2 正文布局

文档正文应在首屏更早出现：

- 文档标题到 Markdown 正文第一行的垂直距离应小于 96px。
- 不再用大面积空白卡片承载标题区。
- 右侧目录只在文档存在多个二级标题时展示。
- 右侧目录宽度固定，不应挤压正文。
- 当页面宽度不足时，右侧目录折叠为浮动目录按钮。

### 6.3 关联实体

关联实体继续沿用 M42 的降噪原则，但本轮进一步收敛：

- chip 文案只展示表名或实体名，不展示重复的 `未知语义对象`。
- 用 status dot 或轻量状态色区分已识别 / 未识别。
- 超过 3 个时默认聚合为 `关联 N 个语义实体`。
- 数据库对象名必须防翻译。

## 7. Markdown 文件操作

### 7.1 下载 Markdown

文档详情页必须提供 `下载 Markdown`。

行为：

- 下载当前文档原始 Markdown。
- 文件名默认使用当前文档路径的 basename，例如 `discount-policy.md`。
- 下载失败时展示可理解错误，不暴露栈信息。
- 如果当前文档存在未保存在线编辑内容，下载按钮应明确下载的是“已保存版本”，或先提示保存。

API 建议：

- `GET /api/wiki/:key/raw` 返回 `text/markdown`。
- 如果现有详情 API 已稳定返回 raw Markdown，可前端直接复用，但下载行为必须有独立测试。

### 7.2 上传 Markdown

根路径和目录路径下提供 `上传 Markdown`。

行为：

1. 选择 `.md` 文件。
2. 选择目标目录，默认当前目录。
3. 系统推导目标路径，例如 `wiki/global/new-doc.md`。
4. 进入上传预检 Modal。
5. 用户确认后写入磁盘。

上传预检必须展示：

- 目标目录。
- 目标文件名。
- 是否新建或覆盖。
- Markdown 标题预览。
- 关联表解析结果。
- 校验错误和警告。

### 7.3 上传覆盖

文档详情页提供 `上传覆盖`。

行为：

1. 选择本地 `.md` 文件。
2. 目标路径固定为当前文档。
3. 预检展示差异摘要。
4. 用户确认后覆盖当前 Markdown。
5. 覆盖成功后刷新预览、更新时间和目录树状态。

覆盖防护：

- 必须有二次确认，不允许选择文件后直接覆盖。
- 如果当前页面存在未保存在线编辑内容，必须先弹出离开/覆盖确认。
- 文件扩展名不是 `.md` 时阻止上传。
- 写入必须经过 `fs-safe.ts`，只允许 `wiki/` 下路径。

## 8. 在线编辑降级

在线编辑仍保留，但不再作为主路径。

调整要求：

- 文档详情页将 `编辑` 放在 `更多` 菜单中，或显示为次级按钮。
- 编辑态 Header 只保留 `取消`、`保存并发布`。
- 移除默认可见的 `专注编辑`。
- 移除默认可见的 `文档信息`。元数据可放入 `更多` 或右侧可折叠面板。
- 如果保留 Focus Mode，必须修复布局塌陷；否则本轮直接删除该入口。
- 切换文档、新建文档、上传覆盖、返回阅读前必须有未保存变更保护。

## 9. Empty State 与模板

当用户在空目录或新建文档路径上进入页面时，应显示清晰 Canvas Empty State：

- 主操作：`上传 Markdown`。
- 次操作：`新建空白文档`。
- 模板入口：`使用模板`。

模板选择只在新建空文档时出现，不应挤在正文中部造成视觉落差。

点击模板后：

- 自动填充结构化 Markdown 骨架。
- 占位符使用 `[请输入指标定义]` 等明确文本。
- 占位符高亮只在编辑器中生效，不影响 Markdown 渲染结果。

## 10. Terminology Compliance

This feature follows `webui/docs/00-product-terminology-standard.md`.

New terms:

| Canonical Term | UI 主术语 | 允许补充说法 | 禁止文案 | 说明 |
|---|---|---|---|---|
| Markdown Library | Markdown 文档库 | 业务 Wiki 文档库 | 在线编辑器作为主称谓 | `/wiki` 的新主心智 |
| Download Markdown | 下载 Markdown | 下载当前 Markdown | 导出 Wiki 混用 | 下载单篇 `.md` 原文 |
| Upload Markdown | 上传 Markdown | 上传 `.md` 文件 | 上传 YAML、导入 Markdown 混用 | 新建或导入 Markdown 文档 |
| Replace Markdown | 上传覆盖 | 覆盖当前文档 | 上传替换、导入覆盖混用 | 用本地 `.md` 覆盖当前文档 |
| Linked Table | 关联表 | 关联语义对象 | `sl_ref` 直接作为用户文案 | Wiki 文档引用的表或语义对象 |

文案要求：

- `Business Wiki` 的 UI 主术语继续使用 `业务 Wiki`。
- 搜索框不得出现 `sl_ref`。用户可见文案使用 `关联表` 或 `关联语义对象`。
- `Markdown`、`Wiki`、路径、文件名、数据库对象名、URL 必须加浏览器翻译防御。
- `表目录` 只能用于 `/catalog` 或导航中的 Catalog 入口，不得出现在 `/wiki` 内部目录树中。

## 11. API 与数据契约

### 11.1 推荐 API

| 方法 | 路径 | 用途 |
|---|---|---|
| `GET` | `/api/wiki` | 获取目录树和文档摘要 |
| `GET` | `/api/wiki/:key` | 获取文档详情和渲染所需元数据 |
| `GET` | `/api/wiki/:key/raw` | 下载原始 Markdown |
| `POST` | `/api/wiki/upload/preview` | 上传预检，返回目标路径、解析摘要、diff 和警告 |
| `POST` | `/api/wiki/upload/commit` | 确认写入新文档或覆盖文档 |

如果已有 API 能覆盖同等能力，可以复用，但前端动作和测试必须体现上述契约。

### 11.2 安全约束

- 所有写入只允许 `wiki/` 根目录下的 `.md` 文件。
- 禁止 `../`、绝对路径、软链接逃逸和非 Markdown 扩展名。
- 上传文件大小上限建议 1MB。
- 上传预检不落盘。
- 覆盖写入必须产生清晰成功或失败反馈。

## 12. 验收标准

### 12.1 浏览器验收

1. 打开 `/wiki`，默认展示 Markdown 文档库首页，不自动打开 `折扣率口径（Discount Rate Policy）`。
2. `/wiki` 内部侧栏不出现 `表目录`。
3. 页面可见的 `业务 Wiki` 不重复堆叠，同一视口内最多出现导航激活项和页面标题两处。
4. 搜索框占位文案为普通用户可理解文本，不出现 `sl_ref`。
5. 左侧可清楚看到 `global` 等目录，以及目录下 Markdown 文档。
6. 文档详情页顶部不展示冗余面包屑路径和默认可见 `复制链接`。
7. `折扣率口径（Discount Rate Policy）` 详情页首屏正文明显上移，标题到正文第一行距离小于 96px。
8. 文档详情页提供 `下载 Markdown`。
9. 文档详情页提供 `上传覆盖`，点击后进入预检而不是直接覆盖。
10. 根路径或目录页提供 `上传 Markdown`。
11. 编辑入口不再作为主按钮；进入编辑态后不显示默认可见的 `专注编辑`、`文档信息`。
12. 如果仍保留 Focus Mode，1280px 和 1728px 宽度下编辑器不会塌陷；如果删除该入口，则不再出现相关按钮。
13. 有未保存编辑内容时，切换文档、新建、上传覆盖、返回阅读均出现确认保护。

### 12.2 自动化验收

- Wiki 目录树测试覆盖：无内部 `表目录` 链接，目录和文档层级可访问。
- `/wiki` 默认首页测试覆盖：不默认渲染首篇文档详情。
- 搜索占位文案测试覆盖：不包含 `sl_ref`。
- 下载 Markdown 测试覆盖：触发正确文件名和 raw Markdown 内容。
- 上传预检测试覆盖：新建、覆盖、非法扩展名、路径逃逸、未保存变更保护。
- 编辑态测试覆盖：无 `专注编辑` / `文档信息` 主按钮，或 Focus Mode 不塌陷。
- 术语测试：`npm run lint:terminology` 通过。

## 13. 实施优先级

### P0

- 移除 Wiki 内部 `表目录` 跳转。
- `/wiki` 默认进入文档库首页。
- 移除 `sl_ref` 用户文案。
- 顶栏和 Header 去重。
- 删除或修复 Focus Mode 布局塌陷。

### P1

- 下载 Markdown。
- 上传 Markdown 新建。
- 上传覆盖 + 预检 + 二次确认。
- 未保存变更保护。

### P2

- 关联实体聚合交互。
- 模板 Empty State 优化。
- 右侧目录响应式折叠。

## 14. 风险与开放问题

- 上传覆盖需要后端 raw Markdown 写入能力；若当前 API 不足，需要新增受控写入接口。
- 如果产品仍希望保留“在线编辑优先”，需要重新确认用户运维工作流，否则本 Spec 默认文件级导入导出优先。
- 关联实体解析依赖现有 `sl_ref` 元数据，UI 不展示该字段名，但数据层可继续使用。
- 下载行为需要明确“已保存版本”与“编辑器未保存版本”的边界。
