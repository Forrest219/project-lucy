## 1. 目的

定义 Lucy WebUI 页面层的通用布局模式，避免每个页面单独定义结构，导致导航、操作区、信息密度和响应式行为不一致。

## 2. 标准页面结构

默认页面由以下区域组成：

1. Page Header（标题、简述、主操作）
2. Summary Region（核心状态/统计）
3. Primary Workspace（主任务内容）
4. Secondary Region（辅助信息、提示、历史）

要求：

- 主任务内容必须稳定落在 Primary Workspace，不得被次要操作挤占首屏。
- 主操作区不承载低价值信息；低价值状态应放入 summary 或 description。
- 二级区域默认可折叠或弱化，不与主任务争抢层级。

## 3. 列表/工作台页模式

适用：`/connections`、`/catalog`、`/wiki` 等高密度操作页面。

- 顶部：页面身份 + 全局动作（数量可控）
- 中部：筛选/分组工具条
- 主体：数据网格或卡片列表（可滚动）
- 辅助：抽屉/详情区用于次任务，不替代主流程

约束：

- 表格页不得在同一屏引入第二个“等价侧栏导航”。
- 行内动作与页级动作层级分离；行内动作为弱层级。

## 4. 概览页模式

适用：`/overview`。

- Header：系统状态摘要 + 刷新操作
- 中段：待处理事项与风险分区
- 下段：关键配置入口（如 MCP 接入）

约束：

- 概览页以“诊断和引导下一步”为目标，不承载深度编辑工作流。
- 并列入口动作默认同级，避免人为制造主次误导。

## 5. 配置页模式

适用：角色配置、连接配置、规则配置等高责任页面。

- 主体优先展示“当前可服务状态 + 风险状态 + 审阅入口”
- 技术细节（raw scope/tool list）默认放在详情层，而非首页噪音输出

## 6. 响应式与可达性

- 断点至少覆盖 `>=1440`、`1280-1439`、`1024-1279`、`<1024`
- 小屏优先保证：主任务可达、主操作可见、滚动路径明确
- 页面中所有可交互区域必须可键盘访问，焦点顺序符合视觉阅读顺序
- 当视口小于全局最小可读宽度时，页面保持桌面布局并改为横向滚动承载，不进入移动端重排
- 不得通过“隐藏主操作/关键字段”来伪造适配结果

## 7. 验收清单（页面级）

- 页面是否只存在一个清晰的主任务区域？
- 主操作是否与次要信息解耦？
- 是否复用了已有布局模式而非新造结构？
- 断点下是否仍保持操作可达和阅读顺序？
- 是否符合 `docs/ui-ux-feedback/README.md` 的跨页面治理规则？
