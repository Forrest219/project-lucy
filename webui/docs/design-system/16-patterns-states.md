## 1. 三态必须分开

同一区域必须区分四种状态，不得合并成一个「—」或空白：

| 状态 | 含义 | 呈现 |
|---|---|---|
| 加载中 | 请求未返回 | §3 |
| 失败 | 请求出错 | §4 |
| 空 | 请求成功且确实没有数据 | §2 |
| 无权限／被过滤 | 有数据但当前身份或筛选看不到 | 须明确说明原因，不得伪装成「空」 |

## 2. 空状态

- 使用 `pl-empty-state`（浅底圆角、`text-sm`、`fg-muted`）。
- 文案必须说明**为什么为空**，能给出下一步时给出（如「当前筛选条件下没有可启用的表。」）。
- 筛选导致的空，要点明是筛选所致，并提供清除筛选的入口。
- 不用「暂无数据」之类无信息文案作为唯一内容；存量中的此类文案在触及时顺手改，不专门迁移。
- 空状态不得使用 `AsyncRegion` 的占位样式，二者含义不同。

## 3. 加载态

- 区域级加载用 `AsyncRegion`，规则见 [`20-patterns-page-layout.md`](20-patterns-page-layout.md) §8：占位立即出现、固定尺寸、无动画，120 ms 后才出现「正在加载…」，`aria-busy` 仅设在对应区域。
- 已有数据时，后台刷新不替换主内容，也不退回占位（`asyncStatus` 已按此实现）。
- 占位不得复用真实内容的 `data-testid`。
- 按钮级提交中：禁用并改为进行时文案（见 [`15-components-overlay.md`](15-components-overlay.md) §3.4）。

## 4. 错误态

- 区域级失败：留在该区域内，文案为「{区域}加载失败：{原因}」，带「重试」按钮，容器 `role="alert"`。不得让一个区域失败拖垮整页。
- 行内字段错误与服务端错误：使用 `pl-error`（`text-danger`）；浮层内错误见 `15` §3.5。
- 错误原因使用用户可理解的语言，不暴露文件系统路径、堆栈或内部错误码原文；需要保留的错误码放在可展开的详情里。
- 失败后恢复可操作状态，不得让界面停在不可点击的中间态。
- 只用 Toast 报告的失败，用户错过就无法找回，因此需要后续处理的失败必须同时有页内呈现。

## 5. 可达性

- 加载区域：`aria-busy="true"` 且有 `aria-label`。
- 错误区域：`role="alert"`，使读屏软件立即播报。
- 空状态是普通内容，不加 `role="alert"`。
- 状态不得只靠颜色表达，必须有文字。

## 6. 验收清单

- 加载、失败、空、被过滤四态是否都有各自的呈现？
- 失败是否留在区域内并带「重试」？
- 空状态是否说明了原因？
- 已有数据时刷新是否保持原内容？
- 状态是否有文字而非只靠颜色？
