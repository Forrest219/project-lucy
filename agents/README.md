# Agents — 双核角色库

本目录提供两个角色定义，供 vibe coding 会话按需调用。角色是视角与产出标准的封装，**可独立调用，不构成强制流水线**。

## 与本仓库其他治理文档的关系

| 文件 | 管什么 | 优先级 |
|------|--------|--------|
| [`docs/DEVELOPMENT.md`](../docs/DEVELOPMENT.md) | project-lucy 开发治理（Plan Mode、红线、工单边界） | **高于本目录** |
| [`CLAUDE.md`](../CLAUDE.md) | KTX 数据问答运行时上下文 | 与本目录无关，互不污染 |
| 本目录（`agents/`） | vibe coding 角色库 | 可在其他仓库复用 |

---

## 两个角色

| 角色 | 职责 | 文件 |
|------|------|------|
| **Thinker** | 对话澄清需求，输出精简技术路径（改动文件、接口、依赖、验收标准） | [thinker.md](thinker.md) |
| **Builder** | 按路径实现代码，终端验证，内联自检安全与不可逆风险 | [builder.md](builder.md) |

## 如何调用

直接在对话里切换视角：

- "以 **Thinker** 视角把这个需求拆清楚"
- "切到 **Builder**，按上面的路径实现"
- "**Builder** 跑一下验证命令看看有没有报错"

**角色独立可调**：不需要先过 Thinker 才能让 Builder 实现——需求已经清楚时，直接给 Builder。

**产出默认走对话**：代码改动以 diff 或文件直接交付；路径分析、验收命令以消息形式产出。仅在 Human 明确要求"落盘"时才写文件。

## 何时需要完整流水线

涉及以下情况时，建议显式启用 [`AGENT_PIPELINE.md`](../AGENT_PIPELINE.md)：

- schema 迁移 / 公共接口契约变化 / 不可逆操作
- 需要事后审计或对外发布说明
- 团队协作交接

否则保持 vibe 模式，两个角色随用随调。
