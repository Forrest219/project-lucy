POC 观察与建议

已验证价值：业务用户可以通过 Telegram / Workhorse 查询授权 KX 财务数据；CIO 侧能看到问题、工具、表、拒绝原因的审计链路，满足“可用且可控”的 POC 目标。

安全结论：kx_readonly role 对非 KX 表和非授权连接保持拒绝；tools/list 已由 proxy 侧过滤，Hermes profile 不再需要本地工具 include。

改进建议：后续应在 audit 中增加 token hash 前缀或 token label 字段，便于同一 agent 多 token 场景下做精确追责；同时把“用户问题 ↔ MCP 请求 ↔ 回答”建立正式关联 ID，减少跨 Hermes state DB 与 Lucy audit DB 拼接成本。
