## 1. 架构定位

Data Agent MCP 部署在客户数据库与 AI Agent 之间，是承担受控访问、语义解释、权限约束、审计记录和质量回归职责的受控数据服务层。

一期目标不是交付一套管理后台，而是先打通并验收这条核心链路：

```text
AI Agent -> Data Agent MCP -> 权限/审计/语义层/业务知识库 -> 客户数据库
```

Agent 不应直接访问数据库。生产部署时建议通过网络策略确保数据库只允许 Data Agent MCP 所在服务器/容器访问，Agent 侧只连接 MCP endpoint。

在上述平台交付范围不变的前提下，R1 建议加入“CEO 管理驾驶舱”作为首个实际落地业务模块。该模块用于把平台能力落到一组客户已认可的管理指标、数据来源、权限边界和回归评测上，证明 Data Agent MCP 不只是可部署服务，而是能支撑真实业务问答闭环的受控数据服务层。

## 2. 核心价值主张：AI 友好的 Data Agent MCP

Data Agent MCP 的核心价值不是让 AI Agent 直接访问更多数据库，而是把企业数据资产整理成 AI Agent 可安全理解、可靠调用、持续评测的受控数据服务层。

R1 的“AI 友好”体现在五个方面：

| 维度 | 含义 | 对应交付锚点 |
|---|---|---|
| 语义友好 | 用业务指标、维度、口径和说明替代裸表、脏字段和临时 SQL | §4.3 业务语义层；§5.1 语义层配置；§5.2 FineReport 逻辑规整 |
| 权限友好 | 通过 token、role、connection、table/view allowlist 和工具 ACL 约束访问边界 | §4.7 权限与审计；§5.1 权限分域方案；§6 一期交付边界 |
| 上下文友好 | 将语义层、Wiki、Skills、报表口径和业务知识组织成 Agent 可检索上下文 | §4.3 业务语义层；§4.4 业务知识库；§4.5 回答口径护栏；§5 CEO 管理驾驶舱模块 |
| 审计友好 | 记录 Agent 调用、数据来源、allow/deny 结果和权限依据 | §4.7 权限与审计；§8 审计与合规需确认事项；§9 一期验收口径 |
| 评测友好 | 用客户确认的业务结果构建 golden eval cases，持续验证回答质量 | §4.8 回归测试与质量验收；§5.1 离线评测集；§5.4 模块验收口径 |

## 3. 一期交付原则

| 原则 | 说明 |
|---|---|
| Headless 优先 | 一期不提供客户自助 WebUI；配置、验证、回归均通过文件、脚本和 MCP 协议完成 |
| 最小可用闭环 | 优先保证 Agent 能安全、可审计地查询指定业务数据 |
| 安全边界前置 | 强安全边界来自 token、ACL、只读数据库账号、工具 allow/deny、网络隔离和审计；业务规则/Skills 主要用于回答质量和口径约束 |
| 业务样板验证 | 在平台能力之外，加入一个客户真实业务模块作为首批落地样板，用于验证资产准入、语义层、权限、审计和 eval 闭环 |
| 实施制交付 | 数据库接入、语义层、业务 wiki、权限配置由 Lucy/Data Agent MCP 团队在交付阶段协助完成 |
| 明确限制 | WebUI、自助配置、秒级撤权、Kubernetes、多机高可用、告警/监控等不纳入一期承诺 |

## 4. 一期交付核心能力

### 4.1 一体化 Docker 部署

- 支持单台服务器使用 `docker compose up` 启动。
- 镜像内置固定版本的数据访问运行时（KTX runtime），客户无需单独安装 Node、Python、pnpm、uv 等开发环境。
- 容器自带健康检查，可通过 Docker 标准运维命令确认服务状态。
- 一期仅承诺单机 Docker Compose 部署，不承诺 Kubernetes、Helm、多机高可用或 SaaS 托管形态。

### 4.2 数据库接入

- 一期支持 MySQL、PostgreSQL 两类数据库接入。
- 支持 Demo MySQL / Demo PostgreSQL 环境，用于客户在不连接生产库前验证链路。
- 客户生产库接入需要客户提供：
  - 只读数据库账号。
  - 网络连通授权。
  - 允许访问的 schema/table 范围。
  - 敏感数据、脱敏、合规授权要求。
- 数据库连接配置通过配置文件和 secret 文件完成；一期不提供客户自助连接配置界面。

### 4.3 业务语义层（Semantic Layer）

- 将数据库表、字段、指标、维度、关联关系转换为 Agent 可理解的业务语义。
- 支持：
  - 字段业务描述。
  - 计算指标（measures）。
  - 维度关联（joins）。
  - 常用过滤/分组口径（segments）。
  - 语义层校验与索引重建。
- R1 采用 GitOps 代码化语义运维模式交付。Lucy/Data Agent MCP 团队在完成初始口径配置后，将向客户移交完整的文件化 SOP、校验命令（`semantic layer validate`）与 Git 协同提交流程，确保客户技术团队在交付后可独立执行口径的改写、校验与回滚，拒绝厂商锁定。
- 一期不提供在线自助编辑界面；语义层变更通过文件、校验命令和 Git 提交流程完成。

### 4.4 业务知识库（Wiki / 业务口径文档）

- 提供业务术语、统计口径、常见误区、指标解释等结构化文档。
- Agent 在回答业务问题时可通过 MCP 检索业务知识库，降低“SQL 算对但业务口径错”的风险。
- 一期知识库由实施交付阶段预置；客户自助维护能力不在一期范围内。

### 4.5 回答口径护栏（Skills / 业务规则）

- 内置回答路由规则，要求 Agent 优先使用语义层和业务知识库。
- 对财务指标、跨表关联、领导汇报、因果判断等高风险场景提供额外复核清单。
- 该能力主要是**回答质量与业务口径护栏**，不是唯一安全边界。
- 真正的数据访问安全仍以 MCP Proxy ACL、只读数据库账号、工具权限、网络隔离与审计日志为准。

### 4.6 MCP 接入与 Agent 客户端兼容

- Data Agent MCP 以 MCP endpoint 形式提供数据访问能力。
- 已人工验收 5 类 Agent 客户端可完成基础 MCP 调用：Claude Code、Codex、Cursor、Openclaw、Hermes。
- 验收口径为：
  - `tools/list` 可用。
  - `sl_read_source` 可读语义层。
  - `sl_query` 可执行受控查询。
- 复杂 Agent 行为、模型效果和客户定制工作流需在客户实际客户端环境中联合验收。

### 4.7 权限与审计

- 支持按 Agent / Token 粒度配置：
  - 可访问的数据库连接。
  - 可访问的数据表或视图。
  - 可调用的 MCP 工具。
- 支持通过数据库视图实现轻量的数据隔离方案，例如区域/部门只能访问对应数据视图。
- 所有 MCP 访问行为会写入审计日志，用于追踪用户、工具、时间、结果和相关数据来源。
- 一期审计能力为基础后台能力：
  - 支持日志记录。
  - 支持通过 API 直接导出 CSV（无需界面），客户技术团队可自行调用，也可由 Lucy/Data Agent MCP 团队协助提取。
  - 不提供客户自助审计查询界面（即没有可视化查询页面，导出依赖 API 调用）。
- 一期配置文件生效存在约 30 秒延迟。秒级应急熔断不作为当前已交付能力；如客户安全负责人要求覆盖 Token 泄漏或 Agent 失控等极端场景，应在上线前将 Kill Switch 运维脚本列为 P0 补齐项，并完成脚本、操作说明、审计留痕和演练记录后再纳入交付验收。

### 4.8 回归测试与质量验收

- 提供业务问答 eval cases 和 smoke scripts。
- 支持在语义层、wiki、权限或规则调整后手工触发回归测试。
- 一期提供脚本化回归能力，不提供自动定时执行、趋势看板或 WebUI 报表。
- 完整 AI 问答效果验证依赖客户提供 Agent 客户端和模型环境；平台链路验收与模型效果验收需要分开记录。

## 5. 首个实际落地模块：CEO 管理驾驶舱

“CEO 管理驾驶舱”不是替代 R1 平台交付主线，而是在 R1 平台能力之上叠加的首个实际落地业务模块。它的作用是把 Data Agent MCP 的资产准入、语义层、业务知识库、权限隔离、审计追踪和离线评测闭环，落到一组客户已经治理和核验过的管理驾驶舱指标上。

该模块建议以 `temp/CEO一眼报数据溯源及验证报告V1.3(2).docx` 作为业务输入材料。该文档覆盖 CEO 一眼报首页、净现金流、营业收入、净利润、M-ROE、负反馈率、CLV、DAU、业务总览等 18 个页面，包含指标清单、指标口径/计算规则、数据溯源、FineDataLink 数仓链路和数据验证结论，可作为 R1 首批业务资产落地的依据。

### 5.1 模块交付内容

| 交付项 | 说明 |
|---|---|
| 资产准入白名单 | 从 CEO 管理驾驶舱文档中提取首批允许接入的系统、schema、表、视图或 API 来源，形成 R1 asset allowlist；默认拒绝未进入白名单的脏表、临时表和未知来源 |
| 语义层配置 | 将核心指标、维度、统计频率、计算口径和来源表映射为 semantic-layer 文件，优先覆盖可机检、可回归的管理指标 |
| 业务知识库 | 将指标解释、统计口径、特殊备注、数据更新时点和常见误区沉淀到 wiki / 业务口径文档 |
| 权限分域方案 | 按财务高敏指标、运营指标、广告/会员/TOB 指标等主题拆分 token、role、connection 和 tableSelectors，避免单一 token 覆盖全部资产 |
| 离线评测集 | 从文档中的验证结论、FineReport 驾驶舱前端最终渲染数值和可核验 SQL 中提取首批 golden eval cases，用于证明 Agent 通过 MCP 语义层回答与管理驾驶舱口径一致 |
| 验收样例问题 | 围绕 CEO / 管理层常问的问题设计可复现 prompt，例如 DAU、营业收入、净现金流、M-ROE、CLV 等指标查询 |

### 5.2 模块边界

- CEO 管理驾驶舱模块不改变 R1 的平台交付范围；R1 仍交付 Data Agent MCP 底座能力。
- 该模块不是完整报表系统复刻，不承诺重建 FineReport 页面、图表、权限系统或调度平台。
- 文档中出现的表名、SQL 和指标口径只能作为准入候选，正式接入前仍需客户确认 owner、连接方式、字段可用性、敏感级别、脱敏要求和只读权限。
- 涉及生产财务库的数据必须单独确认网络路径、账号权限、审计要求和 token 隔离策略。
- 文档中的验证结论如只有“核对一致”叙述而缺少结构化数值，需要补充人工提取、截图核验或 SQL 复算后才能进入自动化 eval。
- 由于 CEO 管理驾驶舱基于 FineReport 开发，R1 不直接信任底层原始表，也不直接复刻报表引擎逻辑；必须先将 FineReport 模板中的数据集 SQL、单元格公式、参数、多源拼接和权限逻辑规整为可审计、可回归的权威视图/宽表或 semantic-layer 资产后，方可开放给 Data Agent MCP。

### 5.3 模块落地风险

FineReport 是 CEO 管理驾驶舱模块的关键落地风险之一。该风险的本质是：业务逻辑可能不在数仓表或 BI 建模层，而是下沉到报表模板、单元格公式、模板内 SQL、参数和报表引擎运行时拼接逻辑中。若直接扫描数据库并开放原始表，Data Agent MCP 可能得到一组缺少业务逻辑的“空壳数据”，导致 Agent 回答与 CEO 驾驶舱最终展示不一致。

| 风险                  | 对 R1 的影响                                                               | R1 规避要求                                                                                 |
| ------------------- | ---------------------------------------------------------------------- | --------------------------------------------------------------------------------------- |
| 单元格公式下沉             | 同比、环比、权重调整、财务订正等逻辑可能写在 FineReport 单元格公式里，KTX 扫描数据库无法看到                 | 交付前必须取得 18 个页面对应的单元格公式；能 SQL 化的公式应逆向重构为 measures、segments 或权威视图                         |
| SQL 硬编码在报表模板        | 权威 SQL 可能散落在 `.cpt` / `.frm` 模板内部，而不是数仓 view 或存储过程                     | 必须取得报表源文件、数据集 SQL、参数定义和模板版本；优先将核心 SQL 固化为 R1 专用 canonical views                         |
| 多源内存拼接              | FineReport 可能在报表引擎内把 MySQL、Oracle、CRM API、填报数据等多源结果拼接，数据库层不存在单条 SQL 路径 | R1 不承诺 Agent 临场跨异构源拼接；跨源报表需先由客户数据平台或 FineDataLink 汇聚为单库单表/视图后再接入 MCP                    |
| Ground truth 难以自动抽取 | FineReport 输出是高度渲染后的页面/PDF，无法稳定一键取得图表后端标准结果                            | Eval 采用结果快照对比法，以客户人工确认的 FineReport 前端最终渲染数值为 golden cases，并记录日期、参数、维度、指标位置和容差           |
| 脏数仓暴露扩大             | FineReport 开发常绕过统一建模，底层可能包含临时表、手工表、废弃字段和同步失败表                          | R1 采取 Deny-by-Default；FineReport 涉及的原始表默认不开放，必须规整为不超过一批受控专用宽表/视图或明确 allowlist 后才能注入 MCP |

该风险必须在客户现场交付前作为 P0 输入核验项关闭：客户需提供 FineReport 模板源文件、数据集 SQL、单元格公式、参数配置、权限规则、刷新周期、页面最终渲染验收值和业务 owner。无法提供上述材料的页面，不应进入 R1 首批 MCP 可访问资产。

### 5.4 模块验收口径

| 验收项 | 通过标准 |
|---|---|
| 白名单 | 首批驾驶舱资产形成明确 allowlist，未列入资产默认不可被 Agent 查询 |
| 语义层 | 至少一批核心指标可通过 `sl_read_source` 查看口径，并通过 `sl_query` 查询出结果 |
| 权限 | 普通运营 token 与财务高敏 token 的 connection/table/tool 范围可区分，越权查询被拒绝并进入审计 |
| Wiki | Agent 查询指标口径时可检索到对应业务定义、来源说明和口径备注 |
| FineReport 输入材料 | 进入 R1 的页面必须提供模板源文件、数据集 SQL、单元格公式、参数配置、权限规则、刷新周期和业务 owner |
| Eval | 首批 golden cases 可运行，输出与客户人工确认的 FineReport 驾驶舱前端最终渲染数值在约定容差内一致 |
| 审计 | 模块内关键查询能记录 user/token、tool、数据来源、allow/deny 结果和时间戳 |

## 6. 一期交付边界

| 客户可能期待的能力 | 一期是否包含 | 一期说明 |
|---|---|---|
| WebUI 管理台 | 不包含 | 客户入口为 MCP endpoint、配置文件和脚本；如镜像中存在内部 WebUI 服务，也不作为客户交付使用入口，生产部署建议不对外暴露 |
| 数据库连接自助配置 | 不包含 | 由交付团队协助配置；客户需提供网络、账号、schema/table 范围 |
| 语义层在线编辑 | 不包含 WebUI 编辑 | R1 采用 GitOps 代码化语义运维模式交付；客户技术团队可按文件化 SOP、`semantic layer validate` 校验命令和 Git 协同提交流程独立改写、校验与回滚 |
| Wiki 在线维护 | 不包含 WebUI 编辑 | 一期随交付物提供文件化 wiki；后续变更走 GitOps 文件变更、校验与回滚流程 |
| Skill Editor / 规则版本化界面 | 不包含 | 一期交付文件资产和运行时规则，不提供编辑器 |
| 多 Agent 客户端接入 | 包含基础能力 | 已验收基础 MCP 调用；客户实际客户端需现场复验 |
| Token / ACL / 工具权限 | 包含基础能力 | 文件配置，后台生效；无自助管理界面 |
| 审计日志记录 | 包含基础能力 | 可追溯后台日志；查询、导出、留存、备份方式需客户确认 |
| 权限秒级撤销 | 当前不包含 | 一期配置文件生效存在约 30 秒延迟；如客户要求 Token 泄漏或 Agent 失控时的秒级网络层熔断及容器挂起（Pause），需在上线前将 Kill Switch 运维脚本列为 P0 补齐项，完成实现、操作说明、审计留痕和演练记录后方可纳入交付验收 |
| 完整端到端 AI 问答效果验收 | 部分包含 | 平台侧 smoke/eval 就绪；真实效果依赖客户模型和 Agent 环境 |
| Kubernetes / 多机高可用 | 不包含 | 一期仅单机 Docker Compose |
| 告警、监控、日志聚合、对象存储归档 | 不包含 | 可作为二期或客户运维体系集成项 |

## 7. 一期变更流程建议

R1 采用 GitOps 代码化语义运维模式交付。Lucy/Data Agent MCP 团队在完成初始口径配置后，将向客户移交完整的文件化 SOP、校验命令（`semantic layer validate`）与 Git 协同提交流程，确保客户技术团队在交付后可独立执行口径的改写、校验与回滚，拒绝厂商锁定。

一期没有客户自助管理界面，因此业务口径、权限、知识库和规则变更建议走以下流程：

1. 客户提出变更需求，明确业务目的、数据范围、权限影响和期望生效时间。
2. 客户技术团队或 Lucy/Data Agent MCP 团队按 GitOps SOP 修改配置、semantic layer、wiki 或规则文件。
3. 执行校验：
   - semantic layer validate。
   - reindex。
   - MCP `sl_read_source` / `sl_query` smoke。
   - 必要时执行 eval cases。
4. 通过 Git 提交或合并流程留下变更记录和验证结果。
5. 发布交付物或更新运行环境。
6. 如验证失败，按上一版本配置回滚。

该流程应在客户正式上线前确认 SLA、审批人、发布窗口和回滚责任人。

## 8. 审计与合规需确认事项

客户 CIO / 技术平台负责人需要确认以下问题：

| 主题 | 需确认问题 |
|---|---|
| 数据库访问路径 | 是否能通过网络策略确保 Agent 不直连数据库，只通过 Data Agent MCP 访问 |
| 数据库账号 | 是否提供只读账号；是否限制 schema/table；是否需要脱敏视图（说明：只读账号是安全建议，平台不会强制校验账号权限级别，最终权限级别由客户账号策略决定） |
| 权限模型 | token 级 ACL + 数据库视图隔离是否满足当前合规要求 |
| 权限撤销 | 配置文件约 30 秒生效延迟是否可接受；如不可接受，是否要求上线前追加 Kill Switch 运维脚本，并单独确认触发权限、触发流程、审计留痕、恢复流程和演练通过标准 |
| 审计日志 | 日志字段、保存位置、留存周期、备份、导出、查询责任是否满足审计部门要求 |
| Token 管理 | 明文 token 如何安全交付、保管、轮换和撤销 |
| 变更流程 | GitOps 代码化语义运维模式、文件化 SOP、`semantic layer validate` 校验命令和 Git 协同提交流程是否满足客户技术团队交付后独立维护诉求 |
| 模型环境 | 客户是否提供真实 Agent / 模型环境用于完整问答效果验收 |
| CEO 管理驾驶舱模块 | 是否同意将该主题作为首个落地模块；是否提供涉及数据源的 owner、只读账号、对应报表模板（`.cpt` / `.frm`）的内置 SQL 源码与单元格计算公式、以及前端最终渲染的数值基准 |
| FineReport 落地风险 | 是否能提供 18 个页面对应的 `.cpt` / `.frm`、数据集 SQL、单元格公式、参数配置、权限规则和刷新周期；无法提供的页面是否退出 R1 首批资产 |

## 10. 给 CIO / 技术平台负责人的结论

Data Agent MCP 一期交付的核心价值是：在不改变客户数据库、不要求 Agent 直连数据库的前提下，为 AI Agent 提供一条**受控、可审计、带业务语义的数据访问链路**。

换句话说，传统 BI 是给人看的，数据库是给程序查的；Data Agent MCP 是给 AI Agent 安全理解和可靠调用企业数据用的。

CEO 管理驾驶舱模块是 R1 的首个实际落地业务模块，用于验证上述平台能力在客户真实管理指标上的效果。它不改变 R1 的平台交付定位，而是为 CIO / 技术平台负责人提供一组更容易验收、追溯和复盘的业务样板。

一期适合作为生产试点或受控范围上线，但需要客户确认以下关键边界：

1. 无 WebUI，自助运营通过 GitOps 文件化 SOP、校验命令和 Git 协同提交流程完成，客户技术团队需确认该模式可接受。
2. 安全能力以基础 ACL、只读账号、网络隔离和审计为主，非完整 IAM/审计平台。
3. 配置文件生效存在约 30 秒延迟；Kill Switch 运维脚本不作为当前已交付能力。若客户要求极端安全事件下的秒级网络层熔断及容器挂起（Pause），需在上线前列为 P0 补齐项并完成脚本、操作说明、审计留痕、恢复流程和演练验收。
4. 完整 AI 问答效果依赖客户真实 Agent 与模型环境联合验收。
5. 单机 Docker Compose 不提供多机高可用能力，生产运维需补备份、监控和升级回滚流程。
6. CEO 管理驾驶舱基于 FineReport 开发，这是 R1 落地风险之一；客户需要确认首批白名单资产、敏感分级、只读账号、FineReport 模板/公式/SQL/参数、前端最终渲染验收值和业务 owner。

如以上边界被接受，一期可进入客户 headless 交付与试点验收；如客户要求自助管理、实时撤权、审计看板、高可用或自动化监控，应纳入二期或专门项目范围。
