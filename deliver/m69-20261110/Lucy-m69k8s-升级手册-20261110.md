# Lucy m69k8s 升级手册

2026-11-10

本次在现有 Release 上更换镜像。命名空间 `lucy-system`、Release `lucy`、数据卷和已有密钥都保持不动。产品版本仍是 `0.25.0`。

执行人需要能向 `mjhub.matrixback.com` 推送镜像，并能对 `lucy-system` 执行 `helm` 与 `kubectl`。

本次镜像使运行中的执行进程在连接配置写入后重读 `ktx.yaml`，并让外部目录和宽表可以列出库内表。已有连接、账号、访问控制和审计记录留在数据卷上。

## 2. 交付文件

三份文件都在公开分支 `lucy-v0.25-catalog-reload` 的 `deliver/m69-20261110/`。拉取该分支即可，不需要另外的下载页。

```bash
git clone --branch lucy-v0.25-catalog-reload https://github.com/Forrest219/project-lucy.git
cd project-lucy
git lfs pull
cd deliver/m69-20261110
```

镜像约 1.1 GB，由 Git LFS 存放。没有执行 `git lfs pull` 时，tar 只是一个指针文件，不能 `docker load`。

| 文件 | SHA256 |
|---|---|
| `lucy-helm-0.1.2.tgz` | `fb56899a97db1b196c4009c23c5ca85ba909030125793e77cec56fa2c3816189` |
| `lucy-runtime-customer-amd64-0.25.0-20261110-2b7ceed3.tar` | `2836b0fcc827e8d49d3478970b9f8744113f9026d0cf5dbe692dc759fe64b277` |
| `Lucy-m69k8s-升级手册-20261110.md` | 本文件 |

升级前执行：

```bash
shasum -a 256 lucy-helm-0.1.2.tgz lucy-runtime-customer-amd64-0.25.0-20261110-2b7ceed3.tar
```

两行摘要必须与上表一致。镜像架构为 `linux/amd64`。后面的命令都在 `deliver/m69-20261110/` 下执行。

## 3. 保持不变

以下内容已经在集群里，本次不新建、不删除、不改名：

- 命名空间 `lucy-system`，Release `lucy`
- Deployment 选择器 `app=lucy`
- 数据卷 `lucy-data-pvc`
- 镜像拉取 Secret `mjhub-cred`
- 数据库 Secret `lucy-doris`，引导 Secret `lucy-bootstrap`
- 节点 `m-69-219`
- Service `lucy-admin` `5174`、`lucy-mcp` `7879`
- 公开 MCP 地址 `https://lucymcp.matrixback.com/mcp`

升级使用 `Recreate`。旧 Pod 停止后新 Pod 才启动，WebUI 和 MCP 在此期间中断。数据卷是单节点读写，副本数保持 1。

不要执行 `helm uninstall`。不要删除 `lucy-data-pvc`。不要重新生成 `lucy-bootstrap`。

## 4. 升级前确认

```bash
helm -n lucy-system status lucy
helm -n lucy-system get values lucy
kubectl -n lucy-system get deploy lucy -o jsonpath='{.spec.template.spec.containers[?(@.name=="lucy")].image}{"\n"}'
kubectl -n lucy-system get pvc lucy-data-pvc
kubectl -n lucy-system get secret mjhub-cred lucy-doris lucy-bootstrap
```

继续升级的条件：

- Release `lucy` 处于 `deployed`
- 当前镜像标签为 `20261105-v1`
- `lucy-data-pvc` 为 `Bound`
- 三个 Secret 都存在
- 目标节点 `m-69-219` 可调度

当前镜像不是 `20261105-v1` 时，先核对现场再升级。

记录当前修订号，供回退使用：

```bash
helm -n lucy-system history lucy
```

## 5. 升级

先推镜像，再执行 Helm。这个标签在仓库里还不存在；`pullPolicy` 为 `IfNotPresent`，节点拉不到镜像时 Pod 不会就绪。

```bash
docker load -i lucy-runtime-customer-amd64-0.25.0-20261110-2b7ceed3.tar
docker push mjhub.matrixback.com/lucy/lucy-runtime:customer-amd64-0.25.0-20261110-2b7ceed3

tar -xzf lucy-helm-0.1.2.tgz
helm template lucy ./helm --namespace lucy-system -f helm/values.m69.yaml \
  | grep 'image:'
helm upgrade lucy ./helm --namespace lucy-system -f helm/values.m69.yaml
kubectl -n lucy-system rollout status deploy/lucy
```

`helm template` 的镜像行必须是：

```text
mjhub.matrixback.com/lucy/lucy-runtime:customer-amd64-0.25.0-20261110-2b7ceed3
```

命令必须带 `-f helm/values.m69.yaml`。省略该文件时，Chart 默认 values 会使用 `project-lucy` 和 `pullPolicy: Never`，节点上没有这张离线镜像。

启动时的初始化只做两件事：把数据卷上的文件属主调整为 `10001`，并把 `lucy-doris` 里的口令同步到数据卷。它不改写连接配置。

## 6. 完成标准

```bash
kubectl -n lucy-system get pod -l app=lucy -o jsonpath='{.items[0].spec.containers[?(@.name=="lucy")].image}{"\n"}'
kubectl -n lucy-system exec deploy/lucy -c lucy -- cat /app/BUILD_REVISION
kubectl -n lucy-system get pvc lucy-data-pvc
```

满足以下四项即完成：

- Pod 为 `Running`，且就绪
- 容器镜像为 `mjhub.matrixback.com/lucy/lucy-runtime:customer-amd64-0.25.0-20261110-2b7ceed3`
- `/app/BUILD_REVISION` 为 `2b7ceed376b23e42638f56c21ad0a52840ba471a`
- `lucy-data-pvc` 仍为 `Bound`

需要从本机看健康检查时：

```bash
kubectl -n lucy-system port-forward deploy/lucy 5174:5174
curl -sS http://127.0.0.1:5174/api/health
```

返回中的产品版本为 `0.25.0`。然后打开现有 WebUI，确认原有连接仍在，并对 `marketingapi`、`hive-1`、`hive-jd` 查看库内表。

## 7. 回退

新 Pod 不能就绪，或核对未通过时，回到第 4 节记下的修订号：

```bash
helm -n lucy-system rollback lucy <修订号>
kubectl -n lucy-system rollout status deploy/lucy
```

回退后的镜像应恢复为 `mjhub.matrixback.com/lucy/lucy-runtime:20261105-v1`。该标签需仍在 `mjhub` 中。回退不删除数据卷。
